# RT-08: content-rules

Applies from phase 1. Runs in: a worktree on branch `redteam/P{k}-RT-08`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the rules that govern what the site says, as opposed to what it computes: every number with a golden value printed through `<G>`, every statement that rests on an open item of Appendix E wrapped in `<Unverified>` and replaced by its fallback in a release build, the bridge sentence of 2.4(a) word for word wherever both views appear, the exact wording of stated limits, "not of finite type" only after `classify`, the anatomy and length of a lesson, the credit and house-style rules, and the statements of Appendix F the site must never repeat. A build passes its gate while breaking all of these: the build fails only on an unresolved `<G>` path or an unknown `<Cite>` key, the numbers-in-prose report is advisory and blind to captions, props and numbers written as words, the release build never fails on an open item, and no test reads a sentence for meaning. If this lens misses, the published site states unverified memories as facts, repeats errors the specification took pains to correct, drifts from the golden data the first time a number is retyped, and loses the one sentence that ties the two games together.

## 5. Methods

All commands use absolute paths. `<wt>` is your worktree, `<scratch>` your scratch directory. Never `cd`, never a multi-line inline script or heredoc: write each script to a file under `<scratch>` or `<wt>/redteam/`, then run it. Run Python with `python3 -I`. Only one Playwright run at a time.

### 5.1 Builds

```
npm --prefix <wt> ci --prefer-offline
npm --prefix <wt> run build                                            # preview build into <wt>/site/dist
OUT_DIR=<scratch>/dist-release npm --prefix <wt> run build:release     # RELEASE=1; keep its stderr: the release report
npm --prefix <wt> run report                                           # reports/numbers-in-prose.md and the open-items report
```

Save the release build's standard error to `<scratch>/release-stderr.txt` (append `2> <scratch>/release-stderr.txt` to the command). If `OUT_DIR` is not honoured (CONTRACTS 1), copy `site/dist` to `<scratch>/dist-preview` with `cp -R` before the release build and report the deviation as `incidental`.

### 5.2 Text extraction

`<wt>/redteam/rt08-extract.mjs`, run with `node`: start from the route list (walk the build directory for `.html` files; `tools/garden/index.html` becomes `/tools/garden/`). Serve the preview with the repository's `playwright.config.ts` `webServer` (it runs `astro preview`), or the release directory with a small static server on `node:http` (about 30 lines; map the base path, serve `index.html` for directories, set `Content-Type` by extension). With Playwright's Chromium in a context with `javaScriptEnabled: false`, for each route evaluate in the page:

- remove from a clone of `main`: `.katex-mathml`, `annotation`, `script`, `style`, `noscript`; keep `.katex-html` (the visible copy);
- record segments with their kind, by the nearest ancestor: `[data-tool]` (tool; with `caption`, `[data-out]`, tables and the live region as sub-kinds), `[data-golden]` (golden, with its path), `[data-unverified]` (with its item), `[data-cite]` (with its key), the `Seen` box, the Lie theory section, `Challenge`, prediction blocks, `details`, headings, paragraphs;
- normalise text with `normalize('NFC')`, collapse runs of white space (including U+202F and U+2009) to one space for comparisons, but keep the raw string for the formatting checks of `<G>` (attack 14); before removing `annotation`, record for each KaTeX formula its TeX source from the `annotation encoding="application/x-tex"` element, for the `<Tex>` grouping check of attack 14;
- split sentences on `. `, `? `, `! ` not preceded by a common abbreviation (`p.`, `pp.`, `e.g.`, `i.e.`, `Fig.`, `No.`).

Write one JSON file per build to `<scratch>/text-preview.json` and `<scratch>/text-release.json`. Every attack that reads prose reads these files. With JavaScript on (a second pass) record the same for the tool roots after hydration, for attacks 6, 9 to 11 and 20.
