# RT-06: no-js-and-no-worker

Applies from phase 0. Runs in: a worktree on branch `redteam/P{k}-RT-06`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks two promises the site makes before the reader does anything. First, every page reads completely with JavaScript disabled: each tool ships its default state as real markup (the SVG board with its values, the caption, the data table of A-10), its controls carry `disabled` until hydration, a `<noscript>` line sits under it, predictions fall back to `<details>`, and the two canvas tools (T10, and T8 above 192 elements) ship an SVG snapshot drawn at build time. Second, no tool needs the Web Worker for its default state: the worker script is fetched only when a tool first needs it, after an interaction. A build passes its gate while breaking both: a figure computed in `onMount` renders an empty board on the server and fills it on hydration, so every Playwright test that runs with JavaScript on passes; a worker constructed at module load is never noticed by a test that only intercepts a URL or only looks above the fold. If this lens misses, the reader with scripts off, or on a slow phone before hydration, sees blank figures and buttons that do nothing, and the size budget of 7.6 silently excludes a script every page downloads.

## 4. Attack list

Each attack names the phases in which it applies. Severity guidance follows `RED-TEAM-COMMON.md` 4: a lesson or page that does not read without JavaScript, or a default figure that is missing, is a blocker; a control not disabled, a missing `<noscript>` line, or a worker fetched for a default state is major unless it breaks the figure.

1. **Server markup differs from the hydrated default (phases 0 to 7).** What: every route, every `[data-tool]` root. How: load the route twice in Playwright, once in a context with `javaScriptEnabled: false` and once with JavaScript on, waiting for hydration and touching nothing (Methods 5.4). Collect from both: `data-tool`, `data-moves`, every `[data-node]` with `data-node`, `data-board`, `data-value`, `data-can-act`, the text of every `[data-out]`, the caption text, the number of `<svg>` elements and of `<circle>` or node shapes per root. Compare. Standard: SPEC 4.0 "The default state of every tool is rendered to HTML and SVG at build time"; 7.4 "ships its default state as real markup: the SVG board with its values". Failure: any difference, for example SSR `data-value` empty or `0` where hydration shows `1`, SSR `data-moves` absent, a `[data-out]` saying "loading" or "computing", or an `<svg>` with no node shapes. The usual cause is a figure computed in `onMount`, `$effect`, a `{#if mounted}` or `{#if browser}` block, or a `client:only` directive; name it in the finding.
2. **A worker constructed without any interaction (phases 1 to 7).** What: every route, including routes with no tool. How: Methods 5.5, the worker watcher: `page.addInitScript` wraps `window.Worker` and `window.SharedWorker` to record every construction with its URL; `page.on('worker')`; `page.on('request')` matching `/worker/i` and the hashed name of `engine.worker` found in `site/dist/_astro/`; and a scan of the HTML for `<link rel="modulepreload">` whose `href` is the worker chunk. Load at 360 by 800, wait for network idle, then scroll the whole page with `window.scrollTo` in steps so every `client:visible` island hydrates, wait for network idle again. Standard: SPEC 7.6 "The worker's script (E-9) is fetched when a tool first needs it. No tool may need it for its default state"; E-9 "No tool may need the worker for its default state". Failure: any recorded construction, `worker` event, request or modulepreload before the first click or key press. Blind spots to probe on purpose: a `new Worker(...)` at the top level of `worker.ts` or of a tool module (created on import, whatever the call); a worker built with Vite's `?worker&inline` (a `blob:` URL that a URL interception never sees, which only the constructor wrap and `page.on('worker')` catch); a modulepreload of the worker chunk emitted by Vite because `worker.ts` imports it statically.
3. **Tools below the fold are not covered by `worker-on-demand.spec.ts` (phases 1 to 7).** What: lesson pages with several tools. How: read `site/tests/e2e/worker-on-demand.spec.ts`; if it does not scroll, it only sees the `client:idle` island. Run attack 2 with scrolling on every lesson route, and separately at 1280 by 800. Standard: SPEC 7.6 and E-9 as in attack 2; 7.6 "the others when scrolled into view (`client:visible`)" hydrate with their default state, so their hydration must not fetch the worker either. Failure: a worker request that appears only after scrolling. Report the instance id (`b3`) and its tool.
4. **A default state routed to the worker by a wrong hint (phases 1 to 7).** What: the hints each tool passes to `engineCall`. How: grep every call of `engineCall(` and `whereToRun(` in `site/src`; for each, write down the `CallHint` the default state produces; then confirm in the browser with the watcher of attack 2 on the tool's route and on every lesson instance of it. Cases most likely wrong: T2 `roots` on a named finite board (at most 288 roots, "known in advance"); T2 with cap exactly 2000 ("any search called with a cap of at most 2000" stays on the main thread); T8 on $F_4$, $B_4$, $C_4$, $A_5$, where a hint built from `n_reduced_words_w0` or from the number of edges instead of the group order would send the count to the worker (SPEC 4 T8: "Every board offered here has at most 1152 group elements, so the count runs on the main thread"); T2 `orbit` mode on a finite board in phase 3, where `orbitSize` makes the orbit known; T12 for an orbit of at most 2000 positions. Standard: E-9 rule 1 and rule 3, CONTRACTS 4 `whereToRun`. Failure: the worker requested on load for any of these, or a hint with `expectedItems` above 2000 on a call whose cap is 2000.
5. **The M1 triangle garden grown at build time (phases 1 to 7).** What: the T2 instance of `/modules/m1-mutation` with `grown` 40 on the triangle, and the `triangle-40` preset on `/tools/garden` if registered. How: with JavaScript off, count the vertices in the instance's SVG, read the counter `[data-out]` and the stop message; with JavaScript on, run the watcher of attack 2 and compare the hooks as in attack 1. Expected from `layer_growth_examples[label=triangle]`: 243 root populations, 6 new per layer, and the message "stopped after 40 layers" (SPEC 4 T2 acceptance; the message is exact). Standard: SPEC 4 T2 "That growth is computed at build time and is part of the default state." Failure: fewer than 243 vertices in the server HTML, no message, a chart with no bars, or a worker request (the garden's cap is 2000, so every call stays on the main thread).
6. **Controls not disabled in the server HTML, or never enabled (phases 0 to 7).** What: every `button`, `input`, `select`, `textarea`, `[role=button]`, `[role=slider]`, `[contenteditable]` and `[tabindex]` element inside each `[data-tool]` root, and every export, Copy link, Download data, Cite, "Show as table", "step", "play to the end", "play on", "keep counting", prediction answer and "show me" control. How: JavaScript off, list the elements that lack the `disabled` attribute (and, for non-form elements, lack `aria-disabled="true"`); JavaScript on, after hydration, list the controls still disabled that the state allows (undo with an empty history may stay disabled; reset, the node buttons in free play and Copy link may not). Failure: any control enabled without JavaScript (name its text and selector), or a control that stays disabled after hydration on a `client:visible` instance after scrolling to it.

Read each line. Standard: SPEC 7.4 "A `<noscript>` line under each tool says that the figure is interactive when scripts are allowed"; 4.0 "a one-line note". Failure: a tool instance without its line, two lines for one instance (T16 or T9 composing T1 with its own frame, which also doubles `data-tool` and the live region), or a line placed in the page header far from the figure. The wording is the builder's; a line that does not say the figure becomes interactive with scripts is minor.

## 5. Methods

All commands use absolute paths. `<wt>` is your worktree, `<scratch>` your scratch directory. Never `cd`, never a multi-line inline script: write each script to a file under `<scratch>` or `<wt>/redteam/`, then run it. Only one Playwright run at a time.

### 5.1 Builds

```
npm --prefix <wt> ci --prefer-offline
npm --prefix <wt> run build                                   # preview build into <wt>/site/dist
OUT_DIR=<scratch>/dist-release npm --prefix <wt> run build:release
BASE_PATH=/sub/path/ OUT_DIR=<scratch>/dist-sub npm --prefix <wt> run build
```

If `OUT_DIR` is not honoured (a deviation from CONTRACTS 1, report it as `incidental`), copy `site/dist` to the scratch directory between builds with `cp -R`.

### 5.2 Serving

Use the repository's `playwright.config.ts` `webServer` (it runs `astro preview`) for the preview build. For the release and base-path builds write `<scratch>/serve.mjs`, a static server of about 30 lines on `node:http` and `node:fs` that maps `GET /sub/path/x` to `<dir>/x`, serves `index.html` for directories, sets `Content-Type` from the extension (`.js` as `text/javascript`, `.svg` as `image/svg+xml`, `.json`, `.css`, `.woff2`), and answers 404 otherwise. Run it with `node <scratch>/serve.mjs <dir> <port> <base>` in the background, and point Playwright at it with `baseURL`.

### 5.3 Route enumeration

`<wt>/redteam/routes.mjs`: walk `site/dist` (or the directory given) recursively, keep every `index.html` and every other `.html`, turn each path into a route (`tools/garden/index.html` to `/tools/garden/`), and print a JSON list. Write it to the file the tests import with `node <wt>/redteam/routes.mjs <wt>/site/dist --out <wt>/redteam/routes.json` (the script writes the list to the path after `--out` with `node:fs` as well as printing it; no shell redirection is needed). Rerun it for each build directory of 5.1, writing `routes-release.json` and `routes-sub.json` beside it. Every attack that says "every route" reads this list, so pages the gate's specs never list (atlas, embed, glossary) are covered. Compare the list with the routes in `nojs.spec.ts`; a released route missing there is a finding against the test (minor, or major for a lesson route).

### 5.4 Playwright: no JavaScript, and server against hydrated

Commit tests as `<wt>/site/tests/e2e/redteam-RT-06-<topic>.spec.ts`. Run one file at a time:

```
<wt>/node_modules/.bin/playwright test --config <wt>/playwright.config.ts <wt>/site/tests/e2e/redteam-RT-06-nojs.spec.ts
```

Shape of the comparison test:

```ts
import { test, expect, type Page } from '@playwright/test';
import routes from '../../../redteam/routes.json' with { type: 'json' };   // written by Methods 5.3
const CAPTION = '[data-caption]';   // placeholder: replace with the caption selector read from ToolFrame.svelte

async function hooks(page: Page) {
  return page.$$eval('[data-tool]', roots => roots.map(r => ({
    tool: r.getAttribute('data-tool'), moves: r.getAttribute('data-moves'),
    nodes: [...r.querySelectorAll('[data-node]')].map(b => [b.getAttribute('data-node'),
      b.getAttribute('data-board'), b.getAttribute('data-value'), b.getAttribute('data-can-act')]),
    outs: [...r.querySelectorAll('[data-out]')].map(o => [o.getAttribute('data-out'), o.textContent?.trim()]),
    caption: r.querySelector(CAPTION)?.textContent?.trim() ?? null,   // CAPTION: the selector read from ToolFrame.svelte (attack 33)
    svgs: r.querySelectorAll('svg').length,
    enabled: [...r.querySelectorAll('button,input,select,textarea')]
      .filter(e => !(e as HTMLButtonElement).disabled).map(e => e.outerHTML.slice(0, 120)),
    live: [...r.querySelectorAll('[aria-live]')].map(l => [l.getAttribute('aria-live'), l.textContent]),
    noscript: r.querySelectorAll('noscript').length + (r.nextElementSibling?.tagName === 'NOSCRIPT' ? 1 : 0),
  })));
}

for (const route of routes) {
  test(`server markup equals hydrated default: ${route}`, async ({ browser }) => {
    const off = await browser.newContext({ javaScriptEnabled: false, viewport: { width: 360, height: 800 } });
    const p1 = await off.newPage(); await p1.goto(route);
    const server = await hooks(p1);
    for (const r of server) expect(r.enabled, `enabled controls without JS in ${r.tool}`).toEqual([]);
```

## 6. Not a finding for this lens

- A link's query string ignored with JavaScript off: the site is static, so with scripts off every instance shows its default state. That is what 7.4 promises.
- The wording of the `<noscript>` line: the builder's choice (7.4 gives its meaning, not its words). Only its absence, duplication, placement or a meaning other than "interactive when scripts are allowed" counts.
- A worker fetched after a real interaction, or for a link that 6.6 and E-9 rule 2 route to it ("a long list of moves read from a link"): a link is not a default state.
- A tool, preset, page or route of a later phase (section 3 of this file; SPEC 9.1). The T8 snapshot before phase 3, T10 before phase 4, the atlas and embed routes before phase 6.
- The data table hidden behind the disabled "Show as table" toggle while present in the HTML: a note for the owner (attack 10), since 4.0 names only figure, caption and note as what the reader sees.
- A theme switch that does nothing without JavaScript: the specification gives no rule for the shell's controls; a note.
- The atlas convention switch disabled without JavaScript, so that the transposed matrix shows only after hydration: SPEC 4 T14 asks for "a convention switch" and 7.4 disables every control until hydration; a note (attack 25).
- Sizes of JavaScript, long tasks, layout shift and draw times: `RT-07`. Report a worker counted in or excluded from `npm run size` only as incidental.
- Contrast and colours of figures in the dark theme without JavaScript, keyboard behaviour, live-region templates after the first move: `RT-05`.
- No atlas page for an affine board: SPEC 4 T14 puts "marks and comarks of the affine board" on each finite type's page, and the plan builds one page per named finite type (attack 25).
- No tool that runs the sweep over all pairs of a board: SPEC names the sweep in E-9 rule 3 but gives it no tool control; record it in `coverage` (attack 17).
- The codec's validation and the notice text: `RT-04`, including whether a link carrying a position field is rejected (attack 34 covers only what the server HTML and the island props carry). The values themselves (a wrong number in a correctly server-rendered figure): `RT-01` and `RT-09`, unless the server and hydrated values differ, which is attack 1 and yours.
- `[D]` choices recorded in `DECISIONS.md`: the compression measure of the 30 kB preset limit, the rendering route of 7.2 item 3, the snapshot format (inline `<svg>` or `<img>` of an SVG file) as long as it is SVG produced at build time.
- A statement of SPEC that the oracle contradicts: a note (SPEC 0.2 item 2).
