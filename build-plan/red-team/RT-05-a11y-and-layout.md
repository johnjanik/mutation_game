# RT-05: a11y-and-layout

Applies from phase 0. Runs in: a worktree on branch `redteam/P{k}-RT-05`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the promise that every board and tool can be used by keyboard, heard through a screen reader, seen at 320 pixels and read in both themes, exactly as SPEC 7.5 (A-1 to A-12), 6.1, 6.3 and 4.0 describe. An axe scan, which is what the gate runs, catches none of the requirements that 7.5 lists as "Requirements that automated scans do not catch": a live-region sentence that differs from the template by one word, a focus that falls to `<body>` after every move because the button was re-rendered, an arrow key that misses the node at exactly 45 degrees through a floating-point comparison, a hit area of 38 pixels where the rule gives 43 because the box has padding, a numeral painted in the orange that is only 3.9 to 1. The builders' own tests run on $A_2$, where the layout is a row, the labels start at 1, no node is at 45 degrees, there are fewer than five nodes and no node is outlined in the dark theme; every one of those is a place where a wrong implementation looks right. If this lens misses, a reader who uses a keyboard or a screen reader cannot play the games the site is about, and a reader on a phone mis-taps nodes on $E_8$.

## 4. Attack list

Severity guidance from `RED-TEAM-COMMON.md` 4: a tool not operable by keyboard or not announced is a **blocker**; a template that differs from 7.5, a hit area below the rule, a contrast below A-6, a missing table view or a drag-only action is **major**; a wording inside a plan reading, a missing `data-out` listing, or a test that compares loosely without being wrong today is **minor**. "Expected" strings below were computed with `lie_games.fire` and `mutate` (section 5.2) or are the examples of A-4 themselves. The attacks are ordered from the most likely to find a blocker (keyboard operation and announcements) to the least (shell basics, embeds, phase 7 boards); run them in this order within your time.

1. **Live-region text, character for character, on the oracle-checked examples (phases 0 to 7).** What: drive the board by keys and read the region after each move. Phase 0, index page, start $(1,0)$: Enter on city 1 must give exactly `Mutated city 1. Populations now minus 1, 0. Move 1.`; from a fresh load, Space on city 2 gives `Mutated city 2. Populations now 1, 1. Move 1.`. From phase 1, on `/tools/board` with links of SPEC 6.6, focus the node by keys and press Enter: `?z=1&g=A3&v=n&m=l&c=n&s=1,1,1&w=1.2.1` then node 3 gives `Fired node 3. Numbers now minus 1, 2, minus 3. Move 4.`; `?z=1&g=A3&v=p&m=f&c=p&s=1,0,0` then city 2 gives `Mutated city 2. Populations now 1, 1, 0. Move 1.`; `?z=1&g=A2&v=l&m=f&c=p&s=1,0&w=2` then node 1 on either board gives `Mutated city 1 and fired node 1. Populations now 0, 1; numbers now minus 1, 2. Move 2.`; `?z=1&g=A2&v=n&m=f&c=n&s=1,1` then node 2 gives `Fired node 2. Numbers now 2, minus 1. Move 1.` (T1 acceptance); `?z=1&g=A3&v=n&m=l&c=n&s=1,1,1&w=1.2.1.3` then `u` with focus on a node gives `Undid move 4. Numbers now minus 1, minus 1, 3.`; `?z=1&g=A3&v=n&m=l&c=n&s=1,1,1` then the legal play 1, 2, 1, 3, 2, 1 by keys ends with `Game over after 6 moves.` How: the recorder of section 5.3; compare with `toBe`, never `toContain`. Standard: A-4 ("Templates, with negative numbers spoken as 'minus'") and CONTRACTS 5.3. Failure: any difference at all: `-1` or `−1` (U+2212) instead of `minus 1`; `Move 1` without the full stop; `numbers` capitalised in the linked sentence; `;` replaced by `,`; a double space; two sentences in the linked view instead of one; `1 moves` against the plan reading recorded by `P0-A5`; the region empty because the text was set before the region was in the accessibility tree.
2. **Enter or Space acts exactly once, and focus survives the move (phases 0 to 7).** What: every board, both keys, both views of the linked board. How: focus a node by Tab and arrows, press Enter once, read `data-moves` and `document.activeElement`; repeat with Space; repeat holding the key down for 300 ms (`keyboard.down`, wait, `keyboard.up`). Standard: A-1 "Enter or Space acts"; 4.0 "Each board is one tab stop"; `P0-A5` 5.5 "Enter and Space act through the button's native click; do not also handle them on keydown". Failure: `data-moves` goes up by 2 for one press (a keydown handler plus the native click); Space scrolls the page; after the move `document.activeElement` is `<body>` or a different element than the button with the same `data-node` (the button was replaced by a re-render, so a keyboard user is thrown out of the board after every move). In the linked view, acting on the numbers board must keep focus on the numbers board.
3. **Nodes that cannot act stay focusable and announce why (phases 1 to 7).** What: `legal` mode in the numbers and linked views; `raising` mode; the frozen board of a prediction; the board after "game over". How: `?z=1&g=A3&v=n&m=l&c=n&s=1,1,1&w=1.2.1.3` (numbers $(-1,2,-3)$); Tab into the board, arrow to node 3 and node 1, press Enter on each. Standard: A-1 "Every node is reachable on every layout"; A-3 `Node 5, value 0, cannot be fired` "(in legal play; in free play every node can be fired)"; A-4 `Node 3 cannot be fired: its number is minus 2.` Expected here: name `Node 3, value minus 3, cannot be fired`, and on Enter the region reads `Node 3 cannot be fired: its number is minus 3.` with `data-moves` unchanged. Failure: illegal nodes carry the `disabled` attribute (they drop out of the arrow sequence, cannot be focused, and the `cannotFire` template can never be heard); arrows skip them; the roving `tabindex="0"` lands on a disabled button so the board has no tab stop at all after game over.
4. **One tab stop per board, History after it (phases 0 to 7).** How: from the top of the page press Tab repeatedly, recording `activeElement` (tag, `data-node`, `data-board`, text) until focus returns to `<body>` or loops; count node buttons reached. Then Shift+Tab back. Standard: A-1 "its nodes are real `<button>` elements, one of which is in the tab order (roving `tabindex`)"; "Undo, redo and reset are visible buttons after the board in the tab order"; 4.0 "Each board is one tab stop". Failure: more than one node button per board reached by Tab (count the `tabindex="0"` buttons per `[role=group]`: must be exactly 1); none reached; Undo before the board; in the linked view one tab stop for both boards together, or three; after leaving and re-entering, the tab stop not on the last focused node (plan reading of `P0-A5`, minor); Undo, Redo or Reset hidden (`display:none`, zero size, off-screen) rather than visible.
5. **Group, buttons and hidden drawing (phases 0 to 7).** How: for each board, the accessibility snapshot of the group: role `group`, a non-empty name; children are buttons (`<button type="button">`, not `div role="button"`, not SVG elements with `tabindex`); the SVG drawing is `aria-hidden="true"` or otherwise not read twice; node labels drawn as `<text>` do not create a second set of focusable or named items. Standard: A-1 "A board is a group with an accessible name; its nodes are real `<button>` elements"; "Because the nodes are ordinary buttons, a screen reader in browse mode reaches them without the arrow-key layer. Focus is never trapped in a canvas." Failure: role missing or name empty; nodes that are not buttons; every value read twice in browse mode (once from the SVG text, once from the button); a `<button>` inside another interactive element.
6. **Keyboard operation of tool interactions other than the board (phases 1, 3, 6).** What: T2 "click a vertex to jump there" (phase 1), T8 "Hovering or focusing a vertex shows the position, a shortest word (`wordTo`), and the positive roots whose mirrors separate it from the start" (phase 3), T13 painting nodes black or white and choosing $\tau$ (phase 6). T13 on `/tools/satake` with $E_6$: paint nodes 2, 3, 4, 5 black by keys, choose the flip as $\tau$ by keys, and compare the copied link (its `x` must be `2.3.4.5` and its `t` the flip) and the three lights with the same state reached by that link. Standard: A-1 "Every tool is fully operable from the keyboard"; A-2 (a visible focus ring on the vertex); 4.0 "Keyboard and screen reader". Failure: a vertex or node that can only be clicked (blocker); focus that shows less than hover (major); no visible focus on vertices (major); painting or $\tau$ only by mouse (blocker). Attack 40 audits the gate's own T13 script; this attack drives the tool independently.

## 5. Methods

All commands use absolute paths. `<wt>` is your worktree, `<scratch>` your scratch directory. Never `cd`, never a multi-line inline script, never a heredoc: write each script to a file under `<scratch>` or `<wt>/redteam/`, then run it. Only one Playwright run at a time on the machine.

### 5.1 Builds, serving and routes

```
npm --prefix <wt> ci --prefer-offline
npm --prefix <wt> run build
RELEASE=1 OUT_DIR=<scratch>/dist-release npm --prefix <wt> run build
```

The preview build is served by the `webServer` of `<wt>/playwright.config.ts` (`astro preview`). For the release build write `<scratch>/serve.mjs` (a static server on `node:http` and `node:fs` that serves a directory, `index.html` for directories, correct `Content-Type` for `.js`, `.css`, `.svg`, `.woff2`), run it in the background with `node <scratch>/serve.mjs <scratch>/dist-release 4400`, and set `baseURL` in the test with `test.use({ baseURL: 'http://localhost:4400' })`. Routes: `<wt>/redteam/routes.mjs` walks `site/dist` for `.html` files and prints a JSON list; every attack that says "every route" reads it.

Run one file at a time:

```
<wt>/node_modules/.bin/playwright test --config <wt>/playwright.config.ts redteam-RT-05-live
<wt>/node_modules/.bin/vitest run --root <wt> site/tests/unit/redteam-RT-05-arrows.test.ts
```

### 5.2 Reference values from the oracle and the formulas

- Announcements: `<scratch>/announce.py` inserts `<wt>/reference` into `sys.path`, imports `lie_games`, builds `lie_games.cartan(letter, n)` (or a custom matrix), applies `fire` or `mutate` for a list of labels (label minus one is the position on finite boards; on affine boards build the matrix with node 0 first and use the label as the position), and prints the expected sentence with each negative value written `minus k`. Run `python3 -I <scratch>/announce.py A5 n 1,1,1,1,1 4.5.4.3.2.1.4`. Changed nodes are those whose value differs, never those that are joined.
- Arrow targets: `<scratch>/arrows.py` holds the coordinates of 6.1 for each layout (y upwards), and for each node and key returns the nearest node with cosine at least $\cos 45°$ minus `1e-9`, ties by smaller label, else the label fallback with stops at the ends; for polygon and custom layouts the label order with wrap. Print JSON `{layout: {from: {key: to}}}` and import it in the Playwright and Vitest tests. A second column computed with a strict comparison shows the cells that a wrong implementation gets wrong (attack 11).
- Node centres: `<scratch>/layout.py` holds the 6.1 table as a function of the board name (finite, untwisted affine, twisted by `reverse_of`, presets, $H_n$) and prints JSON `{board: {label: [x, y]}}` in grid units with $y$ upwards, polygons as angles clockwise from the top; `arrows.py` imports it, so attacks 11 and 12 use one table.
- Hit sides: `Math.min(44, Math.min(64, Math.floor((W - 16) / k)))`; the oracle's `unit_px = lambda W, k: min(64, (W - 16) // k)` in `reference/verify.py` section 20 is the same rule. Polygon radius `(Math.min(W, 360) - 60) / 2`.

### 5.3 Playwright: keys, focus and the live-region recorder

Commit tests as `<wt>/site/tests/e2e/redteam-RT-05-<topic>.spec.ts`. The recorder, installed before any page script runs:

```ts
test.beforeEach(async ({ page }) => {
  await page.addInitScript(() => {
    (window as any).__ann = [];
    new MutationObserver((recs) => {
      for (const r of recs) {
        const el = r.target.nodeType === 1 ? (r.target as Element) : r.target.parentElement;
        const region = el?.closest('[aria-live], [role="status"]');
        if (region) (window as any).__ann.push({ t: performance.now(), text: region.textContent ?? '' });
      }
    }).observe(document, { subtree: true, childList: true, characterData: true });
  });
});
const texts = (page) => page.evaluate(() => (window as any).__ann.map((a) => a.text).filter((s) => s !== ''));
```

Wait for hydration with `await page.locator('[data-tool][data-hydrated="true"], [data-tool]:not([disabled]) button[data-node]:not([disabled])').first().waitFor()` (use whichever hook the build documents), then drive by keys only: `page.keyboard.press('Tab')`, `'ArrowRight'`, `'Home'`, `'Enter'`, `' '`. Read focus with `page.evaluate(() => { const e = document.activeElement as HTMLElement; return { tag: e.tagName, node: e.dataset.node, board: e.dataset.board, label: e.getAttribute('aria-label') }; })`. Wait 600 ms after the last key before reading the final announcement (the 500 ms coalescing of CONTRACTS 4). For burst tests use `page.clock` only if the build's announcer reads `setTimeout`; otherwise real waits of 200 and 700 ms.

### 5.4 Geometry

`locator.boundingBox()` for every `button[data-node]`; overlap of two boxes when both `min(r1, r2) - max(l1, l2) > 0.5` and the same for top and bottom. Corner probes: `page.evaluate(([x, y]) => { const e = document.elementFromPoint(x, y); return e?.closest('button[data-node]')?.getAttribute('data-node') ?? e?.tagName; }, [x, y])`. Reflow: `page.evaluate(() => [document.scrollingElement.scrollWidth, document.scrollingElement.clientWidth])` and a walk of `document.querySelectorAll('body *')` for elements whose right edge exceeds the viewport, each with its nearest ancestor whose computed `overflow-x` is `auto` or `scroll`. Viewports: `test.use({ viewport: { width: 320, height: 800 } })`, and 360, 399, 400, 1280.

### 5.5 Contrast from the shipped CSS

`<wt>/redteam/contrast.mjs` exports `ratio(c1, c2)` with the WCAG formula (the same as `_lum` and `contrast` in `reference/verify.py` section 20: channels over 255, linearised with 0.03928, 12.92, 0.055, 1.055, 2.4; weights 0.2126, 0.7152, 0.0722; `(L1 + 0.05) / (L2 + 0.05)`), accepting `#RRGGBB` and `rgb(r, g, b)`. In the page, read tokens with `getComputedStyle(document.documentElement).getPropertyValue('--sign-pos-fill').trim()`, and rendered colours with `getComputedStyle(el).fill`, `.stroke`, `.color`, `.outlineColor`. The four theme configurations: `test.use({ colorScheme: 'light' })` or `'dark'`, and `await page.evaluate((t) => document.documentElement.setAttribute('data-theme', t), 'dark')` (or an init script that stores the value under the key the build records, then reload). Static cross-check: grep the built CSS in `site/dist/_astro/*.css` for each token and compare with the hex values of 6.3 and 8.3.

### 5.6 Motion

`page.emulateMedia({ reducedMotion: 'reduce' })` or `test.use({ reducedMotion: 'reduce' })`. `page.evaluate(() => document.getAnimations().map((a) => a.effect?.target?.toString()))`. Transitions: `getComputedStyle(el).transitionDuration` for every element under `[data-tool]`, expected `0s` (each comma-separated value) under reduce.

### 5.7 Axe

```ts
import AxeBuilder from '@axe-core/playwright';
const r = await new AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']).analyze();
```
