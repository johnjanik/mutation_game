# RT-04: codec-attacker

Applies from phase 1. Runs in: a worktree on branch `redteam/P{k}-RT-04`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the state object, the link codec and the address-bar plumbing of SPEC 6.6 and 7.4: `site/src/lib/state.ts`, `site/src/lib/urlCodec.ts`, the History API code, "Copy link", "Download data", and every tool and lesson page that reads a link on hydration. A build passes its gate with one unit test per validation rule, written by the same agent that wrote the codec, on the boards it had in mind: symmetric boards on which a transposed legality test agrees with the right one, finite boards whose labels start at 1 (and affine boards that all start at 0, although the presets `pentagon` and `square` start at 1), links that name every key so that no author default is ever combined with a link value, and caps tested on one board and one route (the 20000-move cap on `A1` only, the node cap on a custom matrix only) rather than through the affine names, the prefixes and the routes that also reach them. Every such blind spot lets a link show a position that the rules forbid (which SPEC 7.4 says can never happen), silently rewrite what the reader shared, or break links that were valid at an earlier phase (SPEC 6.6: "Old schema versions stay readable for as long as the site exists"). A reader who follows a shared link to a position no legal play reaches learns the wrong game, and the owner loses the promise that a link made today still opens tomorrow.

## 4. Attack list

Each attack names the phases in which it applies. "Notice" means the instance's notice that the link could not be read; "defaults" means the default state of that instance (the author's configuration on a lesson page, the tool's default on its own route), as CONTRACTS 4 passes it to `decodeState`. Run the unit form of an attack (method A) first and the browser form (method C) only where the attack says so.

1. **Transposed legality in `legal` mode** (phases 1 to 6). Try `/tools/board?g=B2&v=n&m=l&c=n&s=1,-1&w=1.2` and `/tools/board?g=C2&v=n&m=l&c=n&s=1,-1&w=1.2`. How: unit `decodeState` on both, then Playwright reading `data-value` of the two nodes and `data-moves`. The oracle (`fire` with `cartan('B',2) = [[2,-1],[-2,2]]`) says the word is legal on $B_2$ and ends at $(0,-1)$, and that on $C_2$ node 2 has number 0 after the first move, so the second move is forbidden. SPEC 6.6 ("a move that the mode in force forbids at that point of the play") and 7.4 ("A link can therefore never show a position the rules do not allow"). Failure: the $B_2$ link shows the notice, or the $C_2$ link is accepted and shows any position. Either means the codec judges legality with $C^{\mathsf T}$ (column against row of SPEC 2.3), which no symmetric board reveals. Severity blocker (a convention). Repeat with $G_2$ start `-1,1` and word `2.1` (legal on $G_2$, ends at $(-2,1)$; forbidden on the transpose), and with 200 random cases from method B.
2. **Transposed legality in `raising` mode** (phases 1 to 6). Try `/tools/board?g=B2&v=p&m=r&c=p&s=2,1&w=2` and the same on `g=C2`, and `/tools/kostant` with the same keys where its registry accepts them. The oracle: on $B_2$, $Cp=(3,-2)$, so city 2 may be mutated and the population becomes $(2,3)$; on $C_2$, $Cp=(2,0)$ and the move is forbidden. SPEC T1 table ("`raising` (only cities whose number $a_i$ is negative: Kostant's game)") and 6.6. Failure: the $B_2$ link is refused, or the $C_2$ link is accepted. Also $G_2$ population `1,1` and word `1` (allowed on $G_2$, forbidden on the transpose).
3. **A move legal at the start but not at that point of the play** (phases 1 to 6). Try `?g=A2&v=n&m=l&c=n&s=1,1&w=1.1` (the second firing of node 1 meets $-1$), `?g=A2&v=n&m=l&c=n&s=1,1&w=1.2.1.1` (the game is over after three moves; SPEC T1: "game over after 3 moves"), and `m=r` with a word whose third move meets a city with $a_i \ge 0$. How: unit and Playwright. SPEC 6.6, "at that point of the play". Failure: accepted, with the board showing a position no legal play reaches, or `data-moves` reporting 2 or 4. A codec that checks each label against the start only, or checks only the last move, passes the phase-1 acceptance test ("a forbidden move in w → defaults") if that test's forbidden move is the first one.
4. **Linked view judges `legal` on the numbers and `raising` on the populations** (phases 1 to 6). Try `?g=B3&v=l&m=l&c=p&s=1,0,0&w=...` with a word that is legal on $a=Cp$ and not on $p$ itself, and the converse; generate both with method B for $B_3$, $G_2$ and a one-way custom board. SPEC T1 table (legal: "only nodes whose number is positive"; raising: "only cities whose number $a_i$ is negative") and 6.6. Failure: the codec judges legality on whichever vector `coords` names rather than on the numbers.
5. **Labels from 0 on affine boards** (phases 2 to 6). Try `/tools/board?g=A2~&v=n&m=f&c=n&s=1,1,1&w=0.1.2` (must be accepted: labels of $\tilde A_2$ are 0, 1, 2 by E-7) and `w=1.2.3` (must give the notice: label 3 is not a label of the board). Same with `g=D4^(3)` (three nodes, labels 0, 1, 2 by the oracle's `board_from_name('D4^(3)')`: `s=1,1,1`, `w=0.1.2` accepted, `w=1.2.3` refused). On `g=B3~` the board has four nodes, labels 0, 1, 2, 3 (`board_from_name('B3~')`), so the start has four entries and the out-of-range label is 4: `s=1,1,1,1&w=0.1.2.3` accepted, `s=1,1,1,1&w=1.2.3.4` refused (label 4), and `s=1,1,1&w=0.1.2` refused (a start of three entries on a four-node board, rule of list lengths). Repeat each on `/tools/affine` (T15). SPEC 6.6 ("a label in `w` ... that is not a label of the board"), E-7 ("No golden test would notice a stray `+ 1` on a board whose labels start at 0"). Failure: `w=0.1.2` refused or `w=1.2.3` accepted; or accepted with the moves applied to the wrong nodes (compare `data-value` with the oracle's `fire` on `affine_extension`). Also check `encodeState` writes the label 0, not 1, after the reader fires node 0 (read `location.search` after the throttle of attack 21). Blocker. Then the mirror image: the presets `pentagon` and `square` are affine but labelled $1,\dots,n$ (E-7: "presets `pentagon`, `square`; custom boards | $1,\dots,n$"). On `/tools/affine` (T15 offers both) and on `/tools/board` if its registry offers them from phase 2, try `?g=pentagon&v=n&m=l&c=n&s=1,-2,3,-4,1&w=1.3.2.1.5.1.2.4.3.2.5.1.4.5` (golden `pentagon_example`: legal under the lowest-node rule, ends at $(0,0,0,0,-1)$; must be accepted and show that end), `?g=pentagon&v=n&m=f&c=n&s=1,1,1,1,1&w=1.2.3.4.5` (accepted), `w=0.1.2.3.4` and `w=0` (refused: 0 is not a label of the pentagon), and on `g=square` `w=1.2.3.4` accepted and `w=0` refused. Failure: `w=0...` accepted on either preset, or `w=1.2.3.4.5` refused on the pentagon; either means the codec gives every affine board labels from 0. Use `mode` only where the tool's registry reads it; on T15 use `m=f` if `m=l` is not one of its keys and judge the pentagon word with the oracle's `fire` instead.
6. **Labels against positions in `t`, `y`, `x`, `k`, `q`** (phases 4 to 6 by key). `y` and `t` are "the image of every node, in label order" as labels: on $A_3$ in T13 `t=3.2.1` (the flip) must be accepted and `t=2.1.0` (the flip written as positions) must give the notice; `x=0` must give the notice on every finite board; `k=0` on T12 must give the notice; `q=ef:0,1` must give the notice. SPEC 6.6 and E-7. Failure: any of these accepted, or the flip written in labels refused.
7. **A link that fails anywhere loads the whole default state** (phases 1 to 6). Try `?g=E8&v=n&m=l&c=n&s=1,1,1,1,1,1,1,1&w=1.99` on `/tools/board`, and on a lesson page `b1.g=E8&b1.w=99`. SPEC 6.6: "Any of the following makes the instance load its default state". Failure: the tool shows $E_8$ with no moves, or $E_8$ with the move list cut at the bad label (partial application), rather than the instance's defaults. On a lesson page also check that the default is the author's configuration for that instance (the `defaults` argument of CONTRACTS 4), not the tool's global default.
8. **A start beyond `SafeInt` on a named finite board** (phases 1 to 6). Try `?g=E8&v=n&m=f&c=n&s=9007199254740993,1,1,1,1,1,1,1&w=1` and a start of exactly 40 digits on `A2`. Failure: the notice appears; an `EngineOverflow` reaches the console or blanks the tool; or `data-value` shows a rounded number (for example `9007199254740992`, or `-9007199254740992` after the firing). 9. **A play that leaves `SafeInt` part way through the link** (phases 1 to 6). Start within the safe range and choose free-mode moves on $E_8$ or $G_2$ (method B, searching for the shortest word whose entries pass $2^{53}$) so that overflow happens at move $k>1$. Same standard as attack 8. Failure: notice, error, or a rounded `data-value` at any move after $k$ (step through the history strip and read each position).
10. **Caps exactly at the boundary** (phases 1 to 6). For each, the value at the cap must be accepted and the next one refused with the notice (SPEC 6.6, 5.6):

    - a start entry of 40 digits accepted (also with a leading minus sign: the sign is not a digit); 41 digits refused.
    - 12 nodes accepted and 13 refused, first with custom boards only, on `/tools/board`: the 12-node path `c:` matrix accepted, the 13-node path refused. Then named boards: `g=A13` must be refused on every route (13 nodes). `g=A12` and `g=D12` are not among the 32 named types of `golden_data.json` `types`, which are what a tool "whose description names no particular boards offers" (SPEC 4.0 Board pickers), so on `/tools/board` they fall under "a board that the tool does not offer" unless T1's registry `boards: 'all'` (the P1-A5 instruction) is read as every name `boardFromName` accepts. The `P1-A2` instruction already asks for unit tests at 512 and 513 characters, 40 and 41 digits, 20000 and 20001 moves (on `A1`) and a 13-node matrix, so the likely finds are on the routes, prefixes and board kinds those tests do not reach: the cap applied after prefix stripping or before, the length of `g` counted after a `%`-decoding that the test did not exercise, and the affine node count.
11. **Loosely parsed numbers** (phases 1 to 6). The grammar is "one integer per node in label order, separated by commas" (`s`, `d`) and "node labels ... separated by dots" (`w`). For `+1`, `01` and `-0` report what happens as a note unless the decisions fragment of `P1-A2` states a grammar that they break; the specification does not settle them.
