# RT-03: bounds-and-errors

Applies from phase 0. Runs in: a worktree on branch `redteam/P{k}-RT-03`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the edges of every computation: the arithmetic limit of `SafeInt` and the switch to `Big`, every cap of SPEC 5.6 and the flags that report it (`truncated`, `completeLayers`, `depthReached`, `status`, `null`), the interplay of `maxDepth` with a cap, the stop messages of SPEC 4.0, every error class of E-10 on every kind of board in the second table of 5.6, and matrices and names that are not boards at all. A build passes its gate with golden tests that sit comfortably inside every bound: the golden caps are 2000 and 100000 (with one more, 150000: SPEC 5.5, "the golden test of the star with five arms passes 150000 and finds 136008 positions in 18 layers") and never coincide with a layer boundary or an orbit size, no golden integer that a test reads as a JSON number exceeds $2^{53}$, the largest golden `weyl_dimension` is 3875, the only golden overflow test passes as long as the final entries are exact, and no golden key calls a function of the finite theory on an affine board. A defect at a bound shows as a silently wrong digit, a truncated result presented as complete, "stopped after 40 layers" on a search that ended by itself, a page that hangs, or a raw exception where the specification promises a stated limit, and the reader then learns a false fact about the mathematics.

## 4. Attack list

Phases are given in brackets. "Oracle" means a value computed by `reference/lie_games.py` through the bridge of method B; the values quoted below were computed that way for this file, and you recompute them before relying on them. Positions in code, labels on screen (E-7). Each attack has four parts: **Try** (the input), **How** (the method of section 5), **Spec** (what must happen), **Failure** (the observed value that is a finding, with its severity).

1. **`SafeInt` that checks only final entries gives a silently wrong digit** [phases 0 to 7].
   - Try: `safe = { n: 2, cartan: [[2, -3], [-3, 2]], labels: [1, 2], kind: 'gcm', arith: SafeInt }`; replay `bigint_test.mutation_nodes` (converted with `toPositions`) from `[1, 0]` with `mutate`, and `firing_nodes` from `[1, 0]` with `fire`, move by move. From phase 1 replay the same word through `applyWord`, and run `play` and `orbitGraph` on the same hand-built board.
   - How: method A, comparing every move by `show()` with the oracle's `replay` (method B); grep `packages/engine/src` for arithmetic operators applied to entries outside `arith.ts` (method D).
   - Spec: E-2, "every result checked with `Number.isSafeInteger`, a failure throws `EngineOverflow`". After 37 mutation moves the oracle has `(1304969544928657, 3416454622906707)`; move 38 forms `3 × 3416454622906707 = 10249363868720121`, which is unsafe, so move 38 throws `EngineOverflow` (`instanceof EngineError`, `.name === 'EngineOverflow'`). The firing replay throws during move 38 for the same reason.
   - Failure (blocker): move 38 returns any value (the float product rounds, so the result can differ from the oracle's `8944394323791464` in the last digit); no throw before move 40; a throw of another class (`RangeError`, `TypeError`); or `applyWord`, `play` or `orbitGraph` computing with native `*` and `+` and so bypassing the check.
2. **The limit is $2^{53}-1$, not $2^{53}$** [phases 0 to 7].

   - Spec: E-2.
   - Failure (blocker): any of the first five returns a value, which is what a bound written as `Math.abs(x) <= 2 ** 53` does. The golden test is blind to this: its first unsafe entry is far above $2^{53}$.

## 6. Not a finding for this lens

- `EngineOverflow` during move 38 rather than 39 on the `bigint_test` board: the per-operation check of E-2 throws on the unsafe product before the safe result (P0-A2 trap 6). A throw after move 39, or no throw, is the finding.
- The engine accepting 13 nodes, or more than 4 roads each way: the caps belong to the editor and to `resolveBoard` (SPEC 5.6 "(editor only; the engine accepts any count)"; P0-A2 trap 20).
- `boardKind([])` returning `'gcm'`: it follows the oracle; `fromAdjacency([])` must still throw.
- A function of the finite theory that returns a meaningless value on a non-finite board in phase 1: the guards arrive in phase 2 (E-11); before that the phase-1 tools call those functions only on named finite boards. A phase-1 tool that calls one on a custom board is a finding.
- The search with a cap smaller than the number of seeds, and a `maxDepth` of 0 with a cap below the seeds: the specification is silent and the oracle asserts. Report as a note.
