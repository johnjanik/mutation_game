# RT-11: test-integrity

Applies from phase 0. Runs in: a worktree on branch `redteam/P{k}-RT-11`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the tests themselves, not the product: every gate of `SPEC.md` 9.1 is a set of commands whose green result the orchestrator trusts, and this lens asks whether each green result could have been produced while the behaviour it names is absent or wrong. It hunts for tests that were skipped, focused, inverted or never run; assertions that were removed, loosened or made tautological; golden values copied into source; the reference files or `verify.py` changed; golden keys of the phase that no test really checks (the table of `SPEC.md` 5.7 cross-referenced with `GOLDEN_KEYS_BY_PHASE`, `coverage.json` and the test files); and tests that would pass against an empty or deliberately broken implementation (mutation testing by hand on a sample). It aims at the places where golden tests are blind by construction: symmetric boards that hide a transposition, labels that start at 1 and hide a `+ 1`, caps that fall exactly on a layer boundary, defaults never exercised by a link, strings compared loosely, behaviour off the finite boards, and release builds that no test ever builds. If this lens misses, every later phase is built on an engine and a site whose tests say more than they prove, and the owner reads gate reports that are green for the wrong reason.

## 4. Attack list

Each attack names the phases in which it applies; they are ordered from the most likely to find a blocker to the least. "Mutant" means a deliberate change made in your worktree and reverted before any commit (Methods 5.8); a mutant that the suite fails to catch is the finding, not the mutant.

1. **The reference files and every copy of them (phases 0 to 7).** What: `reference/golden_data.json`, `reference/lie_games.py`, `reference/verify.py`, every other file under `reference/`, and any copy of the golden file elsewhere. How: Methods 5.2: `shasum -a 256` of the three files against CONTRACTS 9; `git log` and `git diff` of `reference/` since the first commit; `git ls-files` to confirm the three are tracked and not ignored; a search for every `*.json` larger than 1 MB outside `node_modules` and `reference/`, hashed and compared; read where `_harness.ts` and `site/src/lib/golden.ts` load the file from (it must be `reference/golden_data.json`, CONTRACTS 3: "parsed once from reference/golden_data.json"). Then the hash guard: copy the golden file to your scratch directory with one digit changed and call `verifyGoldenHash` on the copy (Methods 5.2); read that the loader calls it before parsing and does not catch its error. Standard: CONTRACTS 9 "A difference is a blocker"; SPEC 9.3 "Do not edit `golden_data.json` by hand." Exemption: a commit whose only changes add or edit files under `reference/crosscheck/` is the owner's cross-check of SPEC 5.7 "Cross-checks outside the repository [D]" and is not a finding (if its author is not the owner, say so in `notes`); for such files check the other half of that sentence instead: `grep -rn "crosscheck" WT/package.json WT/packages/engine/package.json WT/site/package.json WT/scripts WT/.github WT/packages/engine/vitest.config.ts WT/playwright.config.ts WT/site/astro.config.mjs` and the root Vitest configuration, plus the `include` globs of every configuration (a glob such as `**/*.test.*` from the root would collect a test file under `reference/crosscheck/`). Finding: any hash differing (blocker; if `verify.py` differs by an added check, also a **note** for the owner, since SPEC 9.3 names that as the way to stop); any commit touching `reference/` after the first, apart from the exemption; a test, script, workflow step or build configuration that runs or imports anything under `reference/crosscheck/` (major: "never run in the site's build"); a second golden file read by a test or by `<G>`; a guard constant different from `c45474636fc9a7990c97c3664d2603f090b5b654a39352a87fc992f744e95a2f`; a guard that does not throw on the changed copy.

2. **`npm run verify` that cannot fail (phases 0 to 7).** What: `scripts/verify.mjs` and the root script body. How: Methods 5.10: point `verify.mjs` at a `python3` shim (through `PYTHON`, which P0-A6 5.2 defines (plan), and first on `PATH` as well); the shim intercepts only the oracle run (`[-u] .../reference/verify.py <output>`), passes every other call (the parsed comparison by `python3 -c`) to the real interpreter, and refuses any output path inside `reference/`; then run `npm run verify` five times: the shim writes the golden bytes and exits 0 (control: must pass); writes them with `"n_roots": 240,` changed to `"n_roots": 241,` and exits 0; writes the exact bytes and exits 1; writes nothing and exits 0; writes the same JSON re-serialised with `indent=2` (equal as parsed, different bytes) and exits 0. Afterwards hash `reference/`. Also read whether `verify.mjs` writes its temporary file inside `reference/`, compares the file with itself, or treats a missing summary line as success. Standard: SPEC 5.7 "fails unless the result is byte-for-byte the committed `reference/golden_data.json`"; SPEC 7.7 Oracle row "the oracle reports zero failures and reproduces the committed golden file byte for byte". Before trusting the five statuses, read the shim's log (Methods 5.10): each run must show exactly one intercepted oracle call; a run with none means `verify.mjs` reached a different interpreter and the statuses prove nothing about it. Finding: exit status 0 in any of the four non-control runs (blocker: a gate command that proves nothing), or any change to a reference hash; `verify.mjs` asking for an output file inside `reference/` (the shim refuses it with exit 5 and logs the path; blocker under CONTRACTS 1 "`reference/` read-only").

3. **Skipped, focused, conditional, inverted and soft tests (phases 0 to 7).** What: every file under `packages/*/test/`, `site/tests/`, and the configuration files. How: Methods 5.3: the grep for `.only`, `.skip`, `.todo`, `.fixme`, `.fails`, `test.fail`, `skipIf`, `runIf`, `xit`, `xdescribe`, `fit`, `expect.soft`, `--passWithNoTests`, `passWithNoTests`, `forbidOnly`, `retries`, `bail`, `|| true`, `continue-on-error`, `if: false`; then the runners' own counts: Vitest's and Playwright's skipped, todo and flaky counts in your full run (and in the gate report). A conditional skip (`test.skip(!process.env.X)`, `it.skipIf(...)`, an early `return` at the top of a test body) counts as a skip when the condition is false in the gate's environment. Standard: CONTRACTS 3 and SPEC 7.7 ("100 percent pass; required for every merge"); `COMMON.md` 4.4. Finding: a `.only` anywhere (blocker: it silences the rest of its file); a skipped, todo or inverted (`fails`, `test.fail`) test that belongs to a golden key, a property, an acceptance criterion or a gate item (blocker); any other skip (major); `forbidOnly` absent or false in `playwright.config.ts` for CI, `retries` above 0 without a decisions entry, `--passWithNoTests` in a script, `|| true` or `continue-on-error` on a test step in `ci.yml` (major).

4. **Test files that never run (phases 0 to 7).** What: every file whose name ends in `.test.ts` or `.spec.ts`, or that sits under a `test`, `tests` or `properties` directory. ### 5.10 `verify.mjs` shims

First read `WT/scripts/verify.mjs` for every way it starts Python: the interpreter (P0-A6 5.2 (plan): "`process.env.PYTHON` when set, else `python3`"), the oracle call (`[-u] <root>/reference/verify.py <tmp>/golden_regen.json`), and the parsed comparison when the bytes differ (`python3 -c` with `json.load`, plan). The shim must intercept the oracle call only, whatever its flags, and hand every other call to the real interpreter; it takes the output file as the last argument and refuses any output path that resolves inside `reference/`, so that no run can write there. Write `S/shim/python3` (then `chmod +x S/shim/python3`), a script file:

```bash
#!/bin/bash
# RT-11 shim for python3 (Methods 5.10). Intercepts only: python3 [-u ...] <path>/reference/verify.py <output file>
# Every other call (python3 -c ... for the parsed comparison, --version) goes to the real interpreter.
REAL=/usr/bin/python3
LOG="${RT11_LOG:-/dev/null}"
args=("$@")
while [ "${#args[@]}" -gt 0 ] && [ "${args[0]}" != "-c" ] && [ "${args[0]#-}" != "${args[0]}" ]; do args=("${args[@]:1}"); done
case "${args[0]}" in
  */reference/verify.py|reference/verify.py) ;;
  *) echo "pass: $*" >> "$LOG"; exec "$REAL" "$@" ;;
esac
if [ "${#args[@]}" -ne 2 ]; then echo "refuse (argument count): $*" >> "$LOG"; exit 4; fi
OUT="${args[${#args[@]}-1]}"
OUTDIR="$(realpath "$(dirname "$OUT")")"
REFDIR="$(realpath "$RT11_WT/reference")"
case "$OUTDIR/" in "$REFDIR"/*) echo "refuse (output inside reference/): $OUT" >> "$LOG"; exit 5 ;; esac
echo "oracle $RT11_MODE: $*" >> "$LOG"
G="$RT11_GOLDEN"
case "$RT11_MODE" in
  same)  cp "$G" "$OUT"; echo "6649 checks passed, 0 failed, 1.0s; wrote $OUT"; exit 0 ;;
  flip)  sed 's/"n_roots": 240,/"n_roots": 241,/' "$G" > "$OUT"; echo "6649 checks passed, 0 failed, 1.0s; wrote $OUT"; exit 0 ;;
  exit1) cp "$G" "$OUT"; echo "6648 checks passed, 1 failed, 1.0s; wrote $OUT"; echo "FAILED:"; echo "  - rt11"; exit 1 ;;
  none)  echo "6649 checks passed, 0 failed, 1.0s; wrote $OUT"; exit 0 ;;
  ws)    "$REAL" -c "import json,sys; json.dump(json.load(open(sys.argv[1])), open(sys.argv[2], 'w'), indent=2)" "$G" "$OUT"; echo "6649 checks passed, 0 failed, 1.0s; wrote $OUT"; exit 0 ;;
esac
exit 3
```

Confirm `/usr/bin/python3` and `realpath` exist (`/usr/bin/python3 --version`, `realpath /`); if `python3` on `PATH` is elsewhere, set `REAL` to that path (`command -v python3` before the shim is on `PATH`). Run, one call each: `RT11_MODE=same RT11_WT=WT RT11_LOG=S/shim-same.log RT11_GOLDEN=WT/reference/golden_data.json PYTHON=S/shim/python3 PATH=S/shim:$PATH npm --prefix WT run verify` (expected exit 0), then `flip`, `exit1`, `none`, `ws` (each expected non-zero; a log file per mode). Each log must hold exactly one `oracle` line; `pass` lines show the parsed comparison reaching the real interpreter (expected in `flip` and `ws`); a `refuse` line is itself a finding (attack 2). If `verify.mjs` calls Python by an absolute path or by a mechanism other than `PYTHON` and `PATH`, read it and point the shim there by its own mechanism; say so in the finding. After the five runs, hash `reference/` (5.2). Do not run the real oracle in a loop; one real `npm run verify` (about 133 seconds on this machine) is enough for the control.
