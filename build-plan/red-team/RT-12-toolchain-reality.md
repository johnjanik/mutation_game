# RT-12: toolchain-reality

Applies from phase 0. Runs in: a worktree on branch `redteam/P{k}-RT-12`.

Before this file you have read `build-plan/RED-TEAM-COMMON.md` and `build-plan/CONTRACTS.md`. Everything there applies.

## 1. Mission

This lens attacks the gap between the toolchain the specification names and the toolchain the repository actually runs: the pinned versions, the lockfile, the build modes, the configuration files, the workflows and the self-hosted KaTeX assets. Every tool in the stack (Astro 7, Svelte 5, Vite 8, Vitest 5, TypeScript 6, KaTeX 0.16 to 0.19) postdates most of what the builders know, so a build can pass its gate on the builder's machine while a test runner silently ignores a configuration file, a release build silently renders preview markup, a stylesheet from one KaTeX version dresses HTML from another, a link typed with a leading slash works only at the root, or a deploy workflow fails the first time the owner pushes a tag. If this lens misses, the owner inherits a site whose green gate proves less than it says, whose release build shows open items as fact, and which breaks the day it is served under `/<repository>/`.

## 4. Attack list

Each attack names the phases in which it applies. Severity guidance follows `RED-TEAM-COMMON.md` 4: a gate command that fails or does not do what 7.7 says, or a test suite that passes while tests are not run, is a blocker; a release build that renders preview semantics is a blocker when it prints an open [U] statement as fact, else major; a version, workflow or configuration rule broken is major; a naming or comment issue is minor. Run every attack against a clean clone of the gate commit (Methods 5.1), never against the builder's working tree, because leftovers (a `names.json`, a `site/public/katex/` copy, a `node_modules` from `npm install`) are exactly what hide these failures. The only exceptions are the ignored outputs `GATE` leaves in the primary checkout's `reports/` (the G6 open-items report of attack 6 and the release archives of attack 34), which no clone contains; read those read-only where they are (Methods 5.1).

1. **The root Vitest configuration is not the file Vitest 5 reads (phases 0 to 6).** What: `npm test` from the root. How: list the test files Vitest collects (`npx --prefix <clone> vitest list --root <clone>`, or `vitest run --reporter=json` and count `testResults`), and list the files on disk (`find <clone>/packages/engine/test <clone>/site/tests/unit -name '*.test.ts'`). Read the installed Vitest's own types and changelog (`<clone>/node_modules/vitest/package.json`, its `dist/*.d.ts` for `projects` and `workspace`) to see which file 5.0.3 honours. Standard: CONTRACTS 1 "The Vitest root configuration is whichever file Vitest 5.0.3 reads (`vitest.workspace.ts` or `test.projects` in a root `vitest.config.ts`)"; SPEC 7.7 "`npm test` (Vitest: the engine, and the unit tests of `site/tests/unit`)"; 7.2 item 6 "older configuration examples may not apply". Failure: the collected set differs from the files on disk (for example the site unit tests or the engine golden tests missing), a deprecation warning that the workspace file is ignored, or a site test run with the engine's environment. A suite that reports green while skipping files is a blocker.
2. **A gate command fails from a clean clone (phases 0 to 6).** What: every command of 7.7, in the order of Methods 5.1, from a fresh `git clone` of the gate commit with no `node_modules`, no `site/dist`, no `site/src/generated`, no `site/public/katex`. Standard: SPEC 7.7 commands (quoted in section 2); SPEC 9.1 G0 "a preview build and a release build both succeed"; CONTRACTS 1 root scripts. Failure: a non-zero exit of `npm ci`, `npm test`, `npm run typecheck`, `npm run check`, `npm run build`, `RELEASE=1 npm run build`, `npm run e2e`, `npm run size`, `npm run verify`, `npm run report` (and `npm run lab` from phase 3); `npm run preview` failing to start a server on the built `site/dist` (start it in the background, request `/` under the base, then stop it); a `check` script that does not run both `typecheck` and `test` (CONTRACTS 1 "(plan: typecheck + test)"); a command that passes only after a second run (a build that needs a file the first build writes); a command missing from root `package.json`. In phases 0 to 2 `npm run lab` may exit 2 with its stub message (`P0-A6`); that is not a finding. Record each exit code and the last line of output.
3. **`build:release` skips the prebuild step (phases 0 to 6).** What: `npm run build:release` and `RELEASE=1 npm run build` from a clean clone, each into its own clone. How: after each, check that `site/src/generated/names.json` exists, that `site/public/katex/` (or the versioned directory `P0-A3` chose) exists, and that `site/dist` contains the KaTeX stylesheet the HTML links. npm runs a `prebuild` script only for `build`; a `build:release` defined as `RELEASE=1 astro build` runs neither `names.mjs` nor `katex-assets.mjs` unless it calls them itself. Standard: SPEC 7.3 "`names.mjs` ... runs at the start of every build"; CONTRACTS 1 "`npm run build` must run `scripts/names.mjs` first"; CONTRACTS 4 the KaTeX assets copied "at build time". Failure: a release build that fails on a missing `names.json`, or succeeds but ships a page whose KaTeX stylesheet link returns 404, or ships the stale assets of an earlier build. Do the same for the `e2e:basepath` build and the deploy workflow's build command (attack 20).
4. **`RELEASE` never reaches the components (phases 0 to 6).** What: the real release build, not a unit test. How: add a fixture page on the lens branch (`site/src/pages/redteam-rt12-unverified.astro`, or an `.mdx` with `released: false`) that uses `<Unverified item="E4" fallback="FALLBACK-RT12">SENTENCE-RT12</Unverified>`, and a second use without a fallback. Every item of `unverified.json` is open and the lens never closes one, so the closed-item branch is checked by reading its code path only. Build twice: `npm run build` and `RELEASE=1 npm run build`. Grep both outputs. Read how `Unverified.astro` reads the mode: `process.env.RELEASE` at build time works; `import.meta.env.RELEASE` is exposed by Vite only for variables it is told to expose, so it can be `undefined` in the real build while a test that sets `process.env.RELEASE` passes. Standard: SPEC 7.3 "A preview build (the default) renders the wrapped sentence with a visible mark that links to the item on the page `open-items`. A release build (`RELEASE=1 npm run build`) renders a closed item's sentence unmarked, and for an open item renders the `fallback` text in its place, or nothing when no fallback is given." Failure: `SENTENCE-RT12` present in the release output, `FALLBACK-RT12` absent, text from the no-fallback use present in the release output, or an `open-items` link in the release output (blocker: an open [U] statement printed as fact); in the preview output, `SENTENCE-RT12` without a mark or the mark's link not ending in `open-items#E4` under the base (major).

import { readFileSync } from 'node:fs';
import { execFileSync } from 'node:child_process';
const SPEC = { // SPEC 7.1 and 7.2 items 1 to 3, as written there
  'astro': '7.3.8', '@astrojs/mdx': '8.0.3', 'svelte': '5.57.2', '@astrojs/svelte': '9.0.1',

for (const [where, m] of manifests)
  for (const field of ['dependencies', 'devDependencies', 'peerDependencies', 'optionalDependencies'])
    for (const [name, spec] of Object.entries(m[field] ?? {})) {
      const exact = /^\d+\.\d+\.\d+$/.test(spec);

      rows.push({ where, field, name, spec, exact, locked, registry, specWants: SPEC[name] ?? '-', ok: exact && locked === spec && registry === spec && (!SPEC[name] || SPEC[name] === spec) });

console.table(rows);

Build: `BASE_PATH=/sub/path/ OUT_DIR=<scratch>/dist-sub npm --prefix <scratch>/clone run build` (if `OUT_DIR` is ignored, that is itself a finding against CONTRACTS 1; then copy `site/dist` aside after the build). The crawler, `redteam/rt12/basepath-crawl.mjs <outDir> <base> <origin>`:

```js
import { readFileSync, readdirSync, statSync } from 'node:fs';
import { join, relative } from 'node:path';
const [outDir, base, origin] = process.argv.slice(2);
const files = []; (function walk(d) { for (const f of readdirSync(d)) { const p = join(d, f); statSync(p).isDirectory() ? walk(p) : files.push(p); } })(outDir);
const urls = new Map(); // url -> first file that references it
const add = (u, f) => { if (!u || /^(https?:|mailto:|data:|#|javascript:)/.test(u)) return; if (!urls.has(u)) urls.set(u, relative(outDir, f)); };
for (const f of files) {
  const t = readFileSync(f, 'utf8');
  if (f.endsWith('.html')) {
    for (const m of t.matchAll(/\s(?:href|src|action|poster|data-src|data-href)="([^"]+)"/g)) add(m[1], f);
    for (const m of t.matchAll(/\ssrcset="([^"]+)"/g)) m[1].split(',').forEach(s => add(s.trim().split(/\s+/)[0], f));
  }
  if (f.endsWith('.css') || f.endsWith('.html')) for (const m of t.matchAll(/url\(\s*['"]?([^'")]+)/g)) add(m[1], f);
  if (f.endsWith('.js')) for (const m of t.matchAll(/(?:fetch|new URL|new Worker|href\s*=)\s*\(?\s*["'`](\/[^"'`]*)/g)) add(m[1], f);
}
const bad = [];
for (const [u, f] of urls) {
  if (u.startsWith('/') && !u.startsWith(base)) { bad.push({ u, f, why: 'outside base' }); continue; }
  if (u.includes(base.replace(/\/$/, '') + '/' + '/') ) bad.push({ u, f, why: 'double slash' });
}
console.table(bad);
// then request every absolute URL under origin and record any status other than 200 (resolve relative URLs against the referencing file's path)
```
