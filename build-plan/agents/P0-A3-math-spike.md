### 5.2 The version rule (SPEC 7.2 item 2; CONTRACTS 4; Appendix H)

SPEC 7.2 item 2, verbatim: "The stylesheet and fonts shipped must come from the same KaTeX version that produced the HTML." And: "Self-host them." The reason is in the same item: KaTeX 0.17 (May 2026), 0.18 (July 2026; "CSS class names were prefixed, so custom selectors written for 0.16 fail") and 0.19 (1 October 2026) were breaking minor releases; `rehype-katex` 7.0.1 "still depends on `katex ^0.16`". CONTRACTS 4 restates it as a contract: "The installed KaTeX version, its CSS and its fonts are one package: `site/public/katex/` is copied from `node_modules/katex/dist` at build time by `scripts/names.mjs` or a prebuild step, never hand-copied." Appendix H: "KaTeX CSS and fonts must match the KaTeX version that rendered the HTML. Self-host them." SPEC 7.8: "Fonts and KaTeX assets are self-hosted."

Operative rules:

- Exactly one `katex` is installed in the repository, at an exact version in `site/package.json`. Under route (a) that version is the one `rehype-katex` 7.0.1 resolves (a 0.16.x); pin it explicitly so that npm dedupes to one copy. Under route (b) it is the current 0.19.x from the registry on the day you build. `npm ls katex` must show one entry and no nested copy.
- `renderTex`, `katex-assets.mjs` and `names.mjs` resolve `katex` from `site/` (Node's `createRequire` with the URL of `site/package.json`, then `require.resolve`), never through a hard-coded path into the root `node_modules`, and never through a second import of a different version.
- `KATEX_VERSION` is read from the installed package's `package.json` at module load, never typed into source. The `exports` map of KaTeX 0.16.47 and 0.19.0 contains `"./*": "./*"` (registry, 10 October 2026), so `require.resolve('katex/package.json')` and `require.resolve('katex/dist/katex.min.css')` work; check the installed package all the same, and fall back to deriving the package directory from the resolved main entry if a version ever drops that export.
- The stylesheet path carries the version: `katex/<KATEX_VERSION>/katex.min.css` under the base path. The test of section 6 compares the copied CSS byte for byte with the installed `dist/katex.min.css` and the copied font list with the installed `dist/fonts/`.
- Nobody writes CSS selectors into KaTeX's internal class names; the class names changed in 0.18 and may change again. Style, if ever, the wrapper you own. Tests find formulas by the `<math` element, or by a class attribute that contains `katex`, never by an exact `.katex-...` selector.

### 5.3 `site/src/lib/katex.ts` (CONTRACTS 4; roster deliverable 4; SPEC 7.5 A-12)

The contract, from CONTRACTS 4:

```ts
export function renderTex(src: string, display: boolean): string;   // KaTeX renderToString in Node, MathML included (A-12), throwOnError: true
```

Plus two exports this plan adds:

```ts
export const KATEX_VERSION: string;                      // (plan) read from the installed katex/package.json
export function katexStylesheetHref(base: string): string;  // (plan) `${base}katex/${KATEX_VERSION}/katex.min.css`, with exactly one slash between base and "katex"
```

Rules:

- `renderTex` calls `katex.renderToString(src, { displayMode: display, output: 'htmlAndMathml', throwOnError: true, trust: false })` (roster deliverable 4). `output: 'htmlAndMathml'` is SPEC 7.5 A-12: "Mathematics is rendered with MathML available to assistive technology (KaTeX's default output)." Set it explicitly all the same. `trust: false` keeps `\url`, `\href` and raw HTML commands off. `throwOnError: true` means a malformed formula throws KaTeX's `ParseError`; `renderTex` catches nothing, prints nothing, and never returns fallback text. The rule that a malformed formula fails the build through `throwOnError` comes from CONTRACTS 4 ("throwOnError: true") and the roster ("throwOnError true"), not from SPEC 7.7: the Content row of SPEC 7.7 reads "the build fails on an unknown `<Cite>` key or an unresolved `<G>` or `<Tex>` path", which is a golden-path failure that P0-A4 implements, not a KaTeX parse error. Leave `strict` at its default and record that choice (plan; neither SPEC nor the roster names `strict`). KaTeX's default `strict` is `"warn"`: an input that is valid KaTeX but not valid LaTeX is rendered, and KaTeX itself (not `renderTex`) writes a warning to the console at build time. No formula of 5.1 and no name of 5.5 should produce one: after the build of step 9 run `grep -c 'LaTeX-incompatible' <build log>` and paste the result (expected 0) in `commandsRun`; if a warning appears, report the input in the fragment and in `openQuestions` rather than changing `strict`.
- `renderTex` is the one call that SPEC 7.3 means by "the same KaTeX call that `<Tex>` uses": P0-A4's `Tex.astro` (after `{{path}}` substitution, digits grouped with `\,`), P1-A4's `sources.astro` (the `$...$` of `SOURCES.md`, which does not pass through MDX) and the index page's one formula (P0-A5) all import it from `@lib/katex`. It must therefore accept every shape found in `SOURCES.md` today, among them these ten, quoted exactly from the file: `C = M^{\mathsf T}`, `\mathfrak{so}^*(10)`, `2\pi/h`, `e^{2\pi i m_j/h}`, `\tilde A_4`, `-w_0`, `\tilde s_i = w_{X\cup\{i,\tau(i)\}}\,w_X^{-1}`, `\exp(\operatorname{ad}x)\exp(\operatorname{ad}(-y))\exp(\operatorname{ad}x)`, `\langle h_i, \mathrm{wt}(b)\rangle`, `U_q(\mathfrak g)`.
- The module runs in Node at build time only. It is imported from `.astro` frontmatter and from tests; it is never imported by a `.svelte` file or any script that reaches the browser (SPEC 7.6: "No typesetting library, no layout engine and no polyfill bundle is sent to the client."; SPEC 7.1 "Mathematics in prose": "no typesetting script is sent to the reader; KaTeX output carries MathML for assistive technology"). Mathematics produced while a tool runs is made from plain markup by `MatrixView.svelte`, `Frac.svelte` and `LinearForm.svelte` (phases 1 to 5), not by this module.
- No DOM access, no `console.log`, no `any` without a comment (COMMON 4.4).

## 9. Traps

- **Never mix KaTeX versions** (roster trap 1; SPEC 7.2 item 2). "KaTeX 0.18 prefixed CSS class names; a stylesheet from one version with HTML from another breaks silently." The way it happens by accident: `site/package.json` pins 0.19.x while `rehype-katex` needs `^0.16`, so npm nests a second copy under `node_modules/rehype-katex/node_modules/katex`, and the page carries two kinds of markup under one stylesheet. `npm ls katex` after every install.
- **Astro 7's default Markdown processor runs no remark or rehype plugins** (roster trap 2; SPEC 7.2 item 1). `astro` 7.3.8 depends on `@astrojs/markdown-satteri`, not on `@astrojs/markdown-remark`. The `processor` key of `markdown` in `astro.config.mjs` is where `unified()` goes. Whether `.mdx` inherits it is [S2] and unrun; your build settles it. Do not write the Astro 4 or 5 form `markdown: { remarkPlugins, rehypePlugins }` from memory.
- **Backslashes in an MDX attribute must reach KaTeX unchanged** (roster trap 3; SPEC 7.3). Test with `\frac`. Two MDX-specific hazards: a quoted JSX attribute decodes HTML entities, so `&lt;` becomes `<` before KaTeX sees it (the matrix row `2&-1\\-2&2` is safe because `&-` is not an entity); and `{...}` outside quotes is a JavaScript expression, so `{{types.E8.weyl_order}}` works only inside a quoted `src="..."`, which is how SPEC 7.3 writes it.
- **Do not install three.js, a layout library or `satteri-katex`** (roster trap 4).
- **Class names are not a stable hook.** The roster asks for "a katex span"; test for a `class` attribute that contains `katex` and for `<math`, never for an exact selector such as `.katex-display`, which 0.18 may have renamed. Display mode is proved by `display="block"` on the `<math` element, which KaTeX emits in display mode (plan; confirm against the installed version on the first run of `katex.test.ts` and record the result in the fragment).
- **`set:html` in Astro.** Astro escapes interpolated strings; `{html}` prints KaTeX markup as text and looks like a failed route. Use `<span set:html={html} />` or `<Fragment set:html={html} />`. SPEC 7.2 item 1 adds that Astro 7's compiler rejects invalid HTML that earlier versions tolerated [S2]; KaTeX output is valid, so a compiler error points at your page, not at KaTeX.
- **MDX and `$`.** Under route (a) `remark-math` treats every `$...$` as mathematics; a dollar sign in prose must be written `\$`. `$$...$$` must stand as its own paragraph to be display mathematics. `<` and `{` inside `$...$` are consumed by the math tokenizer before MDX sees them; the spike page checks exactly this, so keep those two formulas in it.
- **A malformed formula under route (a) does not fail the build.** `rehype-katex` is expected to catch the parse error, add a file message and render the source in KaTeX's error colour. A malformed `<Tex>` source fails the build because `renderTex` sets `throwOnError: true` (CONTRACTS 4 and the roster; SPEC 7.7's Content row speaks only of unresolved `<G>` and `<Tex>` paths); nothing makes a malformed `$...$` fail. Record what you observe, and put a proposal (surface those messages as build failures) in `openQuestions`; do not add a plugin for it now.
- **`import.meta.env.BASE_URL` and slashes.** Whether Astro's `BASE_URL` ends with a slash depends on configuration; `katexStylesheetHref` joins with exactly one slash and never starts the path with `/` on its own. A typed leading slash fails P0-A6's `BASE_PATH=/sub/path/` test.
