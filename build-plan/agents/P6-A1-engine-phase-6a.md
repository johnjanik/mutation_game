### 5.2 Common rules for all five functions

- **Positions in, positions out (E-7).** `d.black`, `d.tau`, `p`, `root` and every node in every result are positions $0..n-1$. The oracle's `satake` returns 1-based node numbers (`w_X_word`, `restricted_simple_orbits`, `restricted_orbits_in_bourbaki_order`) and its `admissibility` returns sentences with 1-based numbers; you return positions and `Reason` data. Never add or subtract 1 in `src/`; tests convert with `toLabels` and the harness's `labels`.
- **Guards (5.6, E-11).** On a `one-way` board every one of the five throws `NeedsTwoWayRoads`; on a `gcm` board not of finite type (for example `boardFromName('A2~')`) every one throws `NotFiniteType`. Decide through `guards.ts` (`requireGcm`, `requireFinite`) as the first statement, never by running an enumeration into a cap. `classifyRestricted` takes a set, not a board, and has no guard (as `P4-A1` wrote it).
- **Malformed input (plan, as `P4-A1` did for symmetries).** `d.tau` that is not a permutation of `0..n-1` (wrong length, repeated or out-of-range entry), or `d.black` with a repeated or out-of-range entry, throws `RangeError`. `d.black` is used sorted (the oracle sorts `X`); the input array is not mutated (E-5).
- **Pure (E-5).** No hidden state. Compute the word of $w_X$ once per call and pass it to a private helper rather than caching across calls (the oracle's optional `wx` argument is an internal convenience; it is not part of the contracted signature).
- **Arithmetic.** Populations and shadows are integers (`number` on the `SafeInt` boards that named finite types use, E-2). The form is rational (`gram`, E-3). Internal searches use `roots(board, CAPS.workerPositions)`; a finite board of at most 12 nodes has at most 288 roots, so the enumeration is exact (plan, as `P1-A1`).
- **Errors (E-10).** `satake` and `restrictedBoard` throw `NotAdmissible` carrying the `Admissibility` record (as `data`, the field `P0-A2` declared) on any pair whose `admissible` is false. Message (plan): `not admissible: ` followed by the key of the first failed item in the oracle's order `symmetry`, `condition_1`, `condition_2`, `condition_3` (oracle `admissible`, l.526 to 533). The oracle's `assert` statements become `throw new EngineError(<the oracle's message>)` (plan, as `P4-A1`). Reaching a cap is never thrown; no cap is reachable here on a finite board.

### 5.3 `theta(d, p)` (oracle `theta`, l.464; SPEC 2.15)

$\theta=-w_X\circ\tau$ on a population, in exactly the oracle's three stages:

1. Permute by $\tau$: `q[tau[i]] = p[i]` for every position `i` (entry `i` moves to position `tau(i)`; "move each city's population along the arrows of $\tau$").
2. Play the word of $w_X$, `wx = longestWord(d.board, black)`, as mutations, letters in order (`applyWord(board, q, wx, 'mutation')`).
3. Negate every entry.

Returns `number[]`. `theta` does not check admissibility: on $A_2$ with node 1 black and no arrow it is $-s_1$, an involution that permutes the roots [V], and it must return that. Examples (A.5): on `su(1,2)`, $\theta(p_1,p_2)=-(p_2,p_1)$, so `theta` of `[0, 1]` is `[-1, 0]`; on `su*(4)` (black positions `[0, 2]`, identity) `theta([0, 1, 0])` is `[-1, -1, -1]` and `theta([1, 0, 0])` is `[1, 0, 0]`; on `su(1,3)` (black `[1]`, $\tau$ `[2, 1, 0]`) `theta([0, 0, 1])` is `[-1, -1, 0]` and `theta([0, 1, 0])` is `[0, 1, 0]`.

### 5.4 `shadow2(d, root)` (oracle `shadow2`, l.536)

The integer vector $\alpha-\theta\alpha=2\bar\alpha$, entry by entry: `root[i] - theta(d, root)[i]`. Shadows are always kept doubled, as integers (SPEC 2.15: "In the engine, shadows are kept as the integer vectors $2\bar\alpha$"). Examples: `su(1,2)`, `shadow2([0, 1])` is `[1, 1]` (the shadow $(1/2,1/2)$ of A.5); `su*(4)`, `shadow2([0, 1, 0])` is `[1, 2, 1]` and `shadow2([1, 0, 0])` is `[0, 0, 0]` (a root of the black sub-board).

### 5.5 `admissibility(d)` (oracle `admissibility`, l.489; SPEC 2.15 "Which pairs are real forms")

Every item is judged on its own, whatever the others say (the three lights of T13; SPEC 2.15: "The three conditions are judged independently of one another"). With `X` the sorted black positions, `n` the rank:

- `symmetry`: `C[tau[i]][tau[j]] == C[i][j]` for all `i`, `j` (Cartan matrix entries of the board).
- `condition_1`: `tau[tau[i]] == i` for all `i` (involution) **and** the set `{tau[i] : i in X}` equals `X`.
- `condition_2`: `wx = longestWord(board, X)`; the failing set is every `i` in `X`, in increasing position, for which `applyWord(board, e_i, wx, 'mutation')` differs from `-e_{tau[i]}` ($w_X(\alpha_i)=-\alpha_{\tau(i)}$). Computed even when `symmetry` or `condition_1` fails. `condition_2` is true when that set is empty. On an empty `X` it is vacuously true.
- `condition_3`: with `B = gram(board)` (rationals) and `pos` the positive roots of the black sub-board embedded in full coordinates (oracle `sub_positive_roots`: roots of `subBoard(board, X)`, positive ones, each entry `k` placed at position `X[k]`; empty when `X` is empty), for every position `i` not in `X` with `tau[i] == i`, the rational $\langle\alpha_i,\rho_X^\vee\rangle=\sum_{\beta\in\Phi_X^+}(\alpha_i,\beta)/(\beta,\beta)$, each term `bil(B, e_i, b) / bil(B, b, b)`. The failing set is every such `i`, in increasing position, whose value is not an integer. Computed even when the others fail (the `satake_examples` row $A_3$, black 1, flip: all three fail, condition 3 at node 2 with $-1/2$).
- `admissible`: `symmetry && condition_1 && condition_2 && condition_3`.
- `reasons`: an entry only for each failed item, under the keys `symmetry`, `condition_1`, `condition_2`, `condition_3` (SPEC 5.2 comment "keys: symmetry, condition_1, ..."). Each is a `Reason` with a code and positions, never a sentence (the tool writes the sentence with labels, SPEC 4 T13 and E-7):

| Key | `code` | `nodes` | `value` |
|---|---|---|---|
| `symmetry` | `'not-a-symmetry'` | (plan) the positions `i`, increasing, for which some `j` has `C[tau[i]][tau[j]] != C[i][j]` | absent |
| `condition_1` | `'not-an-involution'` when $\tau^2\ne1$ (this takes precedence, as in the oracle), else `'moves-black-set'` | (plan) for `not-an-involution` the positions `i` with `tau[tau[i]] != i`; for `moves-black-set` the black positions `i` with `tau[i]` white | absent |
| `condition_2` | `'differs-from-minus-wX'` | the failing set of condition 2 (oracle `bad2`, as positions) | absent |
| `condition_3` | `'not-an-integer'` | the failing set of condition 3 (oracle `bad3`, as positions) | the fraction as text through `ratToString` (`"-1/2"`, `"-3/2"`) |

  Several white nodes can fail condition 3 with **different** fractions (on $A_5$ with black nodes 1, 2, 4 and the identity, the oracle reports $-3/2$ at node 3 and $-1/2$ at node 5; this happens for 534 pairs on the boards of rank at most 8). The contract has one `value`. Plan, pending confirmation by the orchestrator: when one node fails, `value` is its fraction; when several fail, `value` lists their fractions in the order of `nodes`, separated by `"; "` (the oracle's own separator). Record this in your fragment, name it in `openQuestions`, and tell `P6-A3` in `handoff`.

- The golden file holds `reasons` as sentences; no test compares them (5.2, rule 6). Your `reasons.test.ts` checks codes, nodes and values instead.

### 5.6 `satake(d)` (oracle `satake`, l.587; SPEC 2.15, 6.4)

First `admissibility(d)`; if `admissible` is false, throw `NotAdmissible` (SPEC 2.15: "The engine function `satake` refuses a pair that is not admissible instead of returning numbers for it"). Then, with `R` all roots, `B = gram(board)`, `wx = longestWord(board, X)`, `th[a] = theta(a)` for every root (one `wx` for all):

- Internal checks, ported from the oracle's asserts (plan: `EngineError` with the oracle text): every `th[a]` is a root (`'theta does not preserve the roots'`); `th[th[a]] == a` (`'theta is not an involution'`); the number of roots with `th[a] == a` equals $|\Phi_X|$ = 2 times the number of positive roots of the black sub-board; for every positive root with `th[a] != a`, every entry of `th[a]` is at most 0; multiplicity constant on each length class (`'multiplicity not constant on a length class'`); each simple restricted root has $m_\lambda>0$ and is never twice a restricted root. These are the statements SPEC 2.15 says "are asserted inside the oracle function `satake` for every record it computes [V]"; keep them.
- Count per root: `th[a] == a`: compact imaginary (restricts to 0, not a restricted root); `th[a] == -a`: real; otherwise complex. For every non-compact root, its shadow `shadow2(a)` is counted in a multiset `restr` (the oracle keys by $\tfrac12(a-\theta a)$ as fractions; keying by the doubled integer vector is the same multiset).
- `rank` = `n`.
- `real_rank` = $r$ = the number of $\tau$-orbits of white nodes (oracle `tau_orbits(tau, white)`), **not** computed from the span. SPEC 2.15 says it is "checked as the dimension of the span of the shadows": your test checks that span for all 167 records (section 6).
- `restricted_type`, `multiplicities`: when $r=0$, `null` and `[]`. Otherwise `classifyRestricted(S, B, r)` on `S`, the set of distinct shadows (pass the integer doubled shadows: `classifyRestricted` is invariant under scaling every vector by 2, since only norm ratios, counts and the "double is in the set" test are used; plan). `restricted_type` is its `name` (`B2` for every rank-2 $B$/$C$ system, `BC1`, `BC2`, ...). `multiplicities` is one entry per class, **in the order `classifyRestricted` returns them (ascending norm)**: `{ class, roots, mult }` where `class` and `roots` come from the class and `mult` is the common value of `restr[v]` over the shadows `v` of that class (match a shadow to a class by its norm under `B` on the same vectors that were passed; `classifyRestricted` returns `form_value` as text, so compare `ratText` of the norm, or compute the class membership yourself in the same ascending order, plan). Class labels are the oracle's: `'all'`, `'short'`, `'long'`, and for $BC_r$ with $r\ge2$ `'short'`, `'medium'`, `'long'`.
- `n_restricted_roots` = number of distinct shadows (`|S|`, 0 for a compact form).
- `dim_g` = `n + |R|`; `dim_k` = $(n-r)+\tfrac12(|\Phi|+|\Phi_X|)$; `dim_p` = $r+\tfrac12(|\Phi|-|\Phi_X|)$ (both halves are exact); `character` = `dim_p - dim_k` (the closed form $2r-n-|\Phi_X|$ is [D] for its presentation as a derived formula on the site; the engine computes the difference, as the oracle).
- `roots_compact_imaginary`, `roots_real`, `roots_complex`: the three counts above.
- `w_X_word` = `wx` (positions; the golden field holds labels).
- `restricted_simple_orbits`, `restricted_simple_multiplicities`, `restricted_cartan`, `restricted_reflection_word_lengths`: from `restrictedBoard` (5.7). For each orbit `O` with simple doubled shadow `s`: `[restr[s], restr[2s] or 0]` $=(m_\lambda,m_{2\lambda})$.
- `restricted_board`, `restricted_orbits_in_bourbaki_order`: when there is at least one orbit and the restricted Cartan matrix is connected (oracle: `identify_labelled(Cbar) if orbs and len(components(Cbar)) == 1`), `identify` of the restricted board gives `{ name, order }`; `restricted_board = name` and `restricted_orbits_in_bourbaki_order = order.map(k => orbits[k])`. Otherwise both `null`. `identify` tries $A, B, C, \dots$ in order, so rank 2 is `B2` and a $BC_r$ system's board is `B` $r$ (`A1` for $r=1$): you write no special case for it. **This departs from the roster's wording**, which says "restricted_board named by classifyRestricted (B_r for BC_r, A1 for r = 1)". ### 5.7 `restrictedBoard(d)` (oracle `restricted_board`, l.788; SPEC 2.15 "The restricted game")

The oracle's `restricted_board` does not check admissibility; the engine does (E-10 lists `restrictedBoard` among the functions that throw `NotAdmissible`). Then:

- `orbits`: the $\tau$-orbits of the white positions, found by walking the white positions in increasing order, each orbit sorted (oracle `tau_orbits`). This is the "order of the smallest node of each orbit", which need not be the Bourbaki order of the restricted type.
- `simpleRestrictedRoots2`: for each orbit `O`, `shadow2(d, e_{O[0]})` (the oracle uses the first, that is the least, node of the orbit), integer vectors $2\bar\alpha_O$.
- `cartan`: $\bar C_{OO'}=2(\bar\alpha_O,\bar\alpha_{O'})/(\bar\alpha_O,\bar\alpha_O)$ with `B = gram(board)`, row `s`, column `t`, denominator from row `s` (this is $\langle\lambda_s^\vee,\lambda_t\rangle$, the site's convention). Every entry must be an integer; otherwise `EngineError` (oracle assert). Rows and columns in the order of `orbits` (6.4: "rows and columns in the order of `restricted_simple_orbits`").
- `compositeWords`: for each orbit `O`, `wx` followed by `longestWord(board, sorted(X ∪ O))`, as one word of positions played left to right (the oracle comment: "apply w_X first, then w_{X u O}"). Its operator is $\tilde s_O=w_{X\cup O}\cdot w_X$. The word is the concatenation, not reduced: its reduced length is $\ell(w_{X\cup O})-\ell(w_X)$, which is what `satake` reports as `restricted_reflection_word_lengths[k] = compositeWords[k].length - 2 * wx.length`.
- `board` (plan, implementing the E-7 row "folded board, restricted board", exactly as `P4-A1` built the folded board): `{ n: m, cartan, labels, kind: 'gcm', arith: SafeInt, name }` built directly, not through `fromAdjacency`. `cartan` stays in orbit order. Call `identify` only when $m>0$ and `components(board)` has a single entry (the oracle's guard `identify_labelled(Cbar) if orbs and len(components(Cbar)) == 1`, the same guard as in 5.6): `identify` requires a connected board and throws `NeedsConnectedBoard` otherwise (E-10; SPEC 5.6 table: "`cartanClass`, `identify` and `identifyAffine` require a connected board and throw `NeedsConnectedBoard` otherwise"), so calling it unguarded would make `restrictedBoard` and `satake` throw where the oracle returns `restricted_board` null. With `id = identify(board)`: `labels[id.order[k]] = k + 1` and `name = id.name`. Otherwise (when $m=0$, when the restricted Cartan matrix is disconnected, or when `identify` gives `null`), `labels = [1, ..., m]` and `name` undefined, as E-7 requires ("in the order of the orbits when no type is named"). Example: the split form of $A_2+A_2$ (no black node, $\tau$ the identity) has a disconnected restricted Cartan matrix, so its restricted board has labels 1 to 4 and no name, and `satake` gives `restricted_board` and `restricted_orbits_in_bourbaki_order` both `null`. For the compact form, $m=0$: `orbits`, `simpleRestrictedRoots2`, `cartan`, `compositeWords` are `[]` and `board` has `n: 0` (plan; record it).
- Behaviour that the golden data confirm [V for the 135 records of positive real rank]: each composite word commutes with $\theta$ and acts on shadows as the reflection in the simple restricted root of its orbit.

1. **Condition 3 is judged independently of 2: the three lights (2.15).** Do not short-circuit. The `satake_examples` row $A_3$, black 1, flip has all three failing, and condition 3 there is computed although $\tau$ moves the black set.

Arrows (white pairs only) are `P6-A2`'s field.
3. **`restricted_type` is always `B2` for rank 2; the `C2` display adjustment is `P6-A2`'s `satakeRecord`, not `satake`.** Four golden records store `C2` and a reversed orbit list; your computed-field test must expect `B2` and the reverse there, with a comment citing 6.4. Do not "fix" `satake` to say `C2`.
4. **`classifyRestricted` must refuse pairs that fail condition 3** (generalized diagrams give non-root-systems); it is called only after admissibility. The refusal has to come from your admissibility check, not from `classifyRestricted`: on $G_2$ with the long node 2 black the shadows are $\pm\lambda,\pm2\lambda,\pm3\lambda$ and the ported function fails an internal assert, but with the short node 1 black they are $\pm\lambda,\pm2\lambda$ with multiplicities 4, 1, and it returns `BC1` without complaint, a plausible but wrong name (SPEC 2.15: "which looks like $BC_1$ although $\mathfrak g_2$ has no real form of real rank 1"). Your `G2 generalized pairs are refused` test covers both nodes. `generalized_satake_example` is a phase 7 key: do not `covers()` it.
5. **The multiplicity of a restricted root is the number of roots with that shadow; a $BC$ system has exactly one simple restricted root with a double.** Count `restr` over the non-compact roots only, keyed by the doubled shadow, and read $m_{2\lambda}$ at `2 * s`, not at `s / 2`.
6. **Order of $\theta$'s stages.** Permute first (`q[tau[i]] = p[i]`, not `q[i] = p[tau[i]]`; equal for an involution, different for a $\tau$ of order 3, which `admissibility` may be handed), then play $w_X$, then negate. A word "applied" means its letters played left to right.
7. **The composite word is `wx` followed by the longest word of $X\cup O$**, played in that order, and it is not reduced: `restricted_reflection_word_lengths` is `length - 2 * wx.length`, not `length` and not `length - wx.length`. For $\mathfrak e_{6(-26)}$ the word has 32 letters and reduced length 8.
8. **Real rank is the number of $\tau$-orbits of white nodes** in the oracle; the span of the shadows is a check, not the definition. The roster's phrase "real rank as the span of the shadows" means that check.
9. **Orbit order versus Bourbaki order.** `restricted_simple_orbits`, `restricted_simple_multiplicities` and `restricted_cartan` follow the order of the least node of each orbit; only `restricted_orbits_in_bourbaki_order` and the board's `labels` follow `identify`'s order. On `e6(-14)` they differ (`[[1, 6], [2]]` against `[[2], [1, 6]]`). `identify`'s `order[k]` is the position playing Bourbaki node `k + 1`; `labels[order[k]] = k + 1`, never the inverse (trap 19 of `P4-A1`).
10. **The compact form.** `restricted_cartan` is `[]`, not `null`, although the contract type allows `null`; the four name fields are `null`; the lists are empty. Rule 7: a meaningful `null` compares as `null`.
11. **The restricted Cartan matrix's denominator is the row's norm** ($\bar C_{OO'}$ divides by $(\bar\alpha_O,\bar\alpha_O)$). Transposing it gives `[[2, -1], [-2, 2]]` instead of `[[2, -2], [-1, 2]]` on `su(2,2)` and `e6(-14)`, and the wrong Bourbaki order.
12. **Positions against labels (E-7).** The oracle's `satake` returns `[i + 1 for i in ...]` and its reasons print 1-based numbers; you return positions. On named finite boards labels are positions plus one, so no golden test would catch a stray `+ 1`; `reasons.test.ts` must use a board whose labels are not `1..n`. An affine board cannot serve, because every Satake function throws `NotFiniteType` there (5.6); use a finite sub-board that keeps other labels (plan): `subBoard(boardFromName('A5'), [2, 3, 4])` is $A_3$ with labels 3, 4, 5; black position 0, identity, gives `nodes: [1]` and `toLabels` gives `[4]`. The roster's "affine-labelled board" is read this way; say so in the fragment.
13. **Re-export without ambiguity.** `index.ts` already exports `classifyRestricted` through `restrictedType.ts`. A second `export * from './satake.js'` that also re-exports it can raise TypeScript's ambiguity error (TS2308) for star exports of the same name; use named exports from `satake.ts` in `index.ts`.
14. **`classifyRestricted` returns `form_value` text, not multiplicities.** `P4-A1` returns `{ class, roots, form_value }`; you supply `mult` yourself by matching shadows to classes by norm, on the same vectors you passed (doubled shadows: their norms are 4 times the oracle's, the classes and their order are the same).
15. **`multiplicities` order** is ascending norm: `short` before `long`, and `short`, `medium`, `long` for $BC_r$ with $r\ge2$ (`e6(-14)`: 8, 6, 1). Not the order of the orbits.
16. **Several failing nodes in condition 3 with different fractions** exist (section 5.5); the contract's single `value` needs the plan's reading, which you must record and report.
17. **Reason precedence.** For `condition_1` the oracle reports "not an involution" before "does not send the black set to itself"; keep `not-an-involution` first.
18. **Admissible pairs enumerate involutions only, identity included.** `verify.py` filters `automorphisms` to `t[t[i]] == i`; a $\tau$ of order 3 fails condition 1 anyway, but enumerating it changes nothing only if your condition 1 is right. $D_4$ has 4 involutive symmetries and 11 admissible pairs; $E_6$ 2 symmetries; $E_7$, $E_8$, $F_4$, $G_2$, $B_n$, $C_n$ only the identity.
19. **Do not read the golden file in `src/`.** The property test for 9 needs "every catalogue record of B"; `satakeCatalogue` is `P6-A2`'s and arrives later, so the test takes the records of B from `golden.satake` through the harness (plan) and converts their `black_nodes` and `tau` to positions. `P6-A2` may switch it to `satakeCatalogue` later.
20. **Gram matrix scaling.** `gram` is $DC$ with the least $d_i$ equal to 1; condition 3's terms and the restricted Cartan entries are ratios, so the scale cancels, but sums must be exact rationals (`Rational` on `bigint`), never floats.
21. **Performance (E-9).** Satake data for $E_7$ and $E_8$ run in the worker in the browser, but the engine is synchronous and knows nothing of it. Compute `wx` once per call and $\theta$ once per root; do not call `theta` (which recomputes `wx`) inside the loop over 240 roots. The admissible-pairs test makes a few thousand `admissibility` calls over the 32 types; precompute per board what does not depend on the pair (roots, `gram`, symmetries) in the test, and raise that test's timeout only if needed (record it).
22. **Disconnected boards.** `verify.py` also runs `satake` on the direct sum of two $A_2$ (complex $\mathfrak{sl}(3)$ as a real form). Whether your guard admits such a board is `guards.ts`'s decision (`requireFinite`); do not add a connectivity requirement of your own, and do not pin this case in a test. If the guard does admit it, the restricted Cartan matrix can be disconnected (the split form, no black node, $\tau$ the identity), and an unguarded `identify` would throw `NeedsConnectedBoard`; guard every `identify` call on the restricted board with $m>0$ and a single entry in `components` (5.6, 5.7), so the result is `restricted_board` `null` and labels `1..m`, as in the oracle.
23. **The A.5 shadow table lists halves** ($(1/2,1/2)$); `shadow2` returns doubles (`[1, 1]`). Do not halve in the engine.
24. **`restricted_board` is named by `identify`, not by `classifyRestricted`.** The roster's deliverable reads "restricted_board named by classifyRestricted (B_r for BC_r, A1 for r = 1)"; the oracle computes it as `identify_labelled(Cbar)` on the restricted Cartan matrix, and SPEC 6.4 gives the same names ($B_r$ for $BC_r$, $A_1$ for $r=1$). `classifyRestricted` gives `restricted_type` (`BC1`, `BC2`, ...), a different field. Like trap 8 for "real rank as the span of the shadows", read the roster phrase as describing the result, not the function to call.
