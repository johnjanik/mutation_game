### 5.3 `fold(board, symmetry): FoldResult`

`FoldResult { folded: Board | null; orbits: number[][]; reason: string | null }` (5.2). Oracle `fold(C, tau)` with `tau_orbits`.

- Guard (5.6): `NeedsTwoWayRoads` on a `one-way` board, `NotFiniteType` on a `gcm` board that is not of finite type (through `guards.ts`). The oracle does not check that `symmetry` preserves `C`; neither do you. A `symmetry` that is not a permutation of `0..n-1` (wrong length, repeated or out-of-range entry) throws `RangeError` (plan).
- Orbits (oracle `tau_orbits`): for `i` from 0 to n minus 1, if `i` is not yet seen, follow `j = tau[i], tau[j], ...` until it returns to `i`, sort the orbit ascending, append. Orbits are therefore in order of their least position, each sorted. Position `t` of the folded board is `orbits[t]`.
- Edge test (2.13 (a): "Require that no two nodes in the same $\sigma$-orbit are joined"): with `A = adjacency(board)`, if any orbit `o` has `A[i][j] != 0` for some `i, j` in `o`, return `{ folded: null, orbits, reason: "an orbit contains an edge" }`. The reason text is the one the golden record of A4 carries (plan: fixed so that T11's first tab can show it); rule 6 says `reason` is documentation, so compare it in your test as a plan addition, not as a golden rule.
- Folded matrix (2.13 (a) and the oracle): `Af[s][t] = sum of A[j][i] for j in orbits[s]`, with `i = orbits[t][0]` one fixed node of orbit `t`, for `s != t`; then `Cf[s][t] = 2` for `s == t` and `-Af[t][s]` otherwise. This is `C = 2I - A^T` applied to `Af`. Both D4 rows: the swap of nodes 3 and 4 gives `[[2, -1, 0], [-1, 2, -2], [0, -1, 2]]` (identified `C3`); the rotation gives `[[2, -1], [-3, 2]]` in orbit order (orbits `{1, 3, 4}` then `{2}`), identified `G2` with its nodes exchanged.
- The folded board object (plan, implementing the E-7 row "folded board, restricted board: 1..m in the Bourbaki order of the type that `identify` names (`folded_orbits_in_bourbaki_order`); in the order of the orbits when no type is named"): build it directly as `{ n: m, cartan: Cf, labels, kind: 'gcm', arith: SafeInt, name }`, not through `fromAdjacency` (which would give labels `1..m` in position order). `cartan` stays in orbit order, so that `cartanNumbers(folded)` equals `folded_cartan` as 5.2 requires. With `id = identify(folded)`: `labels[id.order[k]] = k + 1` for `k = 0..m-1` (position `id.order[k]` plays Bourbaki node `k + 1`), and `name = id.name` (plan; record it). ## 9. Traps

1. Two constructions, dual answers (2.13). `fold` is construction (a): orbit sums, `Af[s][t]` counts edges from orbit `s` into ONE node of orbit `t`, larger orbits become longer roots (A3 folds to B2 with the orbit `{1, 3}` long). `averagedRootsType` and `averagedSimpleCartan` are construction (b): larger orbits give shorter roots, and the matrix is the transpose of (a)'s. Do not "fix" one to agree with the other.
2. The factor `Lambda^{1/2}` is essential; bare eigenvectors distort the picture (2.14). `E = Lambda^{1/2} V^T D^{1/2}`, and the `D^{1/2}` on the right multiplies column `j` by `sqrt(d_j)`. Without either factor `E^T E` is not `B` and the rotation test fails.
3. Eigenvector signs and repeated-eigenvalue bases are not unique (5.5): D4 has the double eigenvalue 2 (exponents 1, 3, 3, 5). Test invariants only; never compare `E`, `vectors` or `coxeterPlanePoints` coordinates with stored numbers, and never compare them with the oracle's output pasted into a test.
4. For the rotation of D4 the folded matrix in the golden file is G2 with its nodes exchanged: `folded_cartan` is `[[2, -1], [-3, 2]]` in orbit order (`{1, 3, 4}` first), while `cartan('G2')` is `[[2, -3], [-1, 2]]`. Compare `cartanNumbers(folded)` in orbit order and use `folded_orbits_in_bourbaki_order` (`[[2], [1, 3, 4]]`) for the drawn order (Appendix G). Likewise E6 folds to F4 with Bourbaki order `[[1, 6], [3, 5], [4], [2]]` while the orbits come as `[[1, 6], [2], [3, 5], [4]]`.
5. A4's flip does not fold (the orbit `{2, 3}` contains an edge) but averages to `BC2`, a non-reduced system with three classes `short`, `medium`, `long`; `classifyRestricted` detects it by the double of a vector being in the set. `averagedSimpleCartan` still returns `[[2, -1], [-2, 2]]` for it.
