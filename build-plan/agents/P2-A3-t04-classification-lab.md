Property names beyond these are yours and are listed in a comment at the top of `T04.spec.ts` (4.0 Test hooks). The plan adds `boardPresets` (section 5.3) and `hunter: boolean` (the switch of 5.7).
- Tool presets (CONTRACTS 6; distinct from the editor's board presets of 5.3): `default` is the path $A_3$ loaded in the editor with the verdict, balance, spectral radius and complete root count shown (plan: SPEC 4 T4 names no default board, so the board of M3 beat 1, "T4 with the path $A_3$ loaded", is taken); `verdict` is the same state with the verdict panel first in reading order (plan reading of M3 beat 2: "T4 verdict panel on the same boards (class, balance, spectral radius)"); `hunter` loads the one-way road `[[2, 0], [-1, 2]]` with the hunter switched on (M3 beat 6: "T4 with the conjecture hunter switched on; presets: the one-way road, a reader-drawn board"). "A preset fixes only things the reader could have set by hand, so every preset is also a state object and a link" (4.0): each preset's `board` is a state field and a link; the hunter switch and the panel order are view options outside schema 1 (6.6: options not listed "are not part of a link in schema 1; a link opens the tool with those at their defaults"), so they travel as properties, not as link keys (plan). Record this in your fragment.
- URL: on hydration read the URL with `decodeState(search, 'lab', defaults, { prefix })` and apply it over the properties; write back with `encodeState` after every edit through `history.ts` (`replaceState`, throttled; `pushState` when a preset is loaded, 7.4). ### 5.2 `BoardEditor.svelte` (SPEC 4 T4 Editor; 5.6 caps; 6.1 Custom boards; 6.2; 7.5 A-1, A-7, A-8, A-10; CONTRACTS 5.1)

The contract T16 builds against (plan; CONTRACTS.md has no entry for the editor, so this block is the contract and your report must repeat it under `editorContract`):

```ts
// site/src/components/board/editor/types.ts (plan)
export interface EditorPreset { id: string; label: string; board: BoardSpec; group: 'finite' | 'affine' | 'twisted' | 'test' }
export interface EditorChange { kind: 'add-node' | 'remove-node' | 'roads' | 'move' | 'preset'; resetsPlay: boolean }
export interface BoardEditorProps {
  value: BoardSpec;                              // SPEC 6.6 "board": a name, or { cartan, xy? }
  onChange: (next: BoardSpec, change: EditorChange) => void;
  name: string;                                  // accessible name of the editor group (A-1)
  disabled?: boolean;                            // true until the host island has hydrated (7.4)
  roadStyle?: 'dynkin' | 'roads';                // ignored on a one-way board, which is always drawn in 'roads' style (6.2)
  presets?: EditorPreset[];                      // section 5.3; omitted: the finite types and the affine names only
  maxNodes?: number;                             // default CAPS.customNodes (12); the editor never allows more
  maxRoads?: number;                             // default CAPS.roadsEachWay (4); the editor never allows more
  values?: (number | string)[];                  // what the host writes on the nodes (T16: the position); T4 passes nothing
  marked?: readonly number[];                    // labels to mark on the drawing (T4: a smallest non-finite sub-board)
}
```

- `onChange` emits the name itself while a preset board is unedited (so the link reads `g=E6` and `resolveBoard` keeps `SafeInt` on a named finite board) and `{ cartan, xy }` as soon as the reader edits (plan). A custom board's labels are $1,\dots,n$ in order of creation (E-7); a named affine board (labels $0,\dots,n$) therefore changes its labels on its first edit, and the editor announces that (plan).
- **Nodes**: "up to 12 nodes" (T4; 5.6: "Nodes of a custom board: 12, editor refuses a 13th"). The add button and key are disabled, with a visible reason, at 12. The engine accepts any count; the editor enforces the cap (roster trap). Refuse to remove the last node (plan: the minimum is 1).
- **Roads**: "between two nodes, 0 to 4 roads each way, including roads one way only" (T4; 5.6: "Roads between two nodes, each way (editor only; the engine accepts any count): 4, editor refuses more"). The two counts of a pair are set independently, each from 0 to 4, so $(4,1)$ ($A_2^{(2)}$, Cartan matrix `[[2, -4], [-1, 2]]`, roster trap) and $(m,0)$ (one-way) are both reachable. The editor keeps the Cartan matrix $C=2I-A^{\mathsf T}$ of 2.1: $A_{ij}$ roads from $i$ to $j$ become $C_{ji}=-A_{ij}$; test this on an asymmetric pair (section 6), since every symmetric board hides a transposition.
- **Arrangement**: "drag to arrange" (T4) onto "whole grid points, all different, between 0 and 11 in each direction" (6.1 Custom boards). Snap on drop; refuse a taken point (or swap, your choice, recorded); clamp to 0 to 11. Every node has coordinates, so the emitted spec always carries `xy`; a spec that arrives without `xy`, or with coordinates that break the rule, is laid out "on a circle in label order" by `P1-A3`'s `nodePositions` and the editor adopts those positions as the starting `xy` (plan).
- **No drag-only action** (T4: "or add and remove with buttons and keys (no action is drag-only)"; A-8: "Nothing requires dragging or a multi-finger gesture: rotation, zoom, node placement and scrubbing all have buttons and keys"; P10: "Every drag has a button equivalent"). Moving a node has buttons (up, down, left, right by one grid point) and a key equivalent that does not take the bare arrow keys, which A-1 reserves for moving focus between nodes (on custom boards: follow the labels and wrap); a modifier plus arrow is acceptable (plan). Adding, removing, setting road counts and choosing a preset are buttons, steppers or selects; Enter or Space on a node selects it as the subject of the road and move controls (plan). The whole of the Playwright test "draw the triangle by keyboard only" (section 6) must pass with `keyboard.press` and nothing else.
- **Deleting**: "Deleting a node renumbers the labels $1,\dots,n$ in their old order and resets `start` and `moves`" (T4). The model removes row and column $i$ and entry $i$ of `xy`; the labels are regenerated as $1,\dots,n$ in the old order; `onChange` carries `resetsPlay: true` and the host resets `start` and `moves` to its defaults for the new board (4.0 Board pickers: "A picker changes `board` and resets `start` and `moves` to the tool's defaults for that board"). Adding a node and choosing a preset also carry `resetsPlay: true`; changing road counts or moving a node carries `false` (plan).
- **Drawing**: through `Board.svelte` with `P1-A3`'s layouts and roads: `dynkin` style by default, "a thick line with the two counts written at its ends" for a pair with $A_{ij}A_{ji}\ge4$ (6.2), and `roads` style forced "always on a board with a one-way road, where the `dynkin` style would be ambiguous" (6.2; T4: "the editor draws every road as its own arrow (`roads` style)"). Expose the style in force as `data-road-style` on the editor root (plan hook). Labels are always visible beside the nodes (6.1). Colours only through the tokens of CONTRACTS 8.
- **Hooks**: every node button keeps the four hooks of 4.0, `data-node` (label), `data-board`, `data-value`, `data-can-act`; in the editor every node can be selected, so `data-can-act="true"` (plan). The editor root carries `data-nodes` (the count) (plan hook).
- **Hit areas** (A-7; 6.1): the grid unit is $u=\min(64,\lfloor (W-16)/k\rfloor)$ with $k$ the number of grid columns occupied; the hit area is $\min(44,u)$; at 320 pixels a twelve-node board spanning the whole grid gives 25, never below 24. The editor box scrolls inside itself if it cannot reflow (A-11).
- **Table view** (A-10): `ToolFrame`'s "Show as table" presents the road counts as an HTML table (one row and column per node, the count of roads from row to column) with a button per node, and the verdict fields as text (plan). It is also a complete keyboard editing surface if you make the cells editable (optional, plan).
- **Announcements**: edits are not moves, but the polite region of A-4 exists for every tool. After each edit announce one short sentence through `createAnnouncer`, naming the edit and the new class (plan wording, for example `Added node 4. Verdict: indefinite.`); bursts coalesce within 500 ms as the announcer does.

### 5.6 The root counter (SPEC 4 T4 Root counter; 4.0 Stated limits and Growth; 5.5 Order and truncation; 5.6; E-9)

- "Number of root populations by breadth-first layer": run `orbitGraph(board, seeds, 'mutation', cap, maxDepth)` with the seeds the single Martians $e_0,\dots,e_{n-1}$ **in position order and in the board's arithmetic** (`1n` and `0n` on a `Big` board), exactly the oracle's `[unit(n, i) for i in range(n)]`, and count `depth[k]` per layer. Show the count per layer (layer 0 is the seeds: the oracle's `new_per_layer` starts with $n$), the total found, and the stop sentence when one applies.
- **Finite boards**: "On a board that `classify` calls finite the count is complete and immediate": no `maxDepth`, a cap of 2000 (the roots of a finite board are "at most 288 on twelve nodes", E-9), on the main thread, at build time for the default state. No stop sentence.
- **Other boards**: "On any other board it runs on the main thread for `layers` layers or 2000 positions, whichever comes first (section 4.0, E-9)": `maxDepth = layers` (default 40), `cap = 2000`. The two stop sentences are decided exactly as 5.5 says: `stopped after 40 layers` (with the `layers` value) "when `truncated` is false and `depthReached` equals `maxDepth`", and `stopped after 2000 positions; layers 0 to 10 are complete` (with `items.length` and `completeLayers`) "when `truncated` is true". Say which bound ended the search and never present a truncated count as complete (4.0 Stated limits). Reproduce T2's two sentences character for character (CONTRACTS 5.3).
- **Keep counting**: "a button 'keep counting' continues in the worker up to 100000 positions. Each stop is reported in the words of section 4.0." The button is labelled `keep counting`. It starts a **new** call, `orbitGraph` with `cap = 100000` and the same `maxDepth`, through `engineCall` with a hint `{ board, kind: 'enumeration', expectedItems: 100000, finiteKnown: false }`, which `whereToRun` sends to the worker (E-9 rule 1; "A call is never started in one place and continued in the other"). Its stop is reported in the same words: on the star with five arms, `stopped after 100000 positions; layers 0 to 17 are complete`, with 74311 positions in the complete layers. The worker's result replaces the main-thread result; the per-layer counts are shown for the complete layers and the incomplete last layer is marked as incomplete (plan). Offer the button when the main-thread search was cut by the position cap (`truncated: true`); after a layer stop the 100000 run with the same `maxDepth` would return the same count, so the button is not offered there (plan; record it). While the worker runs, show that it is running and keep every control usable; the result arrives behind a promise (E-9).
- **On a one-way board** "the counter still runs" (T4): the roots of a one-way board are an infinite set with few new positions per layer, so the layer bound acts; `orbitGraph` works on one-way boards (5.6 first row).
- **Default state**: "No tool may need the worker for its default state" (E-9; 7.6: the worker's script "is fetched when a tool first needs it. No tool may need it for its default state"). The default and every preset's default run the bounded main-thread search at build time; the worker script is requested only after `keep counting` is pressed (roster acceptance; `P1-A2`'s `worker-on-demand.spec.ts` will also check `/tools/lab`).
- Hooks: `rootCount` (total found), `layerCounts` (the per-layer list as text), `stopMessage` (exactly one of the sentences above, or absent when the count is complete) (plan names).

### 5.8 `classify` once on load; worker routing (SPEC 5.6 last sentence; E-9; E-11; CONTRACTS 4)

## 9. Traps

- "Not of finite type" and "indefinite" come only from the `classify` record (4.0; roster). A counter that hits 2000 positions or 40 layers says only its stop sentence; it never implies a class. The star with four arms ($\tilde D_4$) hits the layer bound and is affine; the star with five arms hits the position cap and is indefinite; the words come from `classify` in both cases.
- The editor refuses a 13th node and a 5th road each way; the engine accepts any count (5.6; roster). Enforce the caps in `model.ts`, not only in the buttons, so that a pasted or linked board cannot bypass them; a link with more than 12 nodes is already refused by the codec (6.6).
- `A2^(2)` needs four roads one way and one back: `C = [[2, -4], [-1, 2]]`, that is $A_{21}=4$ roads from node 2 to node 1 and $A_{12}=1$ back. Two independent counts from 0 to 4 per pair make it reachable; a single "multiplicity" control with an arrow does not.
- $C=2I-A^{\mathsf T}$: $A_{ij}$ roads from $i$ to $j$ sit at $C_{ji}$. Every symmetric board hides a transposition; `boardEditor.test.ts` must use an asymmetric pair and compare with `fromAdjacency`. The chevron of the `dynkin` style points from the long node to the short node, in the direction of the extra roads (2.1); `P1-A3`'s `Roads` draws it, your matrix decides it.
- The spectral radius is not shown on a one-way board (`spectralRadius` returns `null`, 5.6); make the element absent, not `0.0000` or `null` as text. `smallestNonfiniteSubboard` is also `null` there and on finite boards.
- `classify` is called once per loaded board (5.6 last sentence). Keep one board object per edit state; the `WeakMap` cache of E-11 is keyed by object identity, and a fresh `resolveBoard` for every engine call defeats it and recomputes the verdict.
- Seeds for the counter are the unit vectors in position order in the board's arithmetic. On a `Big` board `[1, 0, 0]` is wrong and `[1n, 0n, 0n]` is right; `SafeInt` boards take numbers. A mixed seed throws or, worse, compares unequal in the hash set and doubles the count.
- The two stop sentences have exact conditions (5.5): `truncated` false and `depthReached === maxDepth` gives `stopped after 40 layers`; `truncated` true gives `stopped after 2000 positions; layers 0 to 10 are complete` with `completeLayers`.
