## 5. Requirements

### 5.1 `scripts/size.mjs` (SPEC 7.6; roster deliverable 1)

The specification's algorithm, quoted from the bullet "Measured by `npm run size`": "a Playwright script opens each route of the built site at 360 by 800 pixels, waits until the network is idle without touching the page, collects the URL of every script the browser fetched, compresses those files from `site/dist` with Node's `zlib` (gzip, level 9), and fails when a sum exceeds its limit. It prints the table of sums. It needs no service and no dependency beyond Playwright." Every clause below is that bullet made concrete; what the plan adds is marked (plan).

**Serving the built site.** By default the script starts `astro preview` of the built site (roster: "starts astro preview on site/dist (or takes a URL)") on a port of its own (plan: 4323, so that a Playwright `webServer` lingering on 4321 does not collide), waits until the base URL answers, measures, and kills the server in a `finally` block and on `SIGINT` (`COMMON.md` 4.5: "Kill `astro preview` when you are done"). If you spawn the server through npm, kill the whole process group (`detached: true` and `process.kill(-pid)`), or spawn Astro's own binary from `site/` so that there is no npm layer to orphan. Options (plan): `--url <base url>` uses a running server instead and starts none; `--dist <dir>` names the built directory (default `site/dist`, or the directory `OUT_DIR` names when that variable is set and `astro.config.mjs` honours it); `--port <n>`; `--limit-override <kB>` replaces every route's limit by one number and is used only in the unit test of 5.10 (roster acceptance 1: "a temporary limit override flag used only in the test"; say so in the usage text), never in a script body, in `ci.yml`, in a gate run or by hand; `--json <file>` writes the rows as JSON beside the table (optional; `GATE` records the sizes table in every gate report, `README.md` 7). Never `astro dev` (`SPEC.md` 7.2 item 9).

**Routes.** Every `.html` file under the built directory is a route: `index.html` at the root is `/`, `about/index.html` is `/about/`, a file `name.html` is `/name` (Astro's default `build.format` is `directory`; read the merged `astro.config.mjs` and the installed Astro before assuming). Every route is measured, including `/dev/*` and `/open-items/` pages of a preview build; none is skipped. The route's URL is the server origin, then `base` (which begins and ends with `/`: `CONTRACTS.md` 1), then the route path without its leading slash. Take `base` from `siteAndBase(process.env).base`, imported from `site/astro.config.mjs` (`CONTRACTS.md` 1), so that the measurement uses exactly the base the build used. Do not reimplement the rule and do not read `BASE_PATH` alone: `SPEC.md` 7.2 item 10 says that when `BASE_PATH` is unset, "in CI, the values that follow from `GITHUB_REPOSITORY` (`owner/repo` gives `https://owner.github.io` and `/repo/`)" apply, so in `ci.yml` the build is served under `/<repo>/`, and a script that opened `http://localhost:4323/` would get 404 pages that fetch no script. (plan) An option `--base <path>` overrides the imported value, for `--url` against a server built with another environment. If importing the config fails in Node outside Astro, stop and write a request to `MERGE` rather than copy the rule.

**Opening a route.** One Chromium browser, one new context per route with `viewport: { width: 360, height: 800 }`, JavaScript enabled. `page.goto(url, { waitUntil: 'networkidle' })`, and check the status of the response it returns: a route that does not answer with status 200 is an error (plan: print `route answered <status>`, fail the route, exit 1), because an error page fetches no script and would pass every limit at 0 kB, which would make the exit code dishonest. The one exception (plan) is the route built from `404.html`, which the preview server may answer with 404 by design; accept 200 or 404 for that route only and record it in the fragment. Then wait until no further request has started for a short settle (plan: one second), because `client:idle` islands hydrate from `requestIdleCallback` and `client:visible` islands from an intersection observer, both after `load`. Do not touch the page: no click, hover, focus, key, scroll, mouse movement, no `page.evaluate` that dispatches an event, no emulation of a reduced-motion or colour-scheme preference (roster trap 1: "the budget is 'before the reader's first interaction'"). Reading the DOM is not touching it, but you need nothing from the live DOM: the classification reads the file on disk.

**Collecting scripts.** Register `page.on('request')` before navigation and keep the URL of every request whose `resourceType()` is `script` or whose pathname ends in `.js` or `.mjs` (the union; read the installed Playwright's documentation of `resourceType` for `<link rel="modulepreload">`, dynamic `import()` and `new Worker()` before trusting one of the two tests alone). Deduplicate by URL within a route. A request to another origin is a third-party script, which `SPEC.md` 7.8 forbids at runtime; print it as `external script` and treat the route as failed (plan). The worker script of E-9 is not excluded by name: 7.6 says "No tool may need it for its default state, so it never counts toward these limits" because it is never fetched before an interaction; if a default state does fetch it, counting it is the correct result and the failure is real.

**Sizes.** Map each script URL to a file: strip the origin and `base`, join with the built directory, refuse any path that escapes it. A script URL with no file in the built directory is an error (plan): print it and fail the route; do not count it as zero. The size of a script is `zlib.gzipSync(bytes, { level: 9 }).length` of the file in the built directory (roster trap 2: "gzip level 9 of the files in site/dist, not the transfer size the browser reports"; never `content-length` or `request.sizes()`). The route's sum is the sum over its deduplicated scripts; a chunk shared between routes counts on every route that fetched it, because the budget is per route.

**Limits.** The table of 7.6, exactly: a page with no tool, 15 kB; a page with one Game Board (the phase-0 page), 60 kB; each tool alone on `/tools/<id>`, 90 kB; any lesson page, 120 kB. kB means 1000 bytes (plan; the specification does not define it, 1000 is the unit's meaning and the stricter reading; record it in the fragment and print the unit in the table header). A route fails when its sum exceeds its limit, that is, is strictly greater; a sum equal to the limit passes.

**Classification** (roster: "classification by data-tool count in the HTML and by path"), implemented as one pure function `classifyRoute(routePath, html)` returning `{ label, limitKb }` and exported for the unit test (plan for the names):

1. A path beginning with `/modules/` is a lesson page: `lesson`, 120.
2. A path beginning with `/tools/` is a tool alone: `tool`, 90. A path beginning with `/embed/` (the phase-6 embed routes, `SPEC.md` 7.4, which render one tool alone) is classified the same way (plan).
3. Otherwise count the elements of the HTML that carry a `data-tool` attribute, by scanning tags, not by counting the string in the raw text (the string may occur inside a `<script>` or a prop). Zero: `no-tool`, 15. Exactly one, with the value `board`: `one-board`, 60 (the roster's "the index page with one board: 60 kB"; the phase-0 index page carries `data-tool="board"`, P0-A5 instruction, deliverables table and section 6). Exactly one with another value: `tool`, 90 (plan: the nearest row, "each tool alone"). Two or more: `several-tools`, 120 (plan: the lesson row is the only row for a page with several tools). The two plan cases do not occur in phase 0; record them in the fragment and in `openQuestions` so the orchestrator can strike or change them.

**Output.** One table line per route: route, label, limit in kB, HTTP status, number of scripts, gzip sum in kB to one decimal, `ok`, `OVER` or `ERROR` (a non-200 status, an external script or a missing file); then a summary line `size: N routes measured, M over budget`. Exit status 0 when no route is over and no error occurred, otherwise 1. Print the usage text and exit 2 on an unknown option (plan). The script writes nothing into the built directory, `reference/` or `site/src/`.

**Structure for testing.** Keep the browser part (open a route, collect script URLs) separate from the pure parts, and export the pure parts: `routesOf(distDir)`, `classifyRoute(routePath, html)`, `routeUrl(origin, base, routePath)`, `fileForScript(url, origin, base, distDir)`, `gzipSize(bytes)`, `measureRoute(scriptUrls, origin, base, distDir)`, `evaluate(rows, limitOverrideKb?)` (which also fails a row whose HTTP status is not accepted), `formatTable(rows)`, `parseArgs(argv)` (plan for the names). Guard the main-module behaviour with the usual check of `import.meta.url` against `process.argv[1]`, so that importing the module in a test runs nothing.

### 5.2 `scripts/verify.mjs` (SPEC 5.7 "Regenerating the golden data"; 7.7 Oracle row; roster deliverable 2)

The specification: "`python3 reference/verify.py <output file>`. The script needs only the standard library, exits with status 1 if any check fails, and writes every key in every run, so a regenerated file never silently loses a field. The command `npm run verify` writes to a temporary file and fails unless the result is byte-for-byte the committed `reference/golden_data.json`." And: "Should another Python version ever write a different file, compare the two as parsed JSON under the rules above and report the difference to the owner; do not commit the new file."

- Resolve every path from `import.meta.url`: the repository root is the parent of `scripts/`; the oracle is `<root>/reference/verify.py`; the committed file is `<root>/reference/golden_data.json` (roster trap 3: the script runs from the repository root in CI and in a worktree; never rely on `process.cwd()`).
- Create a temporary directory with `fs.mkdtempSync` under `os.tmpdir()` and write to `<tmp>/golden_regen.json`. Always pass this argument: without one, `verify.py` writes `golden_data.json` into the current directory (line 1687), and from `reference/` that would overwrite the committed file. Assert before spawning that the output path is not under `<root>/reference/`.
- Spawn `python3` (plan: the interpreter is `process.env.PYTHON` when set, else `python3`; record it) with the arguments `[<root>/reference/verify.py, <tmp>/golden_regen.json]` and `cwd` set to the repository root. Python puts the script's own directory first on `sys.path`, so `from lie_games import *` resolves from any working directory; this was confirmed on this machine from the root on 10 October 2026 (`6649 checks passed, 0 failed, 134.6s`, byte identical). Use `python3 -u` or stream the child's stdout line by line to the console so that CI shows progress during the two to three minutes of the run; set no timeout below ten minutes.
- Find the summary line, which is the last line matching `^(\d+) checks passed, (\d+) failed, ([\d.]+)s; wrote ` (`verify.py` line 1690). Print it unchanged (roster: "prints the oracle's summary line"). On this machine it reads `6649 checks passed, 0 failed, 134.6s; wrote <path>`; the count 6649 is the number the acceptance of the roster names.
- If the child's exit status is not 0, or the summary line is missing, or its failed count is not 0: print the `FAIL:` lines and the `FAILED:` list the oracle printed, print `verify: oracle failed` with the exit status, keep the temporary file, print its path, exit 1.
- Otherwise compare bytes: `Buffer.compare` of the two files (or a streamed comparison). Equal: print `verify: regenerated file is byte for byte reference/golden_data.json (<N> bytes)`, delete the temporary directory, exit 0.
- Different: also compare as parsed JSON and print whether they are equal as parsed (roster deliverable 2). Do the parsed comparison in Python (plan), `python3 -c` with `json.load` on both files and `==`, because Python keeps integers exact where `JSON.parse` would round anything above 2^53 to a float; if you prefer Node, parse with a reviver that keeps every number as its source text. Print `verify: regenerated file differs from reference/golden_data.json (<N> bytes against <M> bytes); equal as parsed JSON: yes|no`, and when they are not equal as parsed, the first few differing paths (plan: at most twenty, found by a recursive walk, as help for the owner). Keep the temporary file, print its path, exit 1. Never copy the new file anywhere under the repository: 5.7 says "do not commit the new file", and `COMMON.md` 2 says `reference/` is read-only for everyone (roster trap 4).
- The script adds no dependency and imports only Node built-ins (`child_process`, `fs`, `os`, `path`, `url`).

### 5.3 `scripts/numbers-in-prose.mjs` (SPEC 7.7 Content row; roster deliverable 3)

The specification: "`scripts/numbers-in-prose.mjs` lists every number in lesson prose that is not written with `<G>`, for a person to review"; the two content reports are "read by the owner before a release". The report is advisory, so the script always exits 0 (roster: "exits 0 (it is a report for a person)").

- Input: every file matching `site/src/content/modules/*.mdx`, in sorted order, resolved from `import.meta.url`. In phase 0 there are none: the script then writes the report with the single line `No lesson files found under site/src/content/modules/.` and exits 0. A missing directory is the same case, not an error.
- A number is a maximal run of digits, together with the grouping and decimal characters inside it (plan: `,`, `.`, U+202F, U+2009 and an ordinary space between digit groups, and a leading `-` or U+2212); report the matched text as written.
- Excluded from the scan, as the roster lists: the frontmatter (the first `---` block at the top of the file), the contents of `<G .../>` and `<Tex .../>` elements, code spans and fenced code blocks, and component props (every attribute of every JSX or HTML tag, including multi-line tags such as `<Board start={[1, 0]} ... />`). Also excluded (plan, because they are not prose): `import` and `export` lines, standalone JSX expressions in braces, Markdown link and image destinations, and heading ids in braces. Report everything else, including digits inside a word such as `E8`: the person reviewing decides.
