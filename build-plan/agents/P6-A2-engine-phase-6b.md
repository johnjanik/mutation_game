## 5. Requirements

### 5.1 Signatures and types, verbatim (`CONTRACTS.md` 2.4 phase 6 and 2.2)

```ts
satakeCatalogue(name: string): SatakeCatalogueEntry[];  satakeRecord(name: string, entry: SatakeCatalogueEntry): SatakeRecord
canonicalPair(d): { black: number[]; tau: number[] };  matchCatalogue(d): SatakeRecord[]    // 0, 1 or 2 records
```

```ts
export interface SatakeCatalogueEntry { cartan_label: string; real_form: string; black_nodes: number[]; tau: number[];
                                        restricted_type_display: string | null; }
export interface SatakeRecord extends SatakeCatalogueEntry, SatakeComputed {
  dynkin_type: string; arrows: [number, number][]; tau_moves_black_nodes: boolean; }
```

`d` is a `SatakeDiagram` (`{ board: Board; black: readonly number[]; tau: Symmetry }`). Oracle correspondence (5.4): `satakeCatalogue` is `satake_catalogue`, `satakeRecord` is `satake_record`, `canonicalPair` is `canonical_pair`, `matchCatalogue` is `match_catalogue`. The oracle takes a family letter and a rank (`satake_catalogue(L, n)`); the engine takes the board name (`'A3'`, `'C2'`, `'E6'`).

### 5.2 Common rules for all four functions

- **Positions in, positions out (E-7).** `black_nodes`, `tau`, `arrows` and every node field of a record are positions $0..n-1$. The oracle's `satake_record` returns labels (`[i + 1 for i in ...]`); you return positions, and tests convert with the harness's `labels`. Never add or subtract 1 in `src/`.
- **Field names (5.2).** `satakeRecord` returns a plain object with exactly the 27 snake-case field names of 6.4 and the golden file, and no other field. Build it field by field in the oracle's order (plan, so that `exportJSON` of a record reads like the golden file): `dynkin_type`, `cartan_label`, `real_form`, `black_nodes`, `tau`, `arrows`, `tau_moves_black_nodes`, `restricted_type_display`, `rank`, `real_rank`, `restricted_type`, `multiplicities`, `n_restricted_roots`, `dim_g`, `dim_k`, `dim_p`, `character`, `roots_compact_imaginary`, `roots_real`, `roots_complex`, `w_X_word`, `restricted_simple_orbits`, `restricted_simple_multiplicities`, `restricted_cartan`, `restricted_board`, `restricted_orbits_in_bourbaki_order`, `restricted_reflection_word_lengths`. Do not spread `satake`'s result blindly; copy its 19 fields by name.
- **Guards (5.6, E-11).** All four are "Satake functions" in the sense of 5.6: on a `one-way` board `canonicalPair` and `matchCatalogue` throw `NeedsTwoWayRoads`; on a `gcm` board not of finite type they throw `NotFiniteType`. Decide through `guards.ts` as the first statement. `satakeCatalogue(name)` and `satakeRecord(name, entry)` take a name (plan): build `boardFromName(name)` (which throws `NotABoard` on a name it does not know) and apply `requireFinite`, so `satakeCatalogue('A2~')` and `satakeCatalogue('pentagon')` throw `NotFiniteType` and `satakeCatalogue('Q7')` throws `NotABoard`. Ranks beyond 8 are allowed by the parametric rules (`cartan` accepts them); the golden data stop at 8.
- **Malformed input (plan, as `P6-A1`).** A `tau` that is not a permutation of `0..n-1`, or a black list with a repeated or out-of-range entry, throws `RangeError`. Black lists are used sorted; inputs are never mutated (E-5).
- **Errors (E-10).** `satakeRecord` throws `NotAdmissible` (through `satake`) on an entry that is not admissible. `canonicalPair` and `matchCatalogue` never throw `NotAdmissible`: a non-admissible pair has a canonical pair and matches nothing (the oracle: "for pairs that are not admissible (no element)"). The oracle's `assert` in `satake_record` becomes `throw new EngineError('restricted board of a C2 record is not B2')` (plan, as `P4-A1` and `P6-A1`).
- **Pure (E-5).** No cache across calls; compute `symmetries(board)` once per call of `matchCatalogue` and pass it to the private canonical-pair helper (the oracle's optional `auts` argument is an internal convenience, not part of the contracted signature).

### 5.3 `satakeCatalogue(name)` (oracle `satake_catalogue`, l.1476; SPEC 6.4, 6.5, Appendix B.1)

Returns the entries of one board in the oracle's order, each `{ cartan_label, real_form, black_nodes, tau, restricted_type_display }` with `black_nodes` sorted and `tau` the full involution (images of all nodes, black ones included). The oracle's `em` (expected multiplicities) and `dk` (expected $\dim\mathfrak k$) are not fields of the contract: do not add them (a contract change is a deviation); the golden comparison of section 6 covers them. Permutations (positions): `ident(n) = [0, 1, ..., n-1]`; `flipA(n)[i] = n - 1 - i`; `swapD(n)` is the identity with positions `n-2` and `n-1` exchanged; `FLIP_E6 = [5, 1, 4, 3, 2, 0]` (labels $1\leftrightarrow6$, $3\leftrightarrow5$, node 2 fixed).

Family by family, in this order (n is the rank; black positions are 0-based, with the labels of 6.4 in brackets):

- **A** (`A1` and up):
  1. `'A I'`, `sl(${n+1},R)`, black none, `ident`, display `A${n}`.
  2. If $n$ is odd and $n\ge3$, with $m=(n+1)/2$: `'A II'`, `su*(${n+1})`, black `0, 2, ..., n-1` (the odd labels $1,3,\dots,n$), `ident`, display `A${m-1}`.
  3. If $n\ge2$, for $p=1,\dots,\lfloor(n+1)/2\rfloor$ in increasing order, $q=n+1-p$: label `'A IV'` when $p=1$, else `'A III'`; `su(${p},${q})`; black positions `p, ..., n-p-1` (labels $p+1,\dots,n-p$; empty when $p=q$); `flipA`; display `C${p}` when $p=q$, else `BC${p}`.
  4. `'compact'`, `su(${n+1})`, black all, `flipA` (on $A_1$ this is the identity), display `null`.
- **B** (`B2` and up): for $p=1,\dots,n$, $q=2n+1-p$: `'B II'` when $p=1$ else `'B I'`; `so(${p},${q})`; black positions `p, ..., n-1` (labels $p+1,\dots,n$); `ident`; display `'A1'` when $p=1$, else `B${p}`. Then `'compact'`, `so(${2n+1})`, all black, `ident`, `null`.
- **C** (`C2` and up): `'C I'`, `sp(${2n},R)`, none, `ident`, display `C${n}`. Then for $p=1,\dots,\lfloor n/2\rfloor$, $q=n-p$: `'C II'`, `sp(${p},${q})`, black positions `0, 2, ..., 2p-2` followed by `2p, ..., n-1` (labels $1,3,\dots,2p-1$ and $2p+1,\dots,n$), `ident`, display `BC${p}` when $p<q$, `'A1'` when $p=q=1$, `C${p}` when $p=q\ge2$. Then `'compact'`, `sp(${n})`, all black, `ident`, `null`.
- **D** (`D4` and up): for $p=1,\dots,n$, $q=2n-p$: `'D II'` when $p=1$ else `'D I'`; `so(${p},${q})`; when $p=n$: black none, `ident`, display `D${n}`; otherwise black positions `p, ..., n-1` when $n-p\ge2$ and none when $p=n-1$, $\tau$ `ident` when $n-p$ is even and `swapD` when odd, display `'A1'` when $p=1$ else `B${p}`. Then `'D III'`, `so*(${2n})`: for even $n$ black `0, 2, ..., n-2` (labels $1,3,\dots,n-1$), `ident`, display `C${n/2}`; for odd $n$ black `0, 2, ..., n-3` (labels $1,3,\dots,n-2$), `swapD`, display `BC${(n-1)/2}`. Then `'compact'`, `so(${2n})`, all black, `ident` for even $n$ and `swapD` for odd $n$, `null`.
- **E6**: `('E I', 'e6(6)', none, ident, 'E6')`, `('E II', 'e6(2)', none, FLIP_E6, 'F4')`, `('E III', 'e6(-14)', positions [2, 3, 4], FLIP_E6, 'BC2')`, `('E IV', 'e6(-26)', positions [1, 2, 3, 4], ident, 'A2')`, `('compact', 'e6(-78)', all, FLIP_E6, null)`.
- **E7**: `('E V', 'e7(7)', none, ident, 'E7')`, `('E VI', 'e7(-5)', positions [1, 4, 6], ident, 'F4')`, `('E VII', 'e7(-25)', positions [1, 2, 3, 4], ident, 'C3')`, `('compact', 'e7(-133)', all, ident, null)`.
- **E8**: `('E VIII', 'e8(8)', none, ident, 'E8')`, `('E IX', 'e8(-24)', positions [1, 2, 3, 4], ident, 'F4')`, `('compact', 'e8(-248)', all, ident, null)`.

### 5.4 `satakeRecord(name, entry)` (oracle `satake_record`, l.1811; SPEC 6.4 "Names in rank 2" and "Fields")

1. `board = boardFromName(name)`, guarded (5.2). `s = satake({ board, black: entry.black_nodes, tau: entry.tau })`; this throws `NotAdmissible` on a non-admissible entry.
2. Catalogue fields: `dynkin_type` = `name`; `cartan_label`, `real_form`, `restricted_type_display` copied; `black_nodes` sorted copy; `tau` copy.
3. `arrows`: the pairs of **white** nodes exchanged by $\tau$: for every position `i` not black with `tau[i] !== i`, the pair `[min(i, tau[i]), max(i, tau[i])]`, without duplicates, sorted lexicographically (oracle: `sorted({tuple(sorted((i + 1, e['tau'][i] + 1))) for i in range(n) if e['tau'][i] != i and i not in e['X']})`). A compact form has no arrows even when $\tau$ is not the identity.
4. `tau_moves_black_nodes`: true when some black position `i` has `tau[i] !== i`.
5. The 19 fields of `s`, by name (5.2).
6. **The $C_2$ adjustment** (6.4 "Names in rank 2", verbatim: "The restricted **board** is named in `restricted_board`: $B_r$ for a $BC_r$ system ($A_1$ for $r=1$), and for the four records just named `C2`, with `restricted_orbits_in_bourbaki_order` listing the short node first, so that the board is drawn like its relatives $C_p$ with larger $p$. This adjustment is made by `satake_record` (engine: `satakeRecord`); the plain function `satake` would say `B2`." The oracle's docstring of `satake_record`, `reference/lie_games.py` l.1811 to 1815, says the same in its own words): when `entry.restricted_type_display === 'C2'`, check that `s.restricted_board === 'B2'` (else `EngineError`, the oracle's assert), set `restricted_board` to `'C2'` and set `restricted_orbits_in_bourbaki_order` to a **reversed copy** of `s`'s list. Nothing else changes: `restricted_type` stays `'B2'` (6.4: "`restricted_type`, computed, which always writes `B2`"), and `restricted_simple_orbits`, `restricted_simple_multiplicities`, `restricted_cartan` and `restricted_reflection_word_lengths` keep the orbit order. The four records concerned are `su(2,2)`, `sp(4,R)`, `sp(2,2)`, `so*(8)`; `so(2,q)` keeps `B2` (display `B2`).
7. Compact form (6.4): "for a compact form the lists are empty and `restricted_type`, `restricted_type_display`, `restricted_board` and `restricted_orbits_in_bourbaki_order` are `null`". `arrows` is `[]`; `restricted_cartan` is `[]` as `P6-A1` returns it (the golden `su(4)` record).

### 5.5 `canonicalPair(d)` (oracle `canonical_pair`, l.1576; SPEC 5.5)

SPEC 5.5, verbatim: "apply every symmetry $g$ of the board to the pair, giving $(g(X),\,g\tau g^{-1})$, and keep the least result in the order "sorted black set, then the images under $\tau$"."

- Over **every** `g` of `symmetries(d.board)` (not only involutions; on $D_4$ all six, including the two of order 3).
- `black` = the sorted list of `g[i]` for `i` in `d.black`.
- `tau`: `t[g[i]] = g[d.tau[i]]` for every position `i` (this is $g\tau g^{-1}$).
- Keep the least `(black, tau)` comparing `black` lexicographically first and then `tau` lexicographically (Python tuple order; all candidates have black lists of the same length, because `g` is a bijection). Returns `{ black, tau }` in positions.
- No admissibility check: the function is defined for every well-formed pair (the enumeration of `admissible_counts` calls it on admissible pairs only, but `matchCatalogue` calls it on anything).

Examples (oracle): on $D_4$, black positions `[2, 3]` with the identity gives `{ black: [0, 2], tau: [0, 1, 2, 3] }`, the same as `so*(8)`'s own pair; `so(1,7)` (black `[1, 2, 3]`, $\tau$ `[0, 1, 3, 2]`) gives `{ black: [0, 1, 2], tau: [2, 1, 0, 3] }`; on $A_3$, `su(1,3)` (black `[1]`, $\tau$ `[2, 1, 0]`) is its own canonical pair.

### 5.6 `matchCatalogue(d)` (oracle `match_catalogue`, l.1592; SPEC 5.4, 2.15, T13)

## 9. Traps

1. **The catalogue's $\tau$ includes its action on black nodes; arrows are drawn between white nodes only** (6.4, 2.15). Store the full $\tau$ in `tau`; derive `arrows` from white nodes only. `su(4)` has `tau` labels `[3, 2, 1]` and no arrow; `e6(-14)` has `tau` exchanging 3 and 5 (both black) and one arrow `[1, 6]`.
2. **`so(p, 2n-p)` with $p\le n-2$ and $n-p$ odd has the swap as $\tau$ with no arrow drawn** (both swapped nodes are black). For $p=n-1$ the black set is empty and the swap is an arrow: `so(n-1,n+1)` is the quasi-split form. The oracle's rule: black `p..n-1` only when $n-p\ge2$; $\tau$ by the parity of $n-p$.
3. **`sp(p,q)` with $p+q=n$**; some references write `sp(2p,2q)` and `sp(8)` for what is here `sp(p,q)` and `sp(4)`; the Atlas notes it (6.5). Your data spelling is `sp(p,q)` and the compact form is `sp(n)`; the split form is `sp(2n,R)`.
4. **The compact form's $\tau$ is $-w_0$: the flip on $A_n$ ($n\ge2$), the swap on $D_n$ for odd $n$, identity otherwise** among the classical families; and **`FLIP_E6` on $E_6$** (Appendix B.1 `e6(-78)`), which the roster's "identity otherwise" does not cover. On $A_1$ the flip is the identity, so no special case is needed if `flipA(1)` is `[0]`.
5. **`restricted_type` is computed and says `B2`; `restricted_type_display` comes from the table.** Never "fix" `satake` or `restricted_type` to `C2`. The adjustment renames only `restricted_board` and reverses only `restricted_orbits_in_bourbaki_order`, as a copy (reversing in place would corrupt `satake`'s array if it is shared).
6. **Displays in rank 2 follow the family, not the board**: `su(2,2)` (on $A_3$) and `so*(8)` (on $D_4$) display `C2`; `so(2,q)` displays `B2`; `sp(1,1)` displays `A1`; `su*(4)` displays `A1` (`A${m-1}` with $m=2$). `C2` boards and `B2` boards are separate catalogue names with separate spellings (`sp(4,R)` against `so(2,3)`): "The catalogue is organised by board and does not merge coincidences between boards" (6.4).
7. **Cartan labels by $p$**: `A IV` and `B II`, `D II` exactly when $p=1$; `A III` covers both `su(p,q)` with $p\ge2$ and `su(p,p)`; `D I` includes `so(n-1,n+1)` and `so(n,n)`. The family order is $p$ ascending, then `D III`, then `compact`; on $A_n$ `A II` comes before the `su(p,q)`.
8. **`canonicalPair` runs over all symmetries**, the order-3 ones of $D_4$ included; only the enumeration of admissible pairs restricts $\tau$ to involutions. Conjugate correctly: `t[g[i]] = g[tau[i]]`, not `t[i] = g[tau[g[i]]]`; on $D_4$ with an order-3 $g$ the two differ.
9. **Comparison order**: the sorted black list first, then $\tau$, both lexicographic on integers (not on decimal text: `10 < 9` as strings). Lists of black nodes have the same length for every `g`.
10. **`matchCatalogue` returns records in catalogue order; `satake_examples.real_forms` is sorted.** Sort the names in the test, not in `matchCatalogue`. JavaScript's default sort and Python's agree on these ASCII strings (`'so(2,6)' < 'so*(8)'` because `(` precedes `*`).
11. **`matchCatalogue` must not throw `NotAdmissible`** and needs no admissibility call: a catalogue entry is admissible and admissibility is invariant under symmetries, so a non-admissible pair matches nothing. Only `satakeRecord` throws.
