## 9. Traps

- Values of more than 12 digits are shortened on screen (SPEC 4.0 Long numbers); the exact digits live in the table view, the tooltip, every export and `data-value`. (Roster trap.)
- A link's start entries are capped at 40 digits (SPEC 6.6); the sandbox can exceed that in play but not in a link. Positions are never state (7.4), so never turn the current position into a new `start` when copying a link or scrubbing. (Roster trap.)
- The two golden sequences differ: mutations alternate 2, 1, 2, 1 (the first move is at city 2) and firings alternate 1, 2, 1, 2 (the first move is at node 1). Both start at `[1, 0]`, but as a population and as numbers: $Cp$ of $(1,0)$ is $(2,-3)$, so the firing sequence is not the translation of the mutation sequence, and one linked-view link cannot reproduce both. Use two single-view links. By an accident of this symmetric board `numbers_end` equals `population_end` up to the sign of the second entry; a test that replayed only one sequence would pass for the wrong reason, so replay each.
- After move 38 the largest entry is 8944394323791464, just under $2^{53}=9007199254740992$; after move 39 it is 23416728348467685. The golden rule is strictly greater than $2^{53}$ (`> 2 ** 53` in `verify.py`); `Number.isSafeInteger` draws its line at $2^{53}-1$, so a `SafeInt` board throws `EngineOverflow` at move 39 as well. Do not reason with floating point anywhere near these numbers; compare decimal text.
- `mutation_nodes` and `firing_nodes` are labels (Appendix G); on this board labels are positions plus one, so a test that subtracts 1 by hand passes here and fails on an affine board. Use `toPositions`; the `g=A2~` e2e case (labels 0, 1, 2) is there to catch the stray `+ 1`.
- The oracle's `mutate` sums over every $j$, the diagonal included ($C_{ii}=2$), which is why only entry $i$ changes and it becomes $-p_i+\sum_{j\ne i}A_{ji}p_j$. You call the engine; never re-derive a move in a component or a test (SPEC 7.3: components contain no mathematics beyond calling the engine; COMMON 4.4: no golden value typed into source, the end values come from the golden file).
