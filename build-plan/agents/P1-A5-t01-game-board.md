### 5.2 Views and modes (SPEC 4 T1 table; 2.2; 2.3; 2.4(a))

The table, verbatim:

| View | Draws | Modes allowed |
|---|---|---|
| `populations` | one board with the population | `free`; `raising` (only cities whose number $a_i$ is negative: Kostant's game) |
| `numbers` | one board with the numbers | `free`; `legal` (only nodes whose number is positive; "game over" when none is) |
| `linked` | both, one above the other, with the line $a=Cp$ between them | `free`; `legal`; `raising`. Acting on a node of either board acts on both. |

- A mutation at $i$: $p_i\mapsto p_i-\sum_j C_{ij}p_j$ (2.2), `mutate`. A firing at $i$: $a_j\mapsto a_j-C_{ji}a_i$ (2.3), `fire`. Call the engine; "Components contain no mathematics beyond calling the engine" (7.3).
- `free`: every node may act (A-3: "in free play every node can be fired"). `legal`: a node may be fired "only when its number is **positive**, and the game ends when no number is positive" (2.3); the allowed set is `legalNodes(board, a)`. `raising`: a city may be mutated only where its number $a_i=(Cp)_i$ is negative (2.4(a): "a negative number a mutation that raises"); the allowed set is `raisingNodes(board, p)`. In the linked view `legal` and `raising` both test the numbers $a$. SPEC 4 T1 says only "both, one above the other" and does not say which board is on top: the plan puts the populations board above and the numbers board below (plan; record the order in your fragment).
- "The site offers both and always says which is active" (2.3): the mode in force is shown in words beside the board (plan: `data-out="mode"` with `free play`, `legal play` or `raising moves`).
- In `legal` mode, when no number is positive, the tool shows "game over" with the count, `data-out="gameOver"`; the SPEC acceptance names the text "game over after 3 moves" (plan: render `Game over after N moves.` and test case-insensitively; the singular for one move is your choice, recorded).
- In the linked view an action on node $i$ of either board mutates city $i$ and fires node $i$; the two records stay related by $a=Cp$ because $CS_i=R_iC$ (2.4(a)). Recompute both from the engine; never update one board from the other by hand.
- A view and a mode outside the table are refused: by the codec for links (6.6 "a view and a mode that the table of T1 does not allow together") and, for props, by throwing at build time with a message naming the instance (plan), so a lesson author sees the error.

## 9. Traps

1. The number in linked view is the DROP a mutation would cause, $a=Cp$, not Wildberger's gain $-Cp$ (D7; 2.4(e)). Never negate it.
2. Signs of the two restricted modes: `legal` allows a node when its number is POSITIVE; `raising` allows a city when its number $a_i$ is NEGATIVE (a mutation would raise it). The oracle's `play` uses `a[i] > 0` and `raising_play` uses `dynkin_labels(C, p)[i] < 0`, recomputed after every move.
3. Firing at $i$ changes $a_i$ and its neighbours ($a_j-C_{ji}a_i$, a column of $C$); a mutation changes only $p_i$ ($p_i-\sum_j C_{ij}p_j$, a row of $C$). Do not compute either in the component; call `fire` and `mutate`.
4. Positions inside, labels outside (E-7): `onAct` gives a position, `moves`, URLs, announcements and `data-node` use labels; convert only with `toLabels` and `toPositions`. A word from `play` or `raisingPlay` is in positions. Affine boards (phase 2) have label 0 first; a stray `+ 1` passes every phase-1 test and breaks there.
5. Fractions from $C^{-1}a$: denominators divide $\det C$; lowest terms with a stacked fraction, never a decimal; `data-value` is `p/q` (with a leading `-` on a negative numerator). You cannot `mutate` a rational vector: drive a numbers start with `fire` and derive populations with `toPopulation`.
6. `toPopulation` returns `null` exactly when $\det C=0$ (the oracle's `weight_to_root_coords` returns `None` when `determinant(C) == 0`). In phase 1 that means: numbers view only. Do not compute a level-zero population; that needs phase 2.
7. The fallback goes to `linked` when the population is fractional, but to `numbers` when there is no population at all (singular board). On $E_8$, $F_4$, $G_2$ ($\det C=1$) every numbers start has an integral population (2.4(c)).
8. The SafeInt-to-Big switch has no message. An `EngineOverflow` caught and shown as an error, or a notice, fails the SPEC sentence. A per-operation `SafeInt` may throw on an intermediate product even when the result would be safe (`P0-A2` measured this on `bigint_test`); switching on any `EngineOverflow` is correct.
9. A link with a forbidden move loads the default state with the notice (6.6), not a partial play. The codec replays; you never trim a move list.
10. `play` with a cap stops with `'cap'` after exactly `cap` moves; the oracle instead raises after move `cap + 1`. Report the cap as "still running after 20000 moves", never as an error, and never say "not of finite type" (4.0: those words only when `classify` says so, which is phase 2).
11. "play to the end" uses the lowest position (E-5); "step" must make exactly the move the full play would make next, so that stepping $N$ times equals one play to the end. Pass no `choose`.
12. One announcement for a whole play (A-4, 4.0); do not announce each of its moves. Undo needs no legality test (4.0).
13. Prediction steps: board frozen AND hints off (4 T1 "Hints ... off in prediction steps").
14. No tool's default state may need the worker; T1 never enumerates. Only a long move list from a link or a play to the end off the named finite boards may go to the worker, and before phase 2 every custom board counts as not finite (E-9 rule 2).
15. The first tool on a page is `client:idle`, later ones `client:visible`; T1 placed by a lesson must honour whichever directive the lesson gives. Nothing that touches `window`, `document`, `location` or `localStorage` may run during the server render.
16. Svelte 5 only: `$state`, `$derived`, `$props`, `$effect`, snippets, `onclick`. No `export let`, `$:`, `writable` for local state, `on:click`, slots. The one store idiom is a Nano Store read as `$name`.
17. Do not send KaTeX to the client: the $a=Cp$ line and `Frac.svelte` are plain markup or MathML.
18. `bigint` breaks `JSON.stringify`; export through `exportJSON`, which writes unsafe integers as decimal strings (6.6).
19. The bridge sentence wording is SPEC's ("The number on node i ..."), not the roster's paraphrase ("The number on a node ..."). Any other place in T1 that shows both views shows the same words.
20. The Board family is shared with `P0-A5`'s index seed, T2 (`P1-A6`) and T9 (`P1-A7`) in your stage. Breaking a CONTRACTS 5.1 prop, the keyboard model or the hooks breaks them silently; run `P0-A5`'s unit and keyboard tests after each change.
21. Golden keys `longest_word` and `fired_values` are labels in the file; your tests compare labels, and must not call `covers()` for keys owned by `P1-A1`.
22. 4.0 hooks: browser tests read hooks and the live region "and nothing else". Do not select by CSS class or visible text other than `data-out` contents.
