# Decisions of RT-FIX-P6-t13 (phase 6 red-team round, cluster t13: T13, the Satake Studio)

## 2026-10-26 RT-FIX-P6-t13: the hooks of the paint buttons and of the restricted board (P6-RT-10-05 P6-RT-05-03)
Decision: the paint buttons of the decoration carry `data-board="numbers"` and `data-value` "1" on a black (filled) node and "0" on a white (hollow) one; the colour stays readable in `data-colour` ("black" or "white"), which the tests already read. The buttons of the restricted board carry `data-board="populations"`, since the shadows play a mutation game of their own there (SPEC 2.15), and `data-value` stays the shadow coordinate. This replaces, for these two hooks, the entry "2026-10-25 P6-A3: the data-out names and the extra hooks (deviation to confirm)" of decisions/P6-A3.md (DECISIONS.md): its `data-board="decoration"` with `data-value` the colour, and its `data-board="restricted"`, no longer hold; the rest of that entry (the data-out names, `data-colour`, `data-arrow`, `data-black-arrow`, the picture's hooks, `data-panel-tab`, the controls) stands. One hook is added to the table view: `data-table-population` (the node's label) on each cell of the Population column, so that the regression test of P6-RT-05-03 reads the cell through a hook. What the specification left open: 4.0 Test hooks [D] names two values of `data-board`, populations and numbers, and the decoration copy (6.3 last bullet) plays neither game. Default used: none in section 10; the choice of "numbers" keeps the populations that a test or a lesson's Challenge reads on T13 to the game board and the restricted board, and "1" and "0" follow the fill (filled, hollow) as the sign encoding of 6.3 does. Reason: SPEC 4.0 Test hooks, 2.15; the finding as raised by its refuter. Open question for MERGE or the owner: Challenge.svelte reads every `[data-node]` of a tool and sorts the values of one `data-board` by label, so a `reach`, `distinct` or `mixed-signs` check on the populations of a T13 instance would now read the game board and, while the Restricted board panel is open, the restricted board together. No lesson has such a check today (the three Challenges of M9 on T13 are of kind `out`); a group hook that Challenge could read (the lens's proposed fix) is a change to `site/src/components/lesson/`, outside this cluster.

## 2026-10-26 RT-FIX-P6-t13: the records for display come from satakeRecord (P6-RT-02-01)
Decision: `assembleData` (t13/model.ts) takes the restricted board's name and the orbits in Bourbaki order of each entry from the record for display of the reader's own pair, `displayRecord(d, r)`: `satakeRecord` on the board's name with the matched record's catalogue fields (real form, Cartan's label, `restricted_type_display`) and the reader's black nodes and tau. `matchCatalogue` returns `satakeRecord`'s own output for each catalogue pair, so a matched record whose pair is the reader's is that record already and is used as it is; `satakeRecord` runs only for a pair that is the image of a catalogue pair under a symmetry of the board. The site no longer applies the C2 adjustment of SPEC 6.4 itself. Every value shown is unchanged (the unit test compares with `satakeRecord` on every catalogue pair and every symmetry image of rank at most 6, and the existing tests compare every field of every record with the golden file). This replaces two sentences of decisions/P6-A3.md: in "the C2 drawing rule", "the C2 adjustment is applied record by record (where the record displays C2 and satake says B2, the restricted board is named C2 and satake's orbits in Bourbaki order are reversed)"; and in "where the Satake data are computed", "`satakeRecord` is not called (the records come from `matchCatalogue`)": it is now called by `assembleData` for a symmetry image, on the main thread. The rule of which record decides the drawing (MERGE ruling (1) on P6-A3) is unchanged. Where it runs: the data path of t13/load.ts is unchanged (satake, restrictedBoard and matchCatalogue through engineCall; the unit test "where the computation runs" still asserts that it calls no `satakeRecord`). Among the 32 boards only D4, D6 and D8 have catalogue pairs that a symmetry moves (8, 1 and 1 such images, counted over every catalogue entry and every symmetry; every Satake diagram of the other boards is fixed by their symmetries, and E7 and E8 have none but the identity), so on E7 and E8 nothing runs on the main thread (E-9 item 3; a unit test checks that `displayRecord` returns the matched record itself on every admissible pair of E7 and E8). Measured in Node on this shared machine (warm, three runs each): the worst `satakeRecord` on such an image took 4.1 ms on D8 and 2.3 ms on D4 at a moderate load, and 28.8 ms on D8, 8.4 ms on D6 and 17.2 ms on D4 while a build ran beside it; it runs once when the data of such a pair arrive. What the specification left open: where in the site's data path `satakeRecord` is called. Reason: SPEC 6.4 "Names in rank 2", Appendix H Rules, 5.1 E-9.

## 2026-10-26 RT-FIX-P6-t13: the typeset names load on the reader's own actions only (P6-RT-07-01)
Decision: `setConfig` no longer fetches the typeset names. They are fetched by the reader's own actions: a paint (on the decoration or in the table view), a choice of tau, the board picker, an example, a catalogue entry, a panel tab and the back button (popstate). A link read while the island hydrates loads its pair without them, and the names of a link state are written in the plain markup of t13/names.ts until the first action (the server's typeset markup is the default state's). This is the design decisions/P6-A3.md records ("in the browser only after the reader's first change of decoration or of panel"), which the hydration path had broken; the back button counts as the reader's change. Sizes, `npm run size -- --port 7361` (scripts/size.mjs, bare routes; 90 routes, 0 over budget before and after): `/tools/satake/`, `/embed/satake/` and `/modules/m9-real-forms/` 87.1 kB on the base 0436a53 and 87.2 kB on this branch (the two helpers that convert labels of the drawn restricted board and `displayRecord`). Measured by the regression test (T13.spec.ts, regressions, the way npm run size measures a bare route): the default route 87068 B before and 87208 B after; the Atlas links A3 x=1.3, D8 x=1.3.5.7 and E6 x=2.3.4.5 92298 B before (the extra script satakeNames, 5230 B) and 87208 B after, the same scripts as the default state. Reason: SPEC 7.6, 6.6.
