## 2026-10-31 RT-FIX-P6-pages: D10 default used, the projects kept separate (P6-RT-10-04)
Decision: this project and the research-software specification "MutationGraph" are kept separate. The site and the engine share no fixtures with it: `reference/golden_data.json` is this site's acceptance oracle and is not published as fixtures for another project, no source of the site or of the engine names MutationGraph or reads its files, and the site states no common rule for the two projects. The note that D10 asks for, on this project's side: on a simple graph, where A_ij = A_ji is 0 or 1 (SPEC 2.1), the mutation rule p_i <- p_i - sum_j C_ij p_j with C = 2I - A^T reads p_i <- -p_i + (the sum of the populations of the neighbours of i), and C = 2I - A^T is C=2I-A because A is symmetric; so on simple graphs the rule and C=2I-A agree. The site states it in M2 beat 3 (`site/src/content/modules/m2-form.mdx`: on a board with single roads the matrix of the form is B = 2I - A, which is the Cartan matrix C = 2I - A^T of module zero because A is symmetric, and the mutation subtracts (p, e_i) from city i, "the rule of module one"). So no reference page needed a new sentence, and none of them names the other project. The note on the side of MutationGraph lies outside this repository and is the owner's. What the specification left open: D10, the relation to MutationGraph (options: share `golden_data.json` as fixtures and state the common mutation rule; or keep the projects separate); SPEC does not say where in this project the note stands. Default used (SPEC section 10, D10): keep separate; note in both that on simple graphs the rule and C=2I-A agree. Whose default: every build agent's since phase 0, none of which shared a fixture or named the other project; no entry recorded it (RT-10 attack 18). Reason: no answer recorded; the default needs no code. Test: `site/tests/unit/repo-defaults-recorded.test.ts` (the record names M2 beat 3, and the test reads the note there).
