# Decisions of P1-A1 (engine phase 1: matrices, translator, plays, searches, roots, finite-type data)

## 2026-10-10 P1-A1: versions observed
Decision: built and tested against node v22.22.0, typescript 6.0.3, vitest 5.0.3, fast-check 4.10.2, all as installed by `npm ci --prefer-offline` from the committed lockfile. What the specification left open: nothing; recorded as the instruction asks (5.15). Default used: none. Reason: the toolchain postdates training data (COMMON.md 3); the type definitions of `fc.assert` (`seed`, `numRuns`), `fc.property`, `fc.constantFrom`, `fc.array`, `fc.integer`, `fc.bigInt` and Vitest's `it(name, { timeout }, fn)` were read under `node_modules/` before use.

## 2026-10-10 P1-A1: parameter types of the rational helpers, and ratNeg
Decision: `rat(num: bigint | number, den: bigint | number = 1n)`; the seven other helpers take and return `Rational` (`{ num: bigint; den: bigint }`, den > 0n, lowest terms, zero as `{ 0n, 1n }`). A `number` argument must be a safe integer, else `RangeError`; a zero denominator and `ratDiv` by zero throw `RangeError`. One extra helper is exported, `ratNeg(a)`, used by `determinant`. `ratEq` compares by cross product so that it is right even on an unnormalised input. What the specification left open: parameter types (CONTRACTS.md 2.4 names only the functions). Default used: the plan's (P1-A1 instruction 5.2). Reason: E-3, no library; the harness's `ratText` and `ratToString` agree on every value (unit test).

## 2026-10-10 P1-A1: determinant by rational elimination; the empty matrix has determinant 1
Decision: `determinant` is the oracle's method (lines 995 to 1009) over `Rational`: pivot the first nonzero entry at or below the diagonal, negate on a row swap, eliminate below. The empty matrix gives 1, as in the oracle. A non-square matrix or a non-integer `number` entry is a `RangeError`. What the specification left open: the elimination method ("fraction-free or rational elimination"). Default used: rational elimination. Reason: the matrices have at most 12 rows and the method matches the oracle line for line; Bareiss would give the same value.

## 2026-10-10 P1-A1: solve and inverse, null on a singular matrix
Decision: `solve(M, b): Rational[] | null` (Gauss-Jordan, the oracle's lines 656 to 669) and `inverse(M): Rational[][] | null` (one Gauss-Jordan on `[M | I]`, equal to the oracle's column-by-column solves) return `null` when `M` is singular, where the oracle raises `StopIteration`. `solve` throws `RangeError` on a right-hand side of the wrong length. Entry types: `number` (integer), `bigint` or `Rational`, mixed within a call. What the specification left open: CONTRACTS.md 2.4 names only `determinant`; 2.1 places `solve` and `inverse` in `linalg.ts`. Default used: the plan's signatures (5.3). Reason: consistent with `toPopulation` returning `null`; raised under `openQuestions` in the report as a contract addition to confirm.

## 2026-10-10 P1-A1: transposeBoard and subBoard: name, arith, kind; the Board<T> overloads
Decision: `transposeBoard` returns `C^T` in fresh frozen rows, a copy of the labels, the board's own `arith`, the `boardKind` of the transposed integer matrix, and the finite name whose standard matrix equals `C^T` under `P0-A2`'s phase-0 rule (`finiteNameOf`, reused unchanged, families A to G at rank n), with the exception that the `C2` matrix stays unnamed; otherwise `name` is undefined. The match is by matrix only, so a sub-board whose matrix is a standard one gets a name on transposition although its labels may not be 1..n; `identify` settles names in phase 2. `subBoard` sorts the chosen positions, keeps their labels unchanged (E-7), takes the kind of the induced matrix, the board's arithmetic and no name. Both have the overload `<T>(board: Board<T>, ...): Board<T>` before `(board: AnyBoard): AnyBoard`; `components` is generic `<T>(board: Board<T>)`, which accepts `AnyBoard`. What the specification left open: `name`, `arith`, `kind` of derived boards. Default used: the plan's rules (5.4). Reason: a sub-board of a finite board is finite (E-2 gives no reason for `Big`); the rank-2 computed name is `identify`'s business (COMMON.md 2); the overloads keep the arithmetic type in `finite.ts` and the tools without `any`.

## 2026-10-10 P1-A1: RangeError cases added
Decision: `RangeError` on a position outside 0..n-1 (`mutationMatrix`, `firingMatrix`, `kostantPlay`, `subBoard`, `longestWord`), a vector of the wrong length (`toNumbers`, `toPopulation`, `applyWord`, `legalNodes`, a seed of `orbitGraph`), an empty or repeated node list (`subBoard`, `longestWord`), an unknown `game` string (`applyWord`, `orbitGraph`), a cap that is not a non-negative integer (the searches and the plays), a `maxDepth` that is not a non-negative integer, more distinct seeds than the cap, an empty seed list, `legalOnly` with `'mutation'`, an index outside the items (`wordTo`), a `choose` that returns a node not allowed, a non-integer `number` given to `rat` or to a matrix. What the specification left open: invalid arguments the specification does not cover. Default used: `RangeError`, as `P0-A2` did for `mutate`, `fire` and `toPositions`. Reason: E-10 reserves the engine's own classes for the theory; a cap is never thrown.

## 2026-10-10 P1-A1: mutationMatrix and firingMatrix return number entries
Decision: both return `number[][]` whatever the board's arithmetic, converting `bigint` entries with `Number`. What the specification left open: the entry type of the matrices. Default used: plain numbers (CONTRACTS.md 2.4). Reason: road counts are small; `verify.py` and the property tests multiply these matrices as integers.

## 2026-10-10 P1-A1: argument rules of orbitGraph
Decision: `cap` is an integer at least the number of distinct seeds (the oracle asserts `len(graph) <= cap`); an empty seed list is a `RangeError` (the oracle's `max` over an empty graph fails); `maxDepth`, when given, is a non-negative integer; a repeated seed is kept once at its first occurrence; `legalOnly` is defined for `'firing'` only and with `'mutation'` is a `RangeError`. Positions are keyed by `arith.show` of the entries joined with commas. The order and truncation rule is SPEC.md 5.5 verbatim: `completeLayers` is the depth of the position being expanded when the cap acts, also when the cap falls exactly at the end of a layer (the triangle with a cap of 9 reports 1). `depthReached` is the depth of the last item, since breadth-first order has non-decreasing depth. No edges are stored (SPEC.md 5.4). What the specification left open: argument validation. Default used: the plan's (5.6). Reason: port of `orbit_graph_capped` with the `legal_only` test of `orbit_graph`.

## 2026-10-10 P1-A1: orbit keeps breadth-first order and reports truncation
Decision: `orbit` returns `{ items, truncated }` of `orbitGraph` with the same arguments, in the same order. What the specification left open: the oracle's `orbit` without `max_depth` returns an unordered set and raises at the cap. Default used: the plan's (5.6). Reason: E-6 and E-10 (a cap is reported, never thrown); one search routine for every caller.

## 2026-10-10 P1-A1: positiveRoots: default cap, no truncation report, the internal helper
Decision: `positiveRoots(board, cap = CAPS.mainThreadItems, maxDepth?)` returns a plain sorted array and cannot report truncation; callers off the finite types use `roots` with `maxDepth`. The sort is by total in the board's arithmetic, then entry by entry, through `arith.sign(arith.sub(...))`, never through text. The filter-and-sort step is the module export `positiveRootsFrom(board, items)` of `search.ts`, shared with `finite.ts` so that the finite functions run one search and still see `truncated`; it is not re-exported from `index.ts` and is not part of the public API. What the specification left open: the default cap and the truncation report. Default used: the plan's (5.6). Reason: E-9's main-thread bound; a finite board of at most 12 nodes has at most 288 roots.

## 2026-10-10 P1-A1: the default caps of the plays and the wording of the cap rule
Decision: `play`, `raisingPlay` and `kostantPlay` default to `cap = CAPS.playMoves` (20000). The rule: when no node is allowed the result is `'ended'`, even at exactly `cap` moves; when nodes are allowed and `word.length === cap` the result is `'cap'` with exactly `cap` moves, before move `cap + 1`. A cap of 0 gives `'cap'` with 0 moves when a move is allowed and `'ended'` otherwise. `choose` receives the allowed positions in increasing order and the current vector. What the specification left open: the oracle's default of 1000000 raises instead of reporting; `play_fate` (phase 2) tests its cap after recording the move. Default used: the plan's wording (5.7). Reason: SPEC.md 5.6 ("stop, `status: 'cap'`, reported as still running after 20000 moves") and E-10.

## 2026-10-10 P1-A1: the meaning of fired in raisingPlay
Decision: `fired[k]` is the number `(C p)_i` of the city at the moment it is mutated, negative for every raising move, so the city rises by `-fired[k]`; `-1` throughout on a simply laced board (F13). What the specification left open: the field has no stated meaning for this play. Default used: the plan's (5.7). Reason: it is the quantity the bridge sentence of 2.4(a) names, and it lets a tool show the rise.

## 2026-10-10 P1-A1: internal caps and the NotFiniteType fallback of finite.ts
Decision: the internal root search of the six finite functions is `roots(board, CAPS.workerPositions)`, and the internal play of `longestWord` has the cap `CAPS.workerPositions`; a truncated search, a play at its cap, a count of dominant positive roots other than 1 or 2 in `highestShortRoot`, or a `-w0` image that is not a unit vector in `minusW0` throws `NotFiniteType`. Each function's first statement is a comment marking where `P2-A1`'s guard call goes; no work precedes it. No test pins a finite function on a one-way board. `coxeterNumber` divides as integers through `bigint`. What the specification left open: E-11 says the guards are phase 2; E-6 still requires a bound. Default used: the plan's (5.8). Reason: `NotFiniteType` is the class SPEC.md 5.6 gives for a `gcm` board off the finite types; `P2-A1`'s guard throws `NeedsTwoWayRoads` first on a one-way board.

## 2026-10-10 P1-A1: placement of Rational, Enumeration, OrbitGraph, PlayResult
Decision: `Rational` is declared in `rational.ts`, `Enumeration` and `OrbitGraph` in `search.ts`, `PlayResult` in `play.ts`, all verbatim from SPEC.md 5.2 and re-exported as types from `index.ts`. What the specification left open: the file. Default used: the plan's placement (5.2, 5.6, 5.7). Reason: each type lives with the functions that return it.

## 2026-10-10 P1-A1: fast-check seeds and run counts
Decision: every property file records `SEED = 20261010` (the seed of `P0-A2`'s property 1) and its `NUM_RUNS` literally: p2-translator 500, p3-transpose 500, p4-orders 200 (per type, the pairs exhaustive), p6-convergence 300, p7-roots-signs 200, p8-generic-game 300; the unit test p1-rational-linalg uses the same seed with 200 and 300 runs. What the specification left open: the seeds and counts. Default used: the plan's minimum of 200 runs. Reason: CONTRACTS.md 3, "a fixed seed recorded in the file".
