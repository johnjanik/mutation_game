## 2026-10-17 RT-FIX-P3-nojs-phase4: data-measured marks an output that measures the reader's machine (P4-MERGE-04)
Decision: a `data-out` element whose text is a measurement taken on the reader's machine while the page runs (a time read with `performance.now`) carries the attribute `data-measured` (present, empty value). It is not part of any default state: the server markup renders the element empty and the hydrated tool fills it. The elements so marked: T10's `drawMs`, and the drawing-time probe's `drawTime`, `drawTimes` and `firstDrawTime` (`site/src/components/draw/DrawTimeProbe.svelte`, the only other component that times with `performance.now`). The comparison of `site/tests/e2e/nojs.spec.ts` ("the server markup shows the default state's values") lists such an element as `name (measured)` instead of `name=text`: the element must exist, with the attribute, both in the server markup and after hydration, and only its value is not compared; every other `data-out` is still compared by its text. The rule is driven by the attribute on the element, never by a list of names in the test. What the specification left open: SPEC 7.6 asks the drawing time to be recorded and 4.0 asks the default state to be rendered at build time; neither says how a measurement is told apart from the state. Default used: none of section 10; plan addition (the orchestrator's brief for this cluster). Reason: a time measured on the reader's machine can never appear in markup made at build time. The attribute is an addition to the hooks of SPEC 4.0 that no criterion reads; it is documented in the header comments of `nojs.spec.ts`, `T10GeometryStudio.svelte` and `DrawTimeProbe.svelte`. For MERGE: CONTRACTS.md 5.1 and 5.2 list the hooks; if MERGE counts this attribute as a hook, it belongs there.

## 2026-10-17 RT-FIX-P3-nojs-phase4: the Average tab of T11 draws the big board, with no node to act on (P4-MERGE-01)
Decision: the Average tab draws the same big board panel as the Fold tab (`data-out="big-board"`, the orbit overlay with its rings and badges, the node values), between the line naming the averaged type and the table of length classes, so that the tab has a default figure with its text alternative (the board group's name `Big board A5`) before and without JavaScript. On the Average tab no node can act: every node has `data-can-act="false"`, the board is passed `disabled` (after hydration its buttons keep the one tab stop with `aria-disabled="true"`, as a frozen board, RT-FIX-P3-board-a11y), and a click makes no move. The folded board, the History strip and symmetric play stay on the Fold tab. The panel is one snippet used by both tabs, so the two drawings cannot drift apart. What the specification left open: SPEC 4 T11 says the Average tab "averages the roots instead and names the resulting type"; 4.0 and 7.4 require a default figure ("the SVG board with its values") for every tool's default state, and the preset `average` opens on that tab. Default used: none of section 10; the plan's. Reason: the board whose orbits are averaged is the figure the tab's sentence is about; a second, playable copy of the moves on a tab without History would make moves the reader cannot see or undo there.

## 2026-10-17 RT-FIX-P3-nojs-phase4: T10 reads its data files at build time and loads the orbit as the browser does (P4-MERGE-03)
Decision: during server rendering `t10/snapshot.ts` reads the files of `site/public/presets/T10/` (the manifest `index.json` and the data files the browser fetches) through `import.meta.glob` with `?raw`, inside the `import.meta.env.SSR` branch, as `pages/dev/draw-time.astro` does, so the browser build carries none of them (`npm run size`: `/tools/geometry/` 89.8 kB gzip against 89.7 on the base built on this machine, limit 90; `/tools/fold/` 81.7 against 81.6). The snapshot runs the browser's own decision `loadPlan(facts, manifest, 'load')`: when the manifest has a file for the configured board and rings, the server's orbit is that file read by `fromPresetFile` (source `preset`, both graphs, as the browser gets it); otherwise it is computed in-process as before, with the move graph when it is the graph shown or when the browser derives it at once (`moveGraphFitsOneTask`, the rule of the component's move-graph effect). A configuration that the browser leaves waiting for "Draw the orbit" (more than 2000 items, E-9 rule 1) starts in the state `wait` on the server too, with its vertices when they belong on the main thread, while the snapshot still draws the whole orbit (7.4). `data-out="source"` is shown whenever the orbit is complete, before hydration as after. What the specification left open: how the build-time markup learns which data file the browser will read. Default used: none of section 10; plan addition. Reason: SPEC 4 T10 Presets says the default's vertices and edges are shipped as data files that the tool fetches, so the default state is the one drawn from that file, and 4.0 asks that state to be the server markup.
