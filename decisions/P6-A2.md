## 2026-10-25 P6-A2: the order of checks
Decision: `satakeCatalogue(name)`: `boardFromName(name)` (NotABoard on a name it does not know), then `requireGcm` and `requireFinite` (NeedsTwoWayRoads, NotFiniteType), before any entry is built. `satakeRecord(name, entry)`: `boardFromName(name)` (NotABoard), then the shape of the entry (RangeError: not an object, `tau` not a permutation of `0..n-1`, `black_nodes` with a repeated, fractional or out-of-range position), then the guard, then `satake` (NotAdmissible). `canonicalPair(d)` and `matchCatalogue(d)`: the shape of the diagram (RangeError), then the guard, then (matchCatalogue only) the name of the board (RangeError, below). What the specification left open: the instruction says "Decide through guards.ts as the first statement"; MERGE accepted for P6-A1 the engine-wide order "argument shape, then kind, then class", both before any computation. Default used: that order, so a malformed pair is a RangeError on every kind of board. Reason: one order across the public API (P2-A1 to P6-A1). A one-way board without a name still gives NeedsTwoWayRoads from matchCatalogue, as the guard runs before the name check.

## 2026-10-25 P6-A2: error classes of satakeCatalogue and satakeRecord on names
Decision: an unknown name (`Q7`, `A0`, `B1`, `D3`, `E9`, `BC2`, the empty string) throws NotABoard from `boardFromName`; an affine, twisted or preset name (`A2~`, `C2~`, `G2~`, `D4^(3)`, `pentagon`) builds a board that the guard refuses with NotFiniteType; both are `EngineError`. Ranks beyond 8 follow the parametric rules (`satakeCatalogue('A9')` has 8 entries, `D9` 11). What the specification left open: 5.6 speaks of boards, while these two functions take a name (plan). Default used: the plan's (instruction 5.2). Reason: the name is the board; named in `openQuestions`.

## 2026-10-25 P6-A2: matchCatalogue on a board without a name, or with a name that is not its own
Decision: `matchCatalogue` throws `RangeError('matchCatalogue needs a board built by boardFromName')` when the board has no `name` (a custom board of finite type, a sub-board, the C2 matrix built by `fromAdjacency`, the sum of two A2), and also (plan addition, defensive) when the board's integer matrix is not the standard matrix of its name (`cartan(name)`), so that a hand-made object carrying another board's name cannot match the wrong catalogue. `canonicalPair` needs no name and works on every finite board, in several pieces included. What the specification left open: 5.4 and T13 do not say what a board without a name matches. Default used: the plan's (instruction 5.6); the matrix check is mine. Reason: the catalogue is organised by board name (6.4); T13 offers only named boards. Named in `openQuestions`.

## 2026-10-25 P6-A2: satakeRecord fields and the C2 adjustment
Decision: the record is a plain object built field by field in the oracle's order (`dynkin_type`, `cartan_label`, `real_form`, `black_nodes`, `tau`, `arrows`, `tau_moves_black_nodes`, `restricted_type_display`, then the 19 fields of `satake` copied by name), which is also the key order of the golden records. `dynkin_type` is the name given; `black_nodes` a sorted copy; `tau` a copy; `arrows` the pairs `[min(i, tau[i]), max(i, tau[i])]` for white `i` with `tau[i] != i`, each once, sorted lexicographically; `tau_moves_black_nodes` is true when some black `i` has `tau[i] != i`. The adjustment of 6.4 "Names in rank 2" is keyed on `entry.restricted_type_display === 'C2'`, as the oracle's `satake_record`: it checks `satake`'s `restricted_board` is `B2` (else `EngineError('restricted board of a C2 record is not B2')`, the oracle's assert), sets `restricted_board` to `C2` and `restricted_orbits_in_bourbaki_order` to a reversed copy (inner lists copied too). `restricted_type` stays `B2`, and every other field keeps `satake`'s orbit order. The arrays of `satake`'s result are placed in the record as they are (each call of `satake` builds fresh ones). What the specification left open: nothing beyond the plan's field order. Reason: SPEC 5.2 ("records with the golden field names"), 6.4.

## 2026-10-25 P6-A2: canonicalPair and matchCatalogue
Decision: the class representative is the least `(sorted g(X), g tau g^-1)` over every symmetry `g` of `symmetries(board)` (default limit; at most 6 on a finite board, D4's rotations included), with `t[g[i]] = g[tau[i]]`, comparing the black lists first and then tau, lexicographically on integers (Python's tuple order). No admissibility check. `matchCatalogue` computes `symmetries(board)` once per call and passes it to the private helper for the diagram and for every entry, and calls `satakeRecord(name, entry)` only for the matching entries (at most two), in catalogue order; it never throws NotAdmissible, since a pair that is not admissible matches no entry. The examples of the instruction (D4 black 3, 4 or 1, 3 or 1, 4 with the identity giving `{ black: [0, 2], tau: id }`; so(1,7) giving `{ black: [0, 1, 2], tau: [2, 1, 0, 3] }`; su(1,3) its own pair) and six more were checked against the oracle's `canonical_pair` by a script in the scratch directory. What the specification left open: nothing (5.5 verbatim). Reason: E-5.

## 2026-10-25 P6-A2: names.json sections, TeX spellings and the alt field
Decision: `scripts/names.mjs` keeps P0-A3's `names` object (exactly the 32 type keys in golden order), the four KaTeX options, the resolution of KaTeX from `site/`, `texOfName`, `writeNames` and `catalogueNames`, and adds beside `names` three sections, each mapping a data spelling to `{ text, tex, html }`, read from the golden key `satake` (read only) in first-appearance order:
- `realForms` (167): TeX by the plan's spellings, `sl(N,R)` to `\mathfrak{sl}(N,\mathbb{R})`, `su*(N)` to `\mathfrak{su}^*(N)`, `su(p,q)`, `so(p,q)`, `sp(p,q)` and `su(N)`, `so(N)`, `sp(N)` with `\mathfrak{su}`, `\mathfrak{so}`, `\mathfrak{sp}`, `so*(N)` to `\mathfrak{so}^*(N)`, `sp(N,R)` to `\mathfrak{sp}(N,\mathbb{R})`, `e6(-14)` to `\mathfrak{e}_{6(-14)}` and likewise `e7`, `e8`, `f4`, `g2`; any other spelling throws, naming it (exported `texOfRealForm`). Each `su*(2m)` entry carries `alt: { text: 'sl(m,H)', tex: '\mathfrak{sl}(m,\mathbb{H})', html }` (SPEC 6.5, exported `altOfRealForm`): su*(4) with sl(2,H), su*(6) with sl(3,H), su*(8) with sl(4,H).
- `cartanLabels` (24): TeX `\text{<label>}`, `\text{compact}` for the compact form (exported `texOfCartanLabel`, which accepts `A` to `F` followed by a Roman numeral I to IX, `G` and `compact`).
- `restrictedTypes` (36): every non-null value of `restricted_type_display`, `restricted_type` and `restricted_board`, scanned in that order within each record (the order of the fields in the file); typeset by `texOfName`, whose grammar now also accepts `BC` followed by a rank (`BC2` gives `BC_{2}`).

Affine and twisted names (`C2~`, `D4^(3)`) are not added: `texOfName('A4~')` still throws (P0-A3's note against its own test; named in `openQuestions`). The `sp(2p,2q)` note of 6.5 is the Atlas's text, not a name. What the specification left open: the section names, the TeX source spellings and the field name `alt` (plan). Default used: the plan's spellings (braces round every argument, `\mathbb{R}`, `\mathfrak{e}`), which render as the 6.5 display names. Reason: SPEC 7.3 and 6.5; the test pins the spellings only so that the output is stable.
