# Decisions of RT-FIX-P3-codec-state (red team round 1, cluster codec-state)

## 2026-10-17 RT-FIX-P3-codec-state: the 12-node cap on board names (P3-RT-04-01)
Decision: `resolveBoard` (site/src/lib/state.ts) refuses every board with more than 12 nodes, named or custom, with the RangeError "board has more than 12 nodes" that a custom matrix already got. A finite name (`A13`) and an untwisted affine name (`A12~`) are refused from their text (rank, plus one for `~`) before `boardFromName` builds a matrix, so that a 512-character name such as `A999...9` cannot freeze the tab; every other name (twisted, `pentagon`, `square`) is checked on the board built, which the engine bounds at 13 nodes. The codec turns the error into rule 2 as before; T16's import of a name above the cap gives the error's text as its reason ("The board could not be read: board has more than 12 nodes. The board was left as it was.") instead of "no board is named". What the specification left open: nothing on the rule (SPEC 6.6 Validation applies the 12 nodes to every board; CONTRACTS 4); the wording of T16's reason is plan wording. Reason: SPEC 6.6, 2.8 scope, CONTRACTS 4 resolveBoard comment.

## 2026-10-17 RT-FIX-P3-codec-state: a T5 link whose lambda the calculator cannot take (P3-RT-04-03)
Decision: a T5 link whose `d` parses but has a negative entry or an entry of more than 6 digits loads the whole default state with the notice, as every other link T5 cannot read does. This replaces the part of the entry "P3-A3: legal play only, and the link rules" (decisions/P3-A3.md) that kept the link's board, start and moves, reset lambda and showed the notice. What the specification left open: SPEC 6.6 allows only two outcomes, the whole link with no notice or the whole default state with the notice; the finding's two options were these. Default used: the second, because it keeps P3-A3's recorded rule that such a `d` is a link T5 cannot read (and its cap of 6 digits on a link), keeps every existing T5 test green (`a link is read with the legal rule and the lambda cap`), and needs no new behaviour in the calculator for a lambda it refuses. Reason: SPEC 6.6 Validation; finding P3-RT-04-03.

## 2026-10-17 RT-FIX-P3-codec-state: one board object per spec while a tool loads (P3-RT-03-05)
Decision: `resolveBoard` keeps the boards it builds in a map from the spec (a name, or the matrix as JSON; `xy` does not count) to the board object, and empties the map in a microtask queued when the first board of a run of synchronous code is stored. A tool loads its board in one such run (its script and its first render), so every `resolveBoard` of one spec in that load returns one frozen object and the verdict cache (keyed by object, E-11) is hit: one `classify` per load. What the specification left open: the scope of the reuse (SPEC 5.6 says "once when the board is loaded"; E-11 keys the cache by board object). Not chosen: a map kept for the life of the page, which the orchestrator's note suggested ("one board object per spec"). It would make the adopted reproducer read 0 calls instead of 1 for the triangle, which `t02/presets.ts` resolves when the module loads, so the reproducer (unchanged, as RT-FIX 5.3 requires) could not pass; it would also need a bound of its own choosing on the number of boards kept. Consequence for an existing test: `site/tests/unit/tools/T04.test.ts > T4 verdict > buildVerdict calls classify once per board object` obtained a second board object by resolving the same spec again in the same synchronous run, which now returns the same object; the test now awaits the end of the run first (`await Promise.resolve()`), and its assertion (`not.toBe(first)`) is unchanged. Reason: SPEC 5.6 last sentence, E-11; finding P3-RT-03-05.

## 2026-10-17 RT-FIX-P3-codec-state: the values of T9's caption of 2.12 (P3-RT-02-02)
Decision: T9's `EndPanel` (site/src/components/tools/t09/kostant.ts) gains two fields, `markedNumbers` and `markedReturnCounts`: the final number and the return count of each marked city, in the order of `marked`, read by `endPanel` at the position `toPositions` gives. `affineCaptionParts` pairs them with the marked labels instead of reading index `label - 1` of a list in label order. The data export of T9 names its fields one by one, so it does not change. What the specification left open: the shape of a tool's internal module (plan). Reason: E-7, "nothing else converts"; finding P3-RT-02-02.
