## 2026-10-25 RT-FIX-P5-toolchain: the prebuild holds the release report (P5-RT-12-01)
Decision: `site/src/lib/openItemsReport.mjs` gains `holdForReleaseBuild()`. In a release build (`RELEASE` set, the rule of `isReleaseBuild`) it rewrites a release report already on disk, JSON and Markdown, with `complete: false` and without its `linkCheck`, every other field (`generatedAt`, `buildId`, items and pages) unchanged; with no release report on disk, or outside a release build, it writes nothing. `scripts/katex-assets.mjs`, the first command of the root prebuild, calls it first, before it looks for KaTeX, so before anything of `RELEASE=1 npm run build` can fail. The Astro build's start hook then writes the report of the new build as before, its done hook marks it complete, and the postbuild holds and settles it (RT-FIX-P4-toolchain, unchanged). A release build that stops anywhere before the Astro build starts (in the prebuild, or while the site's configuration loads) therefore leaves the earlier report refused by `npm run report` ("comes from a release build that did not finish"), and, since its `linkCheck` is gone, a link check run by hand (`RELEASE=1 npm run postbuild`) does not mark it complete again. `scripts/report.mjs`, root `package.json` and the prebuild line are unchanged. What the specification left open: what `npm run report` does after a release build that failed before the Astro build started (SPEC 7.3 and 7.7 are silent; the decisions RT-FIX-P3-toolchain-b "a complete release report" and RT-FIX-P4-toolchain "the postbuild holds the release report" give the reason). Default used: none. Reason: a release build is prebuild, the Astro build and the postbuild, and a failed release build is never presented as the release report. Of the two fixes the finding proposes, this one (the first prebuild step marks the report) needs no change to root `package.json`, whose prebuild line `site/tests/unit/scripts.test.ts` asserts exactly, and no marker file for `report.mjs` to compare; a separate first prebuild command would have changed both. The report is marked rather than deleted, so that `npm run report` refuses it with the same message as after a failed postbuild and the owner can still read the earlier pages in `reports/open-items-report.md`, which then says "Incomplete". A preview build still never touches a release report (DECISIONS.md P0-A4).
