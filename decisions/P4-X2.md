- "every clock reading left in the parallel suite is listed, with its reason": the files of `site/tests/unit` and of the engine's parallel suite (every file under `packages/engine/test` except `bench/`) that mention a clock, with the exact number of mentions, equal a fixed list: site `content-components.test.ts` 2 (the fixture build's time, kept in its result and never asserted), `lab-thresholds.test.ts` 1 (the text of the canary page, compared as a string), `tools/T03.test.ts` 2 (printed, P2-A2 instruction 5.10), `tools/T15.test.ts` 2 (printed, decisions/P2-A4.md); engine `golden/p3b-complete-games.test.ts` 2 (the limit of the runner, next entry) and `golden/p4-wythoff.test.ts` 2 (printed). - "no assertion of the parallel suite rests on a clock reading, but the one limit of the runner that guards a hang": a search over the code of each file (comments, strings, regular expressions and the text of template literals blanked, the `${}` parts kept) finds every `expect(...)` or `assert...(...)` whose argument reads a clock or a name that holds a reading. A name holds one in the block where it is declared when it is assigned from such an expression (including `x[k] = ...`, `+=`, destructuring and a for-of over it), when such an expression is pushed or added into it, or, for a function, when it returns one; a property that receives one (`{ ms: ... }`, `build.ms = ...`, the shorthand `{ ms }`) holds it wherever it is read as `.ms`; keywords are never names; a list's length (`toHaveLength`) is not a duration. It finds nothing in `site/tests/unit`, and in the engine's parallel suite exactly `expect(elapsed).toBeLessThan(60000);` of `p3b-complete-games.test.ts`, whose comment right above must say "a limit of the runner that guards a hang, not a timing check".
- "the search for assertions on a clock finds the bound of every timing file": the search finds the bound of each of the four timing files (`T07.timing.test.ts`, `T10.timing.test.ts` through its helper `timeMedian` and a for-of over the medians, `orbit.bench.ts`, `weyl-dimension.bench.ts`), and gives the expected count on thirteen fragments written in the test (each binding it follows; a clock in a string, a comment or a template literal; a name of the same spelling in another test; a destructured reading beside `as const`).

Limits, stated: the search does not follow a reading through a function imported from another file, through an `if (...) throw`, or through a value returned as an object from a function and read as a whole; the exact list of clock readings above covers those, since each needs a reading in the scanned files.
