## 2026-10-10 P2-A1: the cache of verdicts and `classify` returning fresh copies
Decision: `guards.ts` holds `const verdicts = new WeakMap<object, ClassifyRecord[]>()` and `cachedClassify(board)`, which computes `classifyUncached(board)` (in `classify.ts`) once per board object; `requireFinite` and `requireAffine` read the cache; the public `classify` returns a deep copy of the cached records on every call, so a caller cannot change the cache. `requireGcm` and `requireConnected` do not use the cache (`boardKind` and `components` are cheap), and `cartanClass`, `identify`, `identifyAffine` check kind and connectedness directly because `classify` calls them (no recursion). The cache is keyed by the board object, never by name or matrix text. What the specification left open: the shape of the cache (E-11 names a `WeakMap` from board objects). Default used: the plan's (5.13, trap 17). Reason: boards are frozen, so the cache cannot go stale; E-5 (the cache changes no result) is checked by `guards.test.ts` (a board object built per call gives the same verdict).

## 2026-10-10 P2-A1: `requireFinite` on a disconnected board
Decision: `requireFinite` throws `NeedsTwoWayRoads` when any component has a one-way road, then `NotFiniteType` unless every component's class is `'finite'`; a board in several finite pieces passes, so `longestWord` keeps working on the black nodes of a Satake diagram (phase 6). `affineExtension` additionally calls `requireConnected` and throws `NeedsConnectedBoard` on several pieces, since the highest root of a disconnected board has no meaning. What the specification left open: 5.6 speaks of "a gcm board that is not of finite type" without saying what a disconnected finite board is. Default used: the plan's (5.13, 5.7). Reason: the instruction's text; tested in `guards.test.ts`.

## 2026-10-10 P2-A1: the order of checks inside each function
Decision: argument shape (`RangeError`), then kind (`NeedsTwoWayRoads`), then connectedness where required (`NeedsConnectedBoard`), then class (`NotFiniteType`, `NotAffine`). So `level(board, a)` with a vector of the wrong length throws `RangeError` before any guard, `cartanClass` of a one-way board in two pieces reports the roads, and `coroot` checks the vector's length before `requireFinite`. What the specification left open: the order. Default used: the plan's (5.13). Reason: a malformed argument is a programming error and should be reported first; the rest follows 5.6 row by row.

## 2026-10-10 P2-A1: the limit semantics of `relabellings`
Decision: `relabellings(b1, b2, limit = CAPS.relabellingsDefault)` stops the backtracking search once `limit` assignments have been found and returns what was found, sorted lexicographically; when the total is at most `limit` the result equals the oracle's list exactly, otherwise it holds the first `limit` found in the search order (the oracle's: the nodes of `b2` in breadth-first order from the least position of each component, candidates in increasing position), sorted. `limit` must be a positive integer (`RangeError` otherwise). `identifyAffine` searches with a limit of 1 (the oracle's `first_only`); `identify` with the default, which is safe because a finite board has at most six matchings onto its standard matrix. What the specification left open: E-6 gives the limit without saying what the truncated list holds. Default used: the plan's (5.5). Reason: `identify` needs the lexicographically smallest matching, which is in every truncated list of at least one element only when the search order starts there; it does, since the candidates are tried in increasing position, and the hand test pins the first five of the star with four arms.

## 2026-10-10 P2-A1: the `isRootPopulation` cap boundary
Decision: mutations are counted; when the total still exceeds 1 after `cap` mutations the answer is `null`; a descent that reaches the single Martian with its `cap`-th mutation returns `true`; a single Martian returns `true` at `cap` 0; `cap` must be a non-negative integer (`RangeError`). On the triangle `e_1 + k delta` takes exactly `2k` steps (checked against the oracle for `k` = 1 to 4), so `cap` `2k` gives `true` and `2k - 1` gives `null`. The descent picks the lowest position whose number is positive, as the oracle does. What the specification left open: whether the cap counts mutations or loop iterations. Default used: the plan's (5.11). Reason: 5.5 ("the test of `e_1 + k delta` on the triangle takes `2k` steps") and E-10 (a cap is reported, never thrown).

## 2026-10-10 P2-A1: `playFate`'s cap and the oracle's order of tests
Decision: `playFate(board, a, choose?, cap = CAPS.playMoves)` requires a positive integer `cap` (`RangeError` otherwise; a cap of 0 would make the first test of the loop meaningless) and keeps the oracle's order: end, move, loop test, cap test. So on `A2` from `(1, 1)` a cap of 3 reports `'cap'` with 3 moves at `(-1, -1)` and a cap of 4 reports `'ended'` with 3 moves, and a repeat on the cap-th move is `'looped'`. `firstVisit` is present only with `'looped'`. Positions are keyed by `arith.show` of the entries joined with commas, like the searches. `choose` receives the allowed positions and the current vector (the plan's `Choose<T>`) and a node outside the allowed list is a `RangeError`. What the specification left open: the cap range and the oracle's differing cap rule. Default used: the plan's (5.14, trap 6). Reason: port of `play_fate` lines 1309 to 1325; the difference from `P1-A1`'s `play` is the oracle's choice and is recorded in the file header.

## 2026-10-10 P2-A1: `RangeError` cases added
Decision: `RangeError` on a vector of the wrong length (`formValue`, `coroot`, `isRootPopulation`, `level`, `playFate`), a non-positive-integer cap (`playFate`), a negative or non-integer cap (`isRootPopulation`), a non-positive-integer limit (`relabellings`), a non-integer node count (`affineCandidates`), `n < 1` in `twistedAEven`, a non-boolean `short` in `affineExtension`, a non-square matrix in `nullVector`, a form matrix that is not square, not of the board's size, not integer or not symmetric (`formIsInvariant`), a coroot of a vector with form value zero or with a non-integral coordinate (`coroot`; the oracle asserts), a `choose` that returns a node not allowed (`playFate`). What the specification left open: invalid arguments the specification does not cover. Default used: `RangeError`, as `P0-A2` and `P1-A1` did. Reason: E-10 reserves the engine's own classes for the theory.

## 2026-10-10 P2-A1: `formIsInvariant` on a non-symmetric `M`
Decision: `M` must be a square, symmetric matrix of safe integers of the board's size; otherwise `RangeError`. `invariant` is the oracle's `form_is_invariant` (every `S_i^T M S_i = M`, computed over `bigint`); when it is false the witness is the oracle's `form_invariance_witness` in its loop order (node outside, population inside, the unit vectors then `e_a + e_b` with `a < b`), present only when found. What the specification left open: the two oracle functions answer different questions on a non-symmetric `M` (trap 9). Default used: the plan's (5.10). Reason: for a symmetric `M` the two agree; refusing other input keeps the record consistent.

## 2026-10-10 P2-A1: `nullVector`'s signature
Decision: `nullVector(M: readonly (readonly (number | bigint)[])[]): number[] | null`, a square matrix of integers; the port of `null_vector` (Gauss-Jordan over `Rational`, one free column, the free variable 1, denominators cleared by their lcm, divided by the gcd, negated when every entry is negative, returned only when every entry is positive). It is exported from `index.ts` (plan). What the specification left open: the signature (CONTRACTS.md 2.1 only places it in `affine.ts`). Default used: the plan's (5.8). Reason: `classify` and the tests call it on raw matrices (transposes included).

## 2026-10-10 P2-A1: `AffineExtension` labels and `name`; the board constructor in `affine.ts`
Decision: `affineExtension(board, short = false)` returns `{ board, marks, comarks }` with `board` a frozen `Board<bigint>` with `Big`, kind `'gcm'`, labels `0, 1, ..., n` for both the untwisted and the short extension, and `name` equal to `` `${board.name}~` `` only when `short` is false and the input board has a name; `undefined` otherwise (tools name boards through `classify`). The board is built by a private `bigBoardOf` in `affine.ts`, which freezes the object, the matrix, every row and the labels exactly as `board.ts`'s private `makeBoard` does. What the specification left open: the labels of a short extension (E-7 names only the untwisted case) and the name. Default used: the plan's (5.7). Reason: `makeBoard` is private to `board.ts` and `board.ts` may be edited only to extend `boardFromName`; duplicating five lines was preferable to widening that file's exports.

## 2026-10-10 P2-A1: `boardFromName` keeps the given name and throws `NotABoard` on unknown names
Decision: `boardFromName('B2~')` has `name: 'B2~'` and `boardFromName('C2~')` has `name: 'C2~'` (their matrices differ; both are identified as `C2~` by `identifyAffine` and `classify`); `pentagon`, `square` and the twisted names keep their spelling. Untwisted names match `^([A-G][1-9][0-9]*)~$` with the finite part validated by `cartan` (so `A0~` and `B1~` throw); twisted names match `^[A-E][1-9][0-9]*\^\((2|3)\)$` and are looked up in `affineCandidates(m)` for `m = 2..13` (the oracle's range; `D14^(2)` and `A25^(2)` throw). There is no node cap in the engine (`A20~` has 21 nodes). Every other string throws `NotABoard`. The phase-0 finite branch is the last statement of the function and is unchanged. What the specification left open: the name field of these boards and the range of the twisted lookup. Default used: the plan's (5.12, trap 18). Reason: the oracle raises `ValueError` on unknown names; E-10 maps that to `NotABoard`.

## 2026-10-10 P2-A1: the absent-not-undefined rule for record fields and the key order

What the specification left open: the representation of an optional field. Default used: the plan's (5.2). Reason: a deep-equality test against the golden record must pass.

## 2026-10-10 P2-A1: the `NotAffine` message text
Decision: `requireAffine` throws `P0-A2`'s `NotAffine(cls)` unchanged for a connected board, whose message already carries the class ("this function needs an affine board; this board is finite"); for a board in several components it sets the message to "this function needs an affine board; this board has N components, whose classes are finite, affine" (each class in order) and `data.class` to the first class that is `'finite'` or `'indefinite'`, or `'indefinite'` when every piece is affine (a board in several affine pieces is not affine, and the class's `data` type admits only these two values). What the specification left open: the wording (the instruction's "not an affine board: its class is finite" is marked plan wording). Default used: `P0-A2`'s text, which is the constructor's. Reason: `errors.ts` is not mine to change; the requirement of 5.6 is that the class is in the message, and `guards.test.ts` checks it on finite, indefinite and two-component boards.

## 2026-10-10 P2-A1: `AnyBoard` overloads on the phase-2 functions
Decision: every phase-2 function whose result does not depend on the arithmetic (`symmetrizer`, `gram`, `cartanClass`, `identify`, `identifyAffine`, `classify`, `smallestNonfiniteSubboard`, `spectralRadius`, `affineExtension`, `marks`, `comarks`, `formIsInvariant`, `isRootPopulation`, the four `require*` guards, the six guarded finite wrappers) has a second overload taking `AnyBoard`; `level`, `coroot`, `formValue` and `playFate` take `AnyBoard` with `Vec<number | bigint>` and return the union. The generic overload `<T>(board: Board<T>, ...)` comes first, as in `P1-A1`'s `transposeBoard` and `subBoard`. What the specification left open: the contract writes `board` as "`Board<number>` or `Board<bigint>`". Default used: the plan's pattern. Reason: a generic parameter does not accept the union that `boardFromName` and the site's `resolveBoard` return; without the overloads `tsc` rejects every tool call on an `AnyBoard`.

## 2026-10-10 P2-A1: `-0` never appears in an extended Cartan matrix
Decision: `extendMatrix` writes `0` rather than `-0` when a pairing is zero (`Ca[0][j+1] = a === 0 ? 0 : -a`). What the specification left open: nothing. Reason: `-0` passes `intEq` and `BigInt(-0)` is `0n`, but `toEqual` tells `-0` from `0`; an integer matrix should hold integers.
