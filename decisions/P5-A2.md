## 2026-10-24 P5-A2: the string viewer
Decision: the string viewer plays free firing (the numbers game, every node can be fired) on a board of its own at the representation's node i, from a start that is omega_i by default and can be typed (one field per node, whole numbers of at most 40 digits; a sentence in `data-out="start-message"` otherwise). The line through mu: for mu_i > 0 `stringThrough(board, mu, i)`; for mu_i < 0 the same line read from mu upward (`stringThrough` of `fire(mu, i)`, reversed; the oracle asserts mu_i >= 0); for mu_i = 0 mu alone. Each position is marked in or out of the orbit of mu by comparing the ends of legal play (F3). More than 12 positions: the first and last six and a count; more than 2000 positions, or entries beyond 2^53 (stringThrough takes numbers only), the two ends (mu and R_i mu, from `fire`) and the count, with a sentence. Firing node i turns the line end over end; the list replays a short flip (none under reduced motion, A-9) and `data-flips` counts them. What the specification left open: the viewer's bounds and how mu is chosen. Default used: the plan's (instruction 5.8).

## 2026-10-25 P5-A2: what a choice does while a pick builds (G5 rerun repair)
Decision: a choice made while a pick builds acts on what the pickers show, and the pickers always show the pick in progress or the state. Cause (the review of the first G5 repair, results 2e): that repair lists the picked board's labels in the node picker one step before the state loads (`picked`), but `pickNode` built `spec`, the board of the state shown. A node chosen in that frame was built on the board shown: a label that board lacks threw `label 3 is not on this board` inside a step, so the run of steps stopped and the tool stayed on `Building A2, node 3.` with `data-drawn="false"` and its panels waiting; a label it has built the wrong board (from E7 node 7, node 4 chosen from E6's list built E7 node 4). Checking every control found two more causes, also on 00e6a4c: the board picker's value followed the state only, and Svelte writes a select only when its value changes, so a load that ended a pick on the board shown left the board picker on the board picked (a node of the board shown chosen just after a board; a typed start in the frame before the panels are taken down); and `load()` left the line `Building E6.` when a link (popstate) or a typed start ended a pick.
What changed: (1) a node of the node picker is built on the board whose labels the picker lists (`pickerSpec`): the board shown until the picked board's labels are listed, that board after; a node chosen while the list is still the board shown's ends the pick of the other board (the reader's last choice wins, as with a link), and a label the list does not hold is refused (only a script can send one). (2) The pickers' values follow the pick from the reader's choice (`aim`: the board, and the node once known) until the state loads, then the state; `build()` writes them in the reader's task (`flushSync`), so that two choices within one task still move the selects; a pick of another board in the frame after `picked` lists the board shown's labels again until its own are known. (3) A load ends a pick in progress: its line goes and the pickers show the state loaded (a link by popstate, a typed start, the pick's own end). Unchanged, checked: the relation selects, the node k select, the board's nodes, the table's buttons and undo (the button and the key u) act on the state shown in the frame before the previous panels are taken down, and the pick then replaces that state; from the next frame the panels holding them are taken down, so none can be reached later in the pick. Not changed: a link whose state is the state shown is ignored by `readLink` as before and the pick goes on; the address bar then keeps the link until the reader acts (the history layer's rule after a popstate, RT-FIX P5-RT-04-01).
