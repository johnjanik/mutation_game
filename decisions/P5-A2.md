## 2026-10-24 P5-A2: the default relation
Decision: `[E_i, F_i] = H_i` (code `ef:i,i`) for a minuscule node, for a node whose matrices are not built, and for an orbit whose relation list is computed in the worker (more than 27 positions; the default never waits for the worker); for a node that is not minuscule with at most 27 positions, the first failing check in the engine's order, so that a failing relation shows on load (`ef:1,1` on node 2 of D4). The checker's three selects write one code (6.6 `q`, labels); picking a Serre relation with i = j moves the other node to the first other label (Serre relations need i != j). A check is always found by its fields (relation, i, j), never by its index in the list. What the specification left open: which relation shows first. Default used: the plan's (instruction 5.5).

## 2026-10-24 P5-A2: the verdict and the explanation (F11)
Decision: `minuscule` is `minusculeNodes(board)`, never read off the relation list. The explanation's number comes from legal play from omega_i (F11's third condition: the first number fired that is greater than 1, with its move), checked against `minusculeNodes` (an Error if they disagree). Wording: minuscule `Node i is minuscule: every number in the orbit of ωi is −1, 0 or 1, and all the relations hold.`; not minuscule `Node i is not minuscule: some number in the orbit is m (legal play from ωi fires a m at move t), so the steps E and F of the recipe miss some moves and the relations fail.` (when not built: `... would miss some moves.`). The phrase of SPEC 4 T12, "some number in the orbit is 2", stands verbatim (`someNumberPhrase`). A board without a minuscule node (E8, F4, G2) adds `This board has no minuscule node; its representations need more than the game.` (`data-out="no-minuscule"`). Above 2000 positions (`orbitSize`, before any enumeration) the tool shows the explanation alone with `The orbit of ωi has N positions, more than 2000, so the matrices are not built here.` (`data-out="limit"`), and `minusculeMatrices`, `signedMoves` and `chevalleySerre` are not called (unit test with a counting engine). What the specification left open: the wording. Default used: the plan's.

## 2026-10-24 P5-A2: the orbit in layers
Decision: layer 0 is omega_i alone, layer d the positions d firings away (orbitGraph with cap CAPS.repOrbit); each vertex shows its position (label order, true minus signs) and, after `#`, its basis index (the row and column of the matrices); each edge joins mu and R_k mu, coloured `edgeColour(k)` with the label k on a badge (text colour, ring in the edge's colour; 6.3, A-5, A-6). An edge whose upper end has mu_k of 2 or more is no entry of E_k or F_k: dashed (`data-step="false"`), and the legend says why. Up to 300 positions (CAPS.gardenDrawEverything, T2's bound) everything is drawn; above, the sizes of the layers are listed (`data-layer-count`) with a sentence. The drawing is one SVG string in two layers (edges, then vertices with role img and a title), inserted as markup (`orbitSvg`, a pure function) and drawn in two tasks; the orbit table of the table view holds the same data as text (capped at 300 rows with a sentence). What the specification left open: the layout and the bound. Default used: the plan's (borrowed bound).

## 2026-10-24 P5-A2: MatrixView
Decision: `site/src/components/math/MatrixView.svelte`, props `caption`, `rowHeaders`, `colHeaders`, `sparse` (a SparseMatrix, keys `spKey(row, column)`, row the image, column the source) or `dense`, `format` (`auto`: grid up to 27 by 27, list above, 5.6), `sparseDisplay` (zeros as a dot with `aria-label="0"`), `indexHeaders` (columns show their index, the position in a hidden span and the tooltip), `listMax` (rows of a list; T12 passes 300, with a sentence that Download data holds them all), `out` (the `data-out` name). Hooks: the root carries `data-out`, `data-format`, `data-rows`, `data-cols`; every cell of a grid and every value of a list carries 1-based `data-row`, `data-col` and `data-value` (exact digits, ASCII minus). A grid is a `<table>` with `<caption>` (`E1, 3 by 3`), a header row of `th scope="col"` and a `th scope="row"` per row (A-10); a list has the columns Row, Column, Value in row-major order, caption `F7: 12 nonzero entries of a 56 by 56 matrix`. The table is written as one string (`matrixTable`) with a `<colgroup>` and `table-layout: fixed`, and its scroll box (a tab stop with a name, A-11) has `content-visibility: auto` with the size `matrixBoxSize` estimates (measured: heights exact, widths within 5 percent): a table outside the viewport is not laid out until the reader comes near it. What the specification left open: the component's interface. Default used: the plan's (instruction 5.4). Reason: SPEC 7.6; the E7 lists and the E6 grids each took 15 to 60 ms of layout with the processor slowed four times.

## 2026-10-24 P5-A2: the relation in MathML
Decision: the relation checker writes its formula with `t12/RelationFormula.svelte` in MathML (`math`, `msub`, `msup`, `mrow`, `mo`, `mn`, `mi`), with C_ij and the exponent 1 - C_ij evaluated and labels as subscripts (`[E1, F2] = 0`, `ad(E1)^2 E2 = 0`), an `aria-label` read in words (`E 1 F 2 commutator equals 0`, `ad E 1 to the power 2 applied to E 2 equals 0`) and the spans fallback of `LinearForm.svelte`'s `RENDER` switch. Default used: the plan's (LinearForm has no commutator or power form, so a small component of T12's own).

## 2026-10-24 P5-A2: the string viewer
Decision: the string viewer plays free firing (the numbers game, every node can be fired) on a board of its own at the representation's node i, from a start that is omega_i by default and can be typed (one field per node, whole numbers of at most 40 digits; a sentence in `data-out="start-message"` otherwise). The line through mu: for mu_i > 0 `stringThrough(board, mu, i)`; for mu_i < 0 the same line read from mu upward (`stringThrough` of `fire(mu, i)`, reversed; the oracle asserts mu_i >= 0); for mu_i = 0 mu alone. Each position is marked in or out of the orbit of mu by comparing the ends of legal play (F3). More than 12 positions: the first and last six and a count; more than 2000 positions, or entries beyond 2^53 (stringThrough takes numbers only), the two ends (mu and R_i mu, from `fire`) and the count, with a sentence. Firing node i turns the line end over end; the list replays a short flip (none under reduced motion, A-9) and `data-flips` counts them. What the specification left open: the viewer's bounds and how mu is chosen. Default used: the plan's (instruction 5.8).

## 2026-10-24 P5-A2: panels, presets, link keys
Decision: five panels in this order, the preset's first panel moved to the top: orbit, matrices (with a node k picker of its own), relations, signed move (the move matrix of node k beside `E_k - F_k + P_k^0`), string. Presets `default`, `string-viewer` (A2 through (2, 0)), `relation-checker`, `signed-move`; the panel order and the matrix node are not part of the state nor of a link (6.6 has no key for them). Link keys read: `z g c s w k q`; the keys of other tools (`v m x t r j e y d`) are ignored; a `g` or `k` that changes the board or node takes that board's and node's defaults for every field the link does not name; `c=p` is refused (the viewer plays numbers); `c` without `s` keeps the start; a board T12 does not offer and a Serre relation with equal nodes are refused with the notice (the codec accepts the latter; request to P1-A2). Nothing is written to the address bar before the reader acts. What the specification left open: the panels and the link rules of a tool with two node fields. Default used: the plan's (instruction 5.10).

## 2026-10-24 P5-A2: where each call runs, and the relation list (the coordinator's ruling)
Decision: `chevalleySerre` over the whole list is computed on the main thread only for orbits of at most 27 positions (`RELATIONS_MAIN_MAX = CAPS.matrixGridDim`; the largest is E6 nodes 1 and 6) and in the worker above (`engineCall('chevalleySerre', ..., relationsHint(board))`, a hint without `expectedItems` that whereToRun sends to the worker). The configured state of an instance computes its list on the main thread whatever the size, at build time and on hydration, so that no default state needs the worker. `minusculeMatrices`, `signedMoves`, `orbitGraph` and `stringThrough` stay on the main thread up to 2000 items (E-9 rule 1, their hints carry `expectedItems` from `orbitSize`); `play` is a legal play on a finite-type board (rule 2); a link's move list above 2000 is replayed in the worker (`positionsOf`). A pick builds the representation one engine call per task (decide, enumerate, sign, and the relation list for a node that is not minuscule with at most 27 positions) and then draws the panels one piece per task after a frame; the worker's call is posted in a task of its own and its reply taken in another, its two sides drawn one per task. What the specification left open: E-9 names `minusculeMatrices` an enumeration but not `chevalleySerre`; SPEC 7.6 bounds a main-thread call at 50 ms on a phone. Default used: the coordinator's choice (move the full list to the worker above a measured size). Measurements (Node, warm medians, whole build of one node): A2 0.9 ms; E6 node 1 6.1 ms (chevalleySerre 4.6); E7 node 7 8.4 ms (minusculeMatrices 0.6, chevalleySerre 7.3); D4 node 2 1.9; E7 node 2 112; E7 node 6 133; E8 node 8 42; B8 node 5 442 (minusculeMatrices 22.7, chevalleySerre 405); C8 node 5 473. In Chromium the first chevalleySerre of E7 node 7 after a pick took 14 ms at full speed, about 56 ms with the processor slowed four times: over the budget, hence 27. Browser results with the processor slowed four times (`T12.spec.ts`, repeated in scratch runs): picking E7 (56 positions), E6 (27), D4, B3, C3, G2 and E8 gives no long task. Residual, reported: on the largest orbits built (B8, C8, D8 nodes of 1120 and 1792 positions) reading the worker's reply (368 records with 57120 entries for B8 node 5, deserialized by `lib/worker.ts`) is one task of 54 to 58 ms at full speed in some runs, and with the processor slowed four times `minusculeMatrices` on 1792 positions (about 25 to 33 ms at full speed) and that reply are tasks of 100 to 270 ms. Neither is `chevalleySerre` on the main thread; the requests ask for a verdicts-only or one-relation form of `chevalleySerre` (P5-A1) and for the E-9 sizing of `minusculeMatrices` (MERGE).

## 2026-10-24 P5-A2: data-out names and the selects
Decision: data-out names `caption notice noscript exportNotice moveCounter historyStrip historyCounter predictResult predictReveal dimension minuscule explanation no-minuscule limit orbit-graph matrix-e matrix-f matrix-h relation-formula relation-verdict relation-left relation-right all-relations move-matrix signed-move string-position string-length string-note start-message`; `data-out="minuscule"` reads `yes` or `no` with `data-minuscule="true|false"`; `relation-verdict` reads `equal` or `not equal` with `data-holds`. Each select carries its value as well as the selected option of the server markup: the browser suite found that an option's `selected` attribute no longer moves a select the reader has used, so a Serre relation moving j, or a link loaded afterwards, showed the old node. Node selects take numbers, as their options (Svelte compares the option's value without conversion).
