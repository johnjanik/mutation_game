## 2026-10-10 P2-A5: board changes and the play
Decision: a preset, an added or removed node, a change of roads (any edit whose Cartan matrix differs), an import and a link with another board reset `start` to the 6.6 default for the current coords on the new board and empty `moves` (4.0 Board pickers). Moving a node changes only `xy`, so the board and the play stay. This is stricter than the editor's `resetsPlay` for roads (false), because the matrix changes; the editor contract is unchanged. Edits have no undo of their own in the sandbox: Undo, Redo and Reset act on moves (4.0 History). A preset load calls `exampleLoaded` (pushState, 7.4); every other change goes through ToolFrame's throttled replaceState.

## 2026-10-10 P2-A5: E-2 for the sandbox's boards
Decision: every custom spec resolves to `Big` (`resolveBoard({ cartan: A3 })` and the default board both give `Big` on the integration branch; no deviation). A named finite board loaded by link (`g=A3`, the module links) is `SafeInt` by E-2; T1Game moves it to `Big` silently when a start entry is not a safe integer or a move overflows (SPEC 4 T1 "reloaded with Big arithmetic, with no message"), tested with a 30-digit start on A2. ## 2026-10-10 P2-A5: JSON import and export of boards
Decision: the format is the `board` value of 6.6 in object form, `{"cartan": [[2, -3], [-3, 2]], "xy": [[0, 0], [1, 0]]}`, `xy` optional. Import also accepts a bare name (`"A3"`), a state object (its `board`) and a whole data export (its `state.board`); starts and moves inside are ignored. Refused, with the board left as it was: text that is not JSON, an unknown name, a `cartan` that is not a square list of whole numbers, an empty matrix, more than 12 nodes, a not-a-board matrix (boardKind, the oracle's board_kind), an `xy` whose length is not the number of nodes or whose points are not pairs of numbers. Coordinates that break 6.1 are kept and spoil only the layout. Wording (plan): "The board could not be read: <reason>. The board was left as it was." and "Board imported: N nodes. The play starts again from the default start." in `data-out="importStatus"` (role status, ordinary text, no announcement of my own). Export: "Export board" downloads `board.json` and the same text is shown in `data-out="boardJson"` (a `<pre>`, so no control is left enabled before hydration). A named board is exported as its matrix with whole grid points (the editor's `gridOf`), so it reads back as a custom board with labels 1..n (E-7). Controls: a labelled textarea, "Import board", a file input, "Export board", all disabled until hydration.

## 2026-10-10 P2-A5: the verdict, the T4 items left out, D19
Decision: the verdict is T4's model, `t04/verdict.ts` `buildVerdict` on one board object per board load (one classify call, cached), shown by T16Verdict.svelte: "Verdict: " then, per component, `finite`, `affine`, `indefinite` or "has a one-way road: the theory does not apply", the name after it, and "nodes 1, 2: " before it when the board has several components (`data-out="verdict"`, names in `data-out="verdictName"` with `data-name`). Finite: `data-out="verdictBourbaki"`, "Your nodes and the Bourbaki labels: node 1 is Bourbaki 1, node 3 is Bourbaki 2, ...", with `data-order` the reader's labels in Bourbaki order. Affine: `data-out="verdictMarks"` and `"verdictComarks"`, "Marks (the frozen population): node 0: 1, ..." with `data-nodes` and `data-values`. T4's "Also shown" items (balance and weights, spectral radius, a smallest non-finite sub-board), the root counter and the hunter are not shown (SPEC T16 "No verdicts beyond those of T4"; the roster asks only for the verdict). D19: a component that classify names B2 reads B2 = C2, as MathML (A-12), when the board was recognised from its shape (any custom matrix); by name (`g=B2`, `g=C2`, a preset) it reads the name chosen. `data-tex` on the verdict element holds the TeX of the names shown (`B_2=C_2`, `A_{3}`, `\tilde{A}_{2}`). Names are plain markup: the letter, `<sub>` for the rank, then `~` or `<sup>(2)</sup>`, so the text reads `A2~` as in 6.6.
