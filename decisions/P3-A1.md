## 2026-10-10 P3-A1: the functions are written once, generically, with AnyBoard overloads
Decision: every function of `weyl.ts` is written once over `Arith<T>` (E-2), with the overload pattern of P2-A1 (`<T>(board: Board<T>, ...)` first, then `(board: AnyBoard, ...)`) so that tools can pass the union type. Products that can exceed 2^53 (`weylDimension`, `countCompleteGames`) are `bigint` through `arith.toBig`; group orders and orbit sizes are numbers multiplied in `SafeInt`, so an impossible overflow throws `EngineOverflow` instead of returning a wrong number. What the specification left open: E-2 allows writing a core function twice [D]. Default used: once. Reason: generics proved no harder than in phases 1 and 2; the guards test exercises the `Big` path on a renumbered A3.

## 2026-10-10 P3-A1: the wave's bound and what it returns there
Decision: `wavePlay` stops after the round that makes `rounds` exceed 10000 (the module constant `WAVE_ROUNDS_CAP`, the oracle's `cap=10_000` tested after each round, so the oracle raises after round 10001) and returns the `WaveResult` reached there: `rounds` 10001, `legal` as accumulated, the position and word so far. From a start that is not dominant the wave can run for ever on a finite board (A3 from `(2, -4, -3)` with either colour first, checked against the oracle). What the specification left open: neither SPEC.md nor CONTRACTS.md says what to return at the bound, and `WaveResult` has no `status` field; E-10 forbids throwing at a cap. Default used: the plan's (P3-A1 instruction 5.4). Reason: a wave that ends within 10001 rounds behaves exactly as the oracle's; the missing `status` field is raised under `openQuestions` as a contract amendment, and no field was added to `WaveResult` on my own.

## 2026-10-10 P3-A1: weylDimension throws RangeError on a lambda that is not dominant or of the wrong length
Decision: `lambda` must have one entry per node, each a non-negative safe integer; anything else is a `RangeError` before the guards run. The replay from `lambda + rho` uses `fire` in the board's own arithmetic (never re-derived) and multiplies the numbers met into a `bigint`; a remainder from `M / D`, impossible for a dominant `lambda`, throws an `Error` naming the board rather than returning a rounded value. What the specification left open: the behaviour on bad input (the oracle asserts). Default used: `RangeError`, the choice of `toPositions` and of P1-A1 and P2-A1 for malformed arguments. Reason: 4 T5 says the calculator takes a dominant lambda; raised under `openQuestions`.

## 2026-10-10 P3-A1: countCompleteGames tests |W| > cap before building a layer
Decision: `countCompleteGames(board, cap = CAPS.countGamesGroup)` returns `null` exactly when `weylOrder(board) > cap`, decided from the game from rho before the dynamic programme starts, so no layer is built for a group that is too large; a cap equal to |W| still returns the count (D6 at 23040). `cap` must be a non-negative integer (`RangeError`). What the specification left open: the oracle's limit is 70000 positions found; SPEC.md 5.5 and 5.6 offer the count for |W| <= 60000. Default used: the plan's reading (instruction 5.8). Reason: the two rules give the same presence on all 32 types (the smallest order above 60000 is D7's 322560), and the engine accepts any cap the caller passes (5.5).

## 2026-10-10 P3-A1: the order of bipartition's classes
Decision: `bipartition` returns `[class0, class1]`, each a fresh array of positions in increasing order; the least position of each component (the oracle's walk starts there) has colour 0. A1 gives `[[0], []]`; `square` gives `[[0, 2], [1, 3]]`; an odd cycle anywhere (A2~, pentagon, a triangle beside an A2) gives `null`. No guard: it works on one-way boards too (the one-way road gives `[[0], [1]]`). The golden mapping is `colour[i] = class0.includes(i) ? 0 : 1`. What the specification left open: the oracle returns one colour per node; the contract type `[number[], number[]] | null` does not say which class comes first. Default used: the plan's reading (instruction 5.3). Reason: the colour-per-node form is recovered in one line, and T1's colour-class panel and T5's wave need the classes as lists.

## 2026-10-10 P3-A1: the unguarded helpers for |W| and |W_J|
Decision: `weyl.ts` has two private helpers: `groupOrder(board)` (the game from rho, the exponents of the tally, the product in `SafeInt`; 1 on no nodes; `NotFiniteType` if the play reaches its cap, which cannot happen after the guard) and `parabolicOrder(board, J)` (1 for the empty set, otherwise the product over the connected components of `subBoard(board, J)` of `groupOrder` of each component's induced board). `orbitSize` uses both after one `play` of the given position; the public `weylOrder` is `groupOrder` behind `requireGcm` and `requireFinite`. What the specification left open: the oracle calls `weyl_order(sub_matrix(C, J))`, which on a disconnected sub-matrix equals this product, and an empty J cannot be a board. Default used: the plan's (instruction 5.6, trap 11). Reason: an empty sub-board never meets `requireFinite`, no sub-board pays for a `classify`, and E-9 item 1 wants `orbitSize` cheap (one play of at most N moves plus small plays).

## 2026-10-10 P3-A1: separatingRoots uses the internal corootOf
Decision: `separatingRoots` pairs `a` with `corootOf(board, beta)` of `form.ts` (P2-A1's internal, unguarded coroot as plain integers) for each `beta` of `positiveRoots(board)` with its default cap, computing the pairing in `bigint`, and returns the roots themselves (fresh arrays from the search) in the order of `positiveRoots`. What the specification left open: whether to call the guarded `coroot` once per root. Default used: the internal helper after this function's own guard. Reason: one guard per call instead of N; the result is identical (the B2 hand cases and F5 on every type with |W| <= 2000 are tested).

## 2026-10-10 P3-A1: legalLayers with a cap of 0, and the RangeError cases
Decision: `legalLayers(board, start?, cap = CAPS.legalLayersDefault)` returns `null` for `cap` 0 (the start itself exceeds it; `orbitGraph` would refuse a cap below the number of seeds) and otherwise `null` exactly when `orbitGraph(..., legalOnly)` reports `truncated`. `RangeError` on: a vector of the wrong length (`wavePlay`, `orbitSize`, `legalLayers`, `separatingRoots`, `weylDimension`), a `firstColour` other than 0 or 1, a cap that is not a non-negative integer, an `n` that is not a non-negative integer in `exponentsFromFired`. The order of checks is P2-A1's: argument shape, then `requireGcm`, then `requireFinite`. What the specification left open: invalid arguments. Default used: `RangeError`, as the earlier phases did. Reason: E-10 reserves the engine's classes for the theory; a cap is never thrown.
