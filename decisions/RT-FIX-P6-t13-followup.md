# Decisions of RT-FIX-P6-t13-followup (phase 6 red-team round, the two MERGE follow-ups of the t13 cluster)

## 2026-10-26 RT-FIX-P6-t13-followup: the typeset names of one board, fetched during hydration of a link state (P6-MERGE-T13-01)
Decision: `scripts/names.mjs` also writes the real forms one file per board, `site/src/generated/satake-names/<board>.json` (32 files, `{ katex, realForms }`, each entry the same as in `satake-names.json`; the boards are the `dynkin_type` of the golden key `satake`, read only, in first-appearance order), through a new export `writeSatakeNamesByBoard(dir)` that the command-line run calls after `writeGenerated`. `writeGenerated` still writes its two files (P6-A2's test of the generated directory is unchanged), and the entry of a real form is now built by one helper for both writers (the bytes of `satake-names.json` are unchanged). In the browser `t13/names.ts` imports those files lazily with `import.meta.glob`, one chunk per board, and `loadNames(board)` fetches only the board shown; the server render still reads every name in-process from `satake-names.json`, and the browser no longer imports `t13/satakeNames.ts`. `readLink` (hydration and the back button) now loads the names of the board after `setConfig` when the link changes the pair, and the reader's actions (paint, tau, picker, example, catalogue entry, panel, back button) load the names of the board they show. The default state fetches no names: its server markup is typeset and hydration keeps it. This replaces two sentences: in decisions/P6-A3.md "the names of real forms, typeset at build time and loaded lazily", "in the browser only after the reader's first change of decoration or of panel"; and decisions/RT-FIX-P6-t13.md "the typeset names load on the reader's own actions only": a link state now fetches the names of its own board while the island hydrates, so that P6-A3's "the first view is always the typeset one" holds for link states too (SPEC 7.5 A-12). Sizes, gzip level 9 as npm run size measures: each board's chunk weighs 487 B (A1, B2) to 833 B (D8); the per-board loaders add 628 B to T13's chunk (20306 to 20934 B), and the whole names chunk (5230 B) is no longer in the client build. `npm run size -- --port 7391`: `/tools/satake/`, `/embed/satake/` and `/modules/m9-real-forms/` 87.3 kB on the base d8102c0 and 87.9 kB on this branch (limits 90, 90, 120); 90 routes, 0 over budget. The RT-07 link sweep (redteam/redteam-RT-07-p6-link-sweep.mjs of the lens branch, a scratch copy) over the 167 links of the built site to the Studio: the default route 87943 B; every link 88430 B (A1) to 88776 B (D8 split), its one extra script being its board's chunk (the E7 and E8 links also fetch the uncounted worker, as at base); 0 over 90000 B. What the specification left open: how the typeset names reach the browser (SPEC 7.3 typesets them at build time; 7.6 counts every script before the first interaction). Reason: SPEC 7.5 A-12, 7.6, 7.3; decisions/P6-A3.md.

## 2026-10-26 RT-FIX-P6-t13-followup: the paint buttons of the decoration are controls (P6-MERGE-T13-02)
Decision: the paint buttons of the decoration carry `data-control="paint"`, the node's label in `data-paint`, the colour in `data-colour` ("black" or "white") and `data-can-act`, and no `data-node`, `data-board` or `data-value`. Their keyboard model (one group, one tab stop, roving tabindex, the arrows, Home and End of A-1, Enter and Space), their focus, their names ("Node 2, black") and the announcements ("Node 1 painted black. ...") are unchanged. The reading of SPEC 4.0 Test hooks [D] this rests on: its node buttons are those of a game's board, since `data-board` names the board of a game ("populations or numbers, which matters in the linked view") and `data-value` is "the value shown"; the decoration copy (6.3 last bullet) shows no value and plays neither game, and a paint changes the pair (X, τ), the tool's configuration, as the τ radio buttons do (A-3's templates name the state of a game, and the paint buttons' names already depart from them, P6-A3). The option of a third `data-board` value ("decoration") was not taken: it would change the two values 4.0 names. This replaces, for the paint buttons, the first entry of decisions/RT-FIX-P6-t13.md ("data-board="numbers" and data-value "1" on a black (filled) node and "0" on a white (hollow) one"); its `data-board="populations"` on the restricted board, its `data-colour` and its `data-table-population` stand. Tests: the new regression test (T13.spec.ts, regressions); the selectors of T13.spec.ts, T13-keyboard.spec.ts and M9.spec.ts read `data-paint` and `data-control="paint"` where they read the decoration's `data-node`, with the same asserted values; T13.spec.ts "every node button carries data-node, data-board, data-value and data-can-act" now counts 6 + 2 node buttons (the game board and the restricted board, was 6 + 6 + 2) and checks the six paint controls separately (their hooks, data-can-act, and the absence of the three node hooks), and its 320-pixel check of the hit areas still covers the paint buttons. nojs.spec.ts compares the server and hydrated `[data-node]` hooks: the decoration leaves that list, and its state stays compared through the outputs `black-nodes`, `tau` and `arrows`. What a Challenge would read (Challenge.svelte readTool over every `[data-node]` of the tool, challengeCheck.ts valuesOf by `data-board`, sorted by label): on every T13 instance the `numbers` group is now empty, so a `reach`, `distinct` or `mixed-signs` check on `numbers` is never met; `populations` holds the game board alone while the Restricted board panel is closed, and while it is open (M9 b7 and b12 open on it by preset) the game board and the restricted board together, interleaved by label (on e6(−26): cities 1 to 6 of E6 and nodes 1 and 2 of A2, eight values, the two with label 1 first, then the two with label 2). There a `reach` with the six populations of E6 fails on the length, `distinct` counts vectors of eight values, and `mixed-signs` can be met by a negative shadow coordinate. No such Challenge exists today (M9's three Challenges on T13, b10 to b12, are of kind `out`); a group hook that Challenge could read (the lens's proposal in P6-RT-10-05) would be a change under site/src/components/lesson/ and stays open. What the specification left open: whether the decoration's buttons are node buttons in the sense of 4.0 Test hooks. Reason: SPEC 4.0 Test hooks, 6.3 last bullet, 7.5 A-1 and A-3; the MERGE follow-up as raised by rtconfirm-p6-t13.
