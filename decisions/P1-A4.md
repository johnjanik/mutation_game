## 2026-10-10 P1-A4: how `released` is decided (lib/pages/released.ts)
Decision: one module, pure functions over plain lists plus build-time wrappers. A module or page is released when its file exists and its frontmatter says `released: true` (read from the raw MDX with `import.meta.glob(..., { query: '?raw', eager: true })` and `parseFrontmatter` of `@astrojs/markdown-remark`, so it is synchronous and usable in MDX). A tool is released when `site/src/tools/registry/T{nn}.ts` exists and its raw text does not say `released: false`. An Atlas page is released when `src/pages/atlas/[board].astro` exists. `sources` always; `open-items` only when `isReleaseBuild()` is false. `hrefFor(target)` and `linkIfReleased(target)` join `import.meta.env.BASE_URL` and the route with exactly one slash; targets: `{kind:'module', slug}` or `{kind:'module', number}`, `{kind:'page', slug}`, `{kind:'tool', id, query?}`, `{kind:'atlas', board}`, `{kind:'static', name: 'index'|'modules'|'sources'|'open-items'}`. `nextModule(n)` is module n + 1 only, never a later one.
MDX pattern for released-aware prose links (P1-A8 asked for it):
```
import { linkIfReleased } from '@lib/pages/released';
export const m = (n) => linkIfReleased({ kind: 'module', number: n });
{m(1) ? <a href={m(1)}>the mutation game</a> : <>the mutation game</>}
```
about.mdx uses exactly this for the seven statements, mapped (plan, [D]) 1 to M7, 2 to M1, 3 to M4, 4 to M5, 5 to M3, 6 to M8, 7 to M9.
