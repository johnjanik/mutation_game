## 2026-10-26 RT-FIX-P6-worker-wire: a named board travels by its name only when it is the standard board of it (P6-RT-03-02 P6-RT-06-02)
Decision: `specOf` (site/src/lib/workerWire.ts) gives a board's name only when the board is the standard board of that name position by position (its matrix and its labels equal those of `boardFromName(name)`); every other board, named or not, travels as `{ cartan }` in its own position order. The check is cached per name in the module (a twisted name takes up to 18 ms in `boardFromName`; boards are immutable, so the cache changes no result). A name `boardFromName` refuses also travels by the matrix. What the specification left open: CONTRACTS 4 sends "Board as its BoardSpec (rebuilt with resolveBoard)" and P1-A2 recorded "its name, or `{ cartan }`", but neither says which BoardSpec belongs to a named board that is not the standard board of its name; SPEC 6.6 makes a name denote the standard board, so the name is not that board's BoardSpec. Reason: the matrix in position order is what the other fields of a RestrictedBoard are written against (orbits, cartan, simpleRestrictedRoots2, compositeWords, and restrictedCoordinates' rule that a composite move at orbit k acts as mutate(rb.board, c, k)); a board rebuilt from its name had its positions permuted against all of them. 7 of the 135 restricted boards of the catalogue travel by the matrix now: su(2,2), sp(4,R), sp(2,2), so*(8), e6(2), e6(-14), e8(-24). The same rule holds for arguments sent to the worker (a folded board of T11 named after its type, MERGE phase 4).
What is lost, because BoardSpec carries no labels: such a board comes back with labels 1..n in position order, no name, and Big arithmetic (resolveBoard gives every unnamed board Big, E-2). For e8(-24) the main thread has F4 with labels 4, 3, 2, 1 in SafeInt; the worker path now gives the same matrix [[2,-1,0,0],[-1,2,-2,0],[0,-1,2,-1],[0,0,-1,2]] with labels 1, 2, 3, 4, no name, entries as bigint. No reader reaches it: T13 never reads rb.board (t13/model.ts) and makes no call for a pair without a white node.
Needs a decision of the owner (the reproducers of RT-03 and RT-06 stay red on these three fields): (a) carry a board's labels and name on the wire with its matrix, for example `{ "$board": { cartan }, "labels": [...], "name": "F4" }`, rebuilt with resolveBoard and then given its labels and name, with SafeInt when the name is a finite type; this changes CONTRACTS 4 ("Board as its BoardSpec"), and it also repairs P1-A2's noted loss of a sub-board's labels; (b) the engine builds a named restricted board (and a folded board) in the Bourbaki order of its name, or names it only when its positions are already in that order; this changes the engine's output and the plan reading of E-7 that P4-A1 and P6-A1 recorded, and the order of RestrictedBoard.board against its other fields; (c) keep the rule above and record in CONTRACTS 4 that a board that is not the standard board of its name crosses the wire as its matrix, without its labels and name. Recommendation: (a), since E-7 makes the labels part of a board and the same loss already reaches sub-boards and folded boards.

## 2026-10-26 RT-FIX-P6-worker-wire: a reply the main side cannot rebuild rejects the call; the empty board (P6-RT-03-02)
Decision: worker.ts's message handler rejects the call with the error that `deserialize` or `wireToError` throws (its own class, for instance NotABoard from resolveBoard) instead of letting it escape the handler with the promise pending. The restricted board of a compact form is the empty board (n 0, MERGE ruling (4) on P6-A1); its BoardSpec `{ cartan: [] }` is refused by resolveBoard (fromAdjacency: "an adjacency matrix needs at least one node"), so restrictedBoard of e7(-133) or e8(-248) routed to the worker now rejects with NotABoard, while the main thread answers the empty board. What the specification left open: CONTRACTS 4 has no rule for a board that resolveBoard refuses inside a result. Reason: CONTRACTS 4 ("errors re-thrown on the main side as the same class") and worker.ts's header ("a worker failure rejects the promise"); no text permits a promise that never settles.
Needs a decision of the owner (the RT-03 reproducer expects the call to resolve with the empty board): (a) a wire rule for the empty board, `{ "$board": { "cartan": [] } }` rebuilt as an empty board without resolveBoard; this changes CONTRACTS 4, and the engine exports no constructor of an empty board (one would be a CONTRACTS 2 change; building the object in the site puts a board outside the engine); (b) keep the rejection and record in CONTRACTS 4 that a board of 0 nodes does not cross the wire; T13 makes no call for a pair without a white node (P6-A3, `noWhiteNode`); (c) let resolveBoard accept a matrix of 0 nodes: not recommended, since a link with an empty board would then pass the validation of SPEC 6.6. Recommendation: (b) now, or (a) together with option (a) of the entry above if the owner changes the wire format.
