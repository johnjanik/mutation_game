## 2026-10-25 P6-A4: the tool root of an Atlas page is its opening figure (plan reading)
Decision: the element with `data-tool="atlas"`, `data-instance=""` and `data-moves=""` (4.0; plan: an empty list) is the opening figure of the page: the drawing of the board (an SVG with role img and a text alternative naming every road with its counts each way, A-10), the caption (`data-out="caption"`, the page's opening sentence stating what the sheet shows) and the noscript line. The items follow it; their `data-out` elements (with `data-exact`) lie outside the root. What the specification left open: which element is the root of a static sheet. Reason: `nojs.spec.ts` checks every `[data-tool]` element of every route for a default figure with a text alternative, a caption, a noscript line, and no enabled control before hydration; the convention switch is a radio group that works before and without JavaScript, so it must not sit inside the root, and the drawing gives the root its figure. No element of an Atlas page carries `data-node`, `data-board` or `data-can-act`; the only `data-value` hooks are MatrixView's own, on its matrix cells.

## 2026-10-25 P6-A4: the downloads (plan formats)
Decision: generated at build time and offered as `<a download="atlas-<T>.<ext>" href="data:<type>;charset=utf-8;base64,...">` (base64 keeps the UTF-8 bytes exactly and the HTML smaller than percent-encoding the JSON); no endpoint file. JSON: `exportJSON(defaultState('atlas', T), atlasDerived(sheet))`, the derived values keyed with the golden field names where one exists (`cartan`, `cartan_transposed`, `adjacency`, `symmetrizer`, `n_roots`, `n_positive_roots`, `positive_roots`, `highest_root`, ..., `n_reduced_words_w0` (null above the cap), `coxeter_plane_rings` (null on A1), `affine` {name, constructor_name, labels, marks, comarks}, `real_forms` [{cartan_label, real_form, black_nodes, tau, restricted_type_display}]). CSV: UTF-8, header `item,label,value`, one row per scalar (empty label: `coxeter_number,,6`), one row per entry of a vector indexed by nodes (label = node label, 0 first on the affine board), one row per matrix row (label = the row's node, value the entries joined by commas, quoted: `cartan,3,"0,-2,2"`), one row per entry of a list (label = 1-based index: `positive_root,5,"0,1,2"`, `exponent`, `minuscule_node` or `minuscule_node,,none`, `coxeter_plane_ring,1,"1.154701,12"`), the count above the cap as `complete_games,,not offered for a group of more than 60000 elements`, and five rows per real form (`real_form`, `real_form_cartan_label`, `real_form_black_nodes`, `real_form_tau`, `real_form_restricted_type`); a field with a comma or a quote is quoted with quotes doubled; integers in full digits; a final line break. LaTeX: `latexFile('dynkin', body, <page address>)` of P6-A5, the body being the line `exportLaTeX('dynkin', { type: T, black: [], tau: identity })` returns (for B3 `\dynkin B{ooo}`), then for each real form in catalogue order its `exportLaTeX('dynkin', { type: T, black, tau })` line followed by three spaces and `% <Cartan label>, <plain-text name>`, as in the examples of 6.7.

## 2026-10-25 P6-A4: plan readings of 4.0 and 7.5 for a static sheet

(10) A-3, A-4, A-7 for nodes, A-8 and A-9 have no subject on a page with no node buttons, no moves and no motion.
