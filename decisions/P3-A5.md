WebKit (playwright-core lists 27.2, revision 2370) and Firefox (157.0, revision 1555) are not installed in this cloud container and cannot be installed here, so their two tests failed at `launch()` with Playwright's "please run npx playwright install" message: not run, not skipped. The owner runs, on the Mac: `npx playwright install webkit firefox` then `npm run build` and `npx playwright test site/tests/e2e/mathml.spec.ts`. If either engine fails there, set `RENDER` in `site/src/components/math/LinearForm.svelte` to `'spans'` (the span path is implemented and unit-tested; the spec then reads the `<sub>` of each term) and record the engine and its version here. What the specification left open: [U] in 7.3 ("MathML Core in Chromium since version 109, from memory; check in phase 3"). Default used: the instruction's (5.9). Reason: Appendix E item 17, the builder settles a tool's [U] when the tool is first used; the item stays partly open (two engines) until the owner's run.

## 2026-10-10 P3-A5: LinearForm rendering and spoken rules
Decision: terms in increasing label order; zero terms omitted; a coefficient 1 is not written, -1 is written as a minus sign; other coefficients as `<mn>`; between terms `<mo>+</mo>` or `<mo>−</mo>` (U+2212), a leading negative term with `<mo>−</mo>`; each variable `<msub><mi>x</mi><mn>label</mn></msub>`; the zero form `<mn>0</mn>`; no invisible times. The `aria-label` speaks coefficients through `speak` of a11y.ts, variables as "x 1", operators "plus" and "minus": "2 x 1 plus x 2", "minus x 1 minus 2 x 3", "0". Props: `coeffs` (by position, number or bigint), `labels` (board.labels, the subscripts, E-7), `letter` (default x), `render` (default the module constant `RENDER`, so that tests can render both paths). The span fallback: the same terms in `<span>` with `<i>` and `<sub>`, `role="math"` and the same `aria-label`. What the specification left open: the plan's rules (5.5). Reason: they reproduce the forms of A.1 and M5 beat 5. Svelte 5.57.2 creates `<math>` and its children in the MathML namespace on the client (checked by mathml.spec.ts after a move); no `<svelte:options namespace>` was needed.

## 2026-10-10 P3-A5: default board, caption and state
Decision: default board A3 (M5 beat 5), start all ones, no moves; the only preset is `default`. Caption: "Play the numbers game on the left. The right board makes the same moves with letters in place of numbers, so every number fired is a linear form. Over a complete game each positive root of the reversed board is fired exactly once." The state is `{ schema: 1, tool: 'symbolic', board, coords: 'numbers', start, moves }`; view and mode are fixed by the tool and never written into links (`?z=1&g=B2&c=n&s=1,1&w=1.2.1.2`). What the specification left open: the plan's (5.2). Reason: 4.0 "default is the state described in this section"; CONTRACTS 6.

## 2026-10-10 P3-A5: links T7 refuses beyond 6.6
Decision: besides the codec's rules (decodeState with the instance prefix), a link loads the default with the codec's notice when: `c=p` (coords other than numbers); a start with an entry that is not a positive integer (T7 needs "a start with all numbers positive"; F6 fills the table only then); a move that legal play forbids at its point of the play (6.6 rule 6 for the mode in force: the tool's mode is legal, but since links carry no `m`, the codec cannot see it, so T7 replays with `firstForbiddenMove` and mode legal itself). The same rules make an authoring error (a page passing such a start or moves) fail the build with a message naming the instance, as T1 does. What the specification left open: plan reading of 5.2. Reason: the left board must always be a legal play from an all-positive start.

## 2026-10-10 P3-A5: the left board is T1's model; Big with no message
Decision: the left board is `T1Game` of `t01/model.ts` (numbers view, legal mode, numbers coordinates), imported and not changed: one engine call per move, step and play to the end lowest position first (E-5), and the silent switch to Big when a start or a play leaves the safe range (SPEC 4 T1), which also gives the long-number display of `Node.svelte` and `t01/longNumber.ts` (shortened on the node, exact in the tooltip, the table view and the export). The announcements are T1's (`t01/announce.ts`) in the numbers view. Every board T7 offers is finite with at most 120 moves, so play to the end runs on the main thread (E-9); the full recomputation after a move (symbolicPlay, n unit-start applyWord calls, positiveRoots of the transposed board) took a median of 3.2 ms on E8 along its 120-move longest word in Vitest here, against the plan's 25 ms bound. Reason: the instruction's "reuse T1's mechanism; do not write a second one".

## 2026-10-10 P3-A5: the right board is a T07 sub-component, with its own hooks
Decision: `Board.svelte` draws a numeral on each node and validates its value as a decimal (sign.ts throws on "2,1"), so the right board is `T07SymbolicBoard.svelte` (README 6: T07*.svelte), built from the board family's parts (draw/layouts.ts, the size rule of 6.1 in Board's CSS, Roads.svelte, keyboard.ts's arrow model). Each disc shows the sign of its entry by fill and a + or − glyph (6.3, A-5); the forms themselves are listed under the drawing, one line per node with LinearForm, so that a long E8 form never covers a neighbour. The node buttons are one tab stop with arrows, Home and End (A-1), `aria-disabled="true"`, `data-can-act="false"`; activating one changes nothing. Hooks: the left board is wrapped in `data-out="numbersBoard"`, the right in `data-out="symbolicBoard"`; the right board's buttons carry `data-board="numbers"` and `data-value` equal to the coefficients in label order joined by commas (for example `2,1`), plus `data-sign` (positive, negative, zero or mixed); each line of the list carries `data-entry` and `data-form`. Tests scope every node query by the wrapper. A request to P0-A5 through MERGE: a `content` snippet prop on Board.svelte would let a later tool draw non-numeric entries without a sub-component. What the specification left open: 4.0 names only `populations` and `numbers` for `data-board` and decimal or `p/q` for `data-value`; raised under openQuestions.

## 2026-10-10 P3-A5: the stacking width and the layout boxes
Decision: the two boards stand side by side when the tool's figure (its inline-size container) is at least 600 pixels wide and are stacked, left board first, below; each board's panel is its own size container, so the size rule of 6.1 measures the panel. The fired list keeps a fixed height of 8em and scrolls inside its box; the side table renders all N rows at build time and scrolls inside a box of at most 24em; the figure's grid column is `minmax(0, 1fr)` so that a long form never widens the page at 320 pixels (A-11). The three scroll boxes (the fired list, the side table and the list of current forms) are keyboard stops (`tabindex="0"`, the first two as named regions), so that their content can be scrolled without a pointer; axe's `scrollable-region-focusable` flagged the side table before this. Reason: 4.0 Small screens and 7.6 (no layout shift on hydration; measured equal boxes and CLS within 0.1 in T07.spec.ts).

## 2026-10-10 P3-A5: the side table and the fired list
Decision: the table's caption is "Positive roots of the reversed board" (the reversed board is not named, which avoids D19 questions); one row per root of `positiveRoots(transposeBoard(board))` in the engine's order, shown as a population in label order; an unused row reads "not yet fired"; a used row shows "move k", the form (LinearForm) and the number fired on the left at that move, read from the left board's play. Hooks: `data-out="rootTable"`; each row `data-out="rootRow"` with `data-root`, `data-used`, and `data-move` when used; the list `data-out="firedForms"` with items carrying `data-move` and `data-form`. Rows are matched by equal coefficient vectors (positions order equals label order on the 32 types). "Show as table" (A-10, `data-out="valuesTable"`) has one row per node with the label, the left number (exact digits), the right form and a "Fire node k" button, disabled when the number is not positive.

## 2026-10-10 P3-A5: the T1 colour-class panel
Decision: key `'colours'` in T1's `panels` (the key P1-A5 declared). Wording: "First class: nodes 1, 3; second class: node 2." ("node" for one label, "no node" for none), each class preceded by a glyph (a disc ● for the first, a square ■ for the second, `aria-hidden`) coloured `--edge-3` and `--edge-4`; node fill is untouched (it carries the sign, 6.3). On an odd cycle: "No two colour classes: the board has a cycle of odd length." Hooks: `data-out="colourClasses"` with `data-class-1` and `data-class-2` (labels joined by commas) or `data-none="true"`. The first class is bipartition's class 0, which holds the lowest position of each component. The edit of T01GameBoard.svelte is additive: a `<script module>` block with `colourClasses` and `classText`, one derived value, the panel's markup after the phase-2 panels and two style rules. The panel deliberately carries no `data-panel` attribute: P1-A5's unit test "no colours panel before phase 3 (MERGE, P2 stage 2.2)" asserts that no `data-panel="colours"` is rendered; that test is now obsolete and is reported to MERGE (not edited). Board.svelte's `decoration` prop is not read by Board (types.ts: "Board does not read it yet"), so no marker is drawn on the nodes; a request to P0-A5 through MERGE asks for a per-node marker. The browser test of the panel bundles T1 with `panels: ['colours']` (T07.spec.ts > `T1 colour-class panel`), since no route sets the property yet; once M5 places it, a lesson test can read the same hooks.
