## 2026-10-17 RT-FIX-P3-small-fixes: T9's road counts come from the engine (P3-RT-10-05)
Decision: the road counts back to the new city in T9's end panel, b_j = <beta^vee, alpha_j> (SPEC 2.12, data-out="returnCounts"), are `toNumbers(transposeBoard(board), coroot(board, end))`: the numbers of the coroot played as a population of the reversed board (2.5), three engine exports that `CONTRACTS.md` 2.4 already lists, so no engine export was added. This replaces the formula of the entry "P1-A7: the end panel and the return counts without coroot" (decisions/P1-A7.md), which built b = C^T beta^vee in t09/kostant.ts from `board.cartan` and found beta^vee through `highestShortRoot` or `highestRoot` of the reversed board; the switch to `coroot` that entry announced for P2-A7 is now made, and the values shown are the same (the recipe test against `affine[T].cartan_node0_first` for all 125 long starts still passes). `recipeMatrix`, which only T09.test.ts used, moved from t09/kostant.ts into that test file as a helper, unchanged, so that no T9 source reads a Cartan matrix. Not chosen: the negated row 0 of `affineExtension(board, short).board.cartan`, which would put the sign and the node-0 offset of the recipe back into the component. Reason: SPEC 7.3 ("Components contain no mathematics beyond calling the engine"), CLAUDE.md Rules, the orchestrator's note for this cluster.

## 2026-10-17 RT-FIX-P3-small-fixes: a move that changes nothing above four nodes (P3-RT-05-08)
Decision: `announceTemplates.changedOnly` omits the clause of changed nodes when there is none, so a move that changes nothing on a board with more than four nodes reads "Fired node 3. Move 1." or "Mutated city 3. Move 1."; with one or more changes the sentence is the A-4 template, unchanged ("Fired node 4. Node 3 now 3, node 4 now minus 2, node 5 now 1. Move 7."). It is the reading T1's linked view above four nodes already used ("Mutated city 3 and fired node 3. Move 1.", t01/announce.ts). What the specification left open: SPEC 7.5 A-4 gives the changed-nodes template only for a move that changes something. Default used: the remedy recommended to the owner by the red team (omit the empty clause). T11's symmetric moves keep their own recorded reading (decisions/P4-A4.md: "... Nothing changed. Move k."), which returns before `changedOnly` is reached; the site therefore has two readings of a move that changes nothing, raised for the owner. Reason: A-4 templates are whole sentences; the orchestrator's direction for this cluster.

## 2026-10-17 RT-FIX-P3-small-fixes: a held road count above four in the editor (residual of P3-RT-03-01)
Decision: when the board in force holds more than four roads one way between the selected pair (a board from a link: the codec and the engine accept any count, SPEC 5.6), BoardEditor's roadsOut and roadsBack selects show that count as an extra option that is selected and disabled, after the options 0 to 4; the reader can still choose only 0 to 4, so the editor refuses more as 5.6 says. Choosing 0 to 4 for the held direction lowers it. A change of the other direction is refused while one direction holds more than four (`setRoads` of editor/model.ts checks both counts, unchanged, decisions/P2-A3.md), and the select then goes back to the count the board holds, so the select never shows a count the board does not hold. Export and import now relate as follows, with neither changed: the export (T16BoardIO `boardJsonText`) writes the board as it is held, more than four roads included, so the file and the link describe the same board; the import of that file is refused with the reason recorded by RT-FIX-P3-drawing ("The board could not be read: it has 5 roads from node 2 to node 1, and the editor allows at most 4 each way. The board was left as it was."); the editor shows the held count and lets the reader lower it to 0 to 4, after which the export reads back through the import. What the specification left open: how the editor shows a count above its cap that it did not produce. Reason: SPEC 5.6 ("Roads between two nodes, each way (editor only; the engine accepts any count) | 4 | editor refuses more"); the orchestrator's direction for this cluster. The regression test in site/tests/e2e/T16.spec.ts checks the export, the refused import and the round trip after lowering.
