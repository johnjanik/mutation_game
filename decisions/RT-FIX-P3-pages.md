# RT-FIX-P3-pages: decisions of the red-team round 1 fixer for the pages cluster

## 2026-10-17 RT-FIX-P3-pages: what a Sources list and a Cite title print (P3-RT-08-03)
Decision: `citeTitle(k)` in `site/src/lib/sources.ts`, which both `<Cite>` (link title) and `Sources.astro` (the text after each key) use, now returns the citation part of the entry's first line: the line up to the first sentence that carries a status label (`[S]`, `[S2]`, `[V]`, `[U]`, `[D]`, by the token rule of the sources page) or that gives the reading status in words ("Not read", "Not opened"). When the label stands in the first sentence, the cut falls before the bracket it would leave open, or else before the clause, after the last semicolon, that holds the label. A full stop ends a sentence unless the word before it is a single letter (an initial) or a capitalised word of letters (an abbreviation such as "Math." or "Soc."). Markdown is then stripped as before. What the specification left open: SPEC 7.3 asks for "the entry's text as the link's title" and 8.2 item 8 for "Sources for the module" with no format; P0-A4 had taken the whole first line (plan rule, decisions/P0-A4.md), which for one-line entries is the research record. Reason: SPEC 0.3 labels belong to the specification, 8.4 forbids dressing computation up as a citation, and 7.3 publishes the record only on the sources page, with the labels spelled out; the full record stays there unchanged. All 95 keys were checked: none keeps a label or a reference to the specification, and each title still begins as its entry does. Entries whose first line holds a note without a label keep it (for example [W-MS] "Project file ...; also at (link not re-checked)"); a removed autolink still leaves "Free: ." as P0-A4 accepted.
