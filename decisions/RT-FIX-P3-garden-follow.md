# RT-FIX-P3-garden-follow: decisions

## 2026-10-17 RT-FIX-P3-garden-follow: where the phase-3 orbit total lives (P3-RT-01-02, P3-RT-03-02, P3-RT-06-01)
Decision: the rule of SPEC 4 T2 Interactions "from phase 3 on a finite-type board it gives the exact size from `orbitSize`" is applied in `gardenTotal` (`site/src/components/tools/t02/phase2.ts`), not in `totalOf` (`t02/garden.ts`) as the P1-A6 entry "counter without a total" foresaw ("`totalOf` is the one function phase 3 changes for `orbitSize`"). What the specification left open: the file. Reason: the finite test from phase 2 is the verdict of `classify` (SPEC 5.6), which P2-A7 placed in `phase2.ts` beside the roots total; `totalOf` keeps the phase-1 answer of the bounded search, which `gardenTotal` returns off the finite types. The component already calls `gardenTotal` for the counter and its announcement. The comment of `totalOf` now points there.

## 2026-10-17 RT-FIX-P3-garden-follow: an orbit size beyond the safe integers
Decision: when `orbitSize` throws `EngineOverflow` (its group order is formed in SafeInt; on twelve nodes it fits, E-4, but a named board such as `A20` reached by a link has an order beyond 2^53), the counter gives what the bounded search gives ("more than 2000", or the count when the search completed). What the specification left open: SPEC 4 T2 names no case where `orbitSize` cannot answer. Default used: none in section 10 applies. Reason: the statement stays true and no number is rounded (E-1); the `Total` type of T2 holds a `number`.

## 2026-10-17 RT-FIX-P3-garden-follow: a population's orbit size (P3-RT-01-02)
Decision: in the mutation game the orbit of a population p is measured by `orbitSize` of its numbers a = Cp (`toNumbers`). What the specification left open: SPEC 5.4 gives `orbitSize` on positions of the numbers game only. Reason: a mutation changes Cp exactly as the firing of that node changes a (SPEC 2.4), and C is invertible on a finite-type board, so the two orbits have the same size (the oracle agrees: `orbit_size(C, -end)` for the A6 population (2, 1, 5, 1, 3, 8) is 2520).

## 2026-10-17 RT-FIX-P3-garden-follow: followers keep the followed play (P3-RT-04-04)
Decision: a T2 or T3 following a T1 through `linkTo` keeps the positions of the followed play and, on each published state with the same board, coords and start, applies only the moves after the longest shared prefix (`extendPlay` in `t02/follow.ts`, `followPlay` in `t03/model.ts`); another board, coords or start is a load, replayed from the start. Both subscriptions run untracked inside their effect. This supersedes, on this point, the P2-A2 entry "the meter reads `positionsOf` of the last published state" and the reading of the P1-A2 entry "a follower recomputes its own positions" as a replay per move; positions still never travel between tools. What the specification left open: nothing (SPEC 7.4 "extends it by one position per move"); recorded because two builder entries said otherwise. Reason: SPEC 7.4; E-9 rule 2.
