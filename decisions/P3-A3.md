## 2026-10-10 P3-A3: the board property overrides a preset's board

## 2026-10-10 P3-A3: legal play only, and the link rules
Decision: T5 plays only legal firings. The state written is exactly `{ schema, tool: 'numbers', board, coords: 'numbers', start, moves, lambda? }`. The codec checks a move against the mode in force only when the state carries a mode, and T5's state carries none, so `t05/link.ts` checks the decoded state itself with `firstForbiddenMove(board, { ...state, mode: 'legal' })`: a forbidden move loads the defaults with `LINK_NOTICE`. A link with `c=p`, or with `v` other than numbers or `m` other than legal, loads the defaults with the notice. A `d` with a negative entry or an entry of more than 6 digits keeps the rest of the link, loads the default `lambda` (the author's when the board is the author's, else zeros) and shows the notice. The tab, the first colour and game B's moves are never in a link (6.6). Note for links on the tool's own route: a link that names A3 without `w` keeps the default's six moves (the codec keeps an absent key), so a link to A3 from another start needs `w=`; links written by "Copy link" always carry `w`. What the specification left open: how the codec learns T5's mode. Default used: the tool checks (plan). Request to P1-A2 recorded in the report.

## 2026-10-10 P3-A3: the start chooser
Decision: the chooser offers all ones, a fundamental weight (with a node picker, `omega_i = e_i`) and custom (one text field per node, an optional minus sign, ASCII or U+2212, and at most 40 digits; "Use this start" is enabled only when every field holds such an integer). The kind shown is derived from `start` (all ones; a unit vector; otherwise custom), never stored; choosing "custom" opens the fields until a start is applied. Changing the start resets the moves and game B and keeps `lambda`; a picker change resets start, moves, `lambda` (to zeros) and game B. A start that leaves the safe range is reloaded with `Big` arithmetic, with no message (SPEC 4 T1, read for T5), and an `EngineOverflow` during play switches to `Big` and recomputes every position.

## 2026-10-10 P3-A3: step, play to the end, the worker
Decision: step fires the lowest legal position (E-5); play to the end is one call of `play` with `CAPS.playMoves`, its word appended; the branch for `status: 'cap'` writes `still running after N moves` in `data-out="limit"`. Every play runs on the main thread and the component never imports `engineCall`: a game from an all-positive start has N <= 120 moves (F4), and the plan reading for a start with zeros or negative numbers is that each legal move lengthens the element of W reached (F5 for all-positive starts), so no legal game has more than N moves. The positions of the play are extended by one engine call per move (7.4).

## 2026-10-10 P3-A3: the wave
Decision: the wave runs from all ones only. Its rounds come from one `wavePlay(board, rho, firstColour)`, split by the colour classes of `bipartition` (class 0 holds label 1). In the wave tab "Step" (labelled "Step one round") appends the moves of the next round and "Play to the end" the rest of the wave's word; both are disabled while the moves do not follow the wave from all ones, and then the panel says `The wave runs from all ones. Start it to fire one colour class per round.` with a button "Start the wave from all ones" (`data-control="startWave"`), which sets the start to all ones and empties the moves. This button is the confirmation the plan asks for before discarding moves (no dialog). A colour choice (`firstColour`, radio buttons, default 0) is shown on rank 2 and more. The round counter counts complete rounds made; beside it the Coxeter number from `coxeterNumber`. On the wave tab each node carries a mark over the board, a filled square for class 0 and an outlined triangle for class 1, and each class is listed in words.

## 2026-10-10 P3-A3: the A1 sentence
Decision: `On A1 one colour class is empty: the wave is a single move.` (`data-out="waveNote"`); on A1 no round count and no colour choice are shown, and the step is announced `Fired node 1. The wave is a single move. Numbers now minus 1.`

## 2026-10-10 P3-A3: two games compared
Decision: game B starts from game A's start with its own move list (outside the link), on a second board in legal play (accessible name `Game B on <board>`), with "Step B" and "Play B to the end" taking the highest legal position, and "Reset B". The overlay shows both tapes sorted numerically, cell by cell, and compares only when both games have ended: `the sorted tapes agree` (`data-out="tapesAgree"`, present only then) or `the sorted tapes differ`; otherwise `Game A is unfinished: play it to the end to compare.`, `Game B is unfinished: play it to the end to compare.` or `Both games are unfinished: play them to the end to compare.` (`data-out="compareStatus"`). The ends and the lengths of both games are shown (`endA`, `endB`, `movesA`, `movesB`). The tapes are never compared in move order. Game B's keys `u` and `r` do nothing (History belongs to game A).

## 2026-10-10 P3-A3: the dimension calculator, the lambda cap and the message
Decision: one text field per node; the field refuses a minus sign, anything but digits, and a seventh digit (the text returns to its last accepted value); at most 6 digits per entry, the same cap on a link. The word is the lowest-node game from rho; the tapes are computed in `Big` arithmetic (so no number on them can overflow), D and M are `bigint` products, and the quotient shown is `weylDimension(board, lambda)`, checked against M / D. Should the calculation ever fail the panel says `The dimension could not be computed for this lambda.` (`data-out="dimensionNote"`). The default `lambda` is zeros (dimension 1) unless a preset or a property sets it.
