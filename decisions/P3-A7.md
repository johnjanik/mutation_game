# Decisions of P3-A7 (npm run lab, the lab timings of SPEC.md 7.6)

## 2026-10-10 P3-A7: the lab tool is Lighthouse CI (Branch A)
Decision: `npm run lab` measures the lab timings of SPEC.md 7.6 with Lighthouse CI, `@lhci/cli` 0.15.1 (which runs Lighthouse 12.6.1), not with the Playwright fallback. What the specification left open: 7.6 [D] names Lighthouse CI as the intended tool, with its current version and its behaviour under Node 22 unchecked [U], and gives a Playwright fallback if it "cannot be made to run within an hour"; 7.1 [U] leaves the version to "the version current when phase 3 starts". Default used: none of SPEC.md section 10 is involved. Reason: the time-boxed trial of the instruction (5.2) succeeded in about two minutes, and 7.6 names Lighthouse CI as the intended tool, so it is chosen even though the fallback would need no dependency.

Trial (wall-clock, UTC, from the first install command to the first good measurement):
- Start 2026-10-10T20:31:22Z (`npm --prefix <tmp> install --save-exact @lhci/cli@0.15.1`, 330 packages in 17 s, in a scratch directory outside the repository). End 2026-10-10T20:32:58Z. About 2 minutes of the hour.
- Registry, read on 2026-10-10: `npm view @lhci/cli version` 0.15.1; `npm view @lhci/cli engines` printed nothing (the package declares no engines); `npm view @lhci/cli license` Apache-2.0; `npm view @lhci/cli dependencies` lists `lighthouse: '12.6.1'` exactly, together with `chrome-launcher ^0.13.4`, `express`, `yargs` and others. `lighthouse` 12.6.1 declares `engines.node >=18.20`. The newest `lighthouse` on the registry is 13.5.0 (engines `>=22.19`), which `@lhci/cli` 0.15.1 does not use. The package name `@lhci/cli` that the plan remembered is the published one.
- What ran: `astro preview` of the preview build on port 4324, then `lhci collect` with a configuration file in the scratch directory and its working directory there (run files in `<tmp>/.lighthouseci/`), `chromePath` set to Playwright's Chromium (`require('@playwright/test').chromium.executablePath()`), one run each of `/` and `/modules/m0-start/`, with the settings `formFactor: 'mobile'`, `screenEmulation { mobile: true, width: 360, height: 800, deviceScaleFactor: 1, disabled: false }`, `throttlingMethod: 'devtools'`, `throttling { cpuSlowdownMultiplier: 4, requestLatencyMs: 0, downloadThroughputKbps: 0, uploadThroughputKbps: 0, rttMs: 0, throughputKbps: 0 }`, `onlyCategories: ['performance']`, Chrome flag `--no-sandbox`.
- Result: both reports carry `configSettings.throttlingMethod` `devtools`, `configSettings.throttling.cpuSlowdownMultiplier` 4 and the screen 360 by 800, no `runtimeError` and no run warning, and numeric values for the audits `largest-contentful-paint`, `total-blocking-time` and `cumulative-layout-shift` (`/`: 393 ms, 106.6 ms, 0.0005; `/modules/m0-start/`: 406 ms, 640.3 ms, 0; one unrepeated run each on a shared machine, functional evidence only).
- Read in the installed Lighthouse 12.6.1 (`core/lib/emulation.js`): with `throttlingMethod: 'devtools'` it sends `Emulation.setCPUThrottlingRate` with `rate` equal to `cpuSlowdownMultiplier`, before navigation, through the DevTools Protocol, which is what 7.6 asks of the fallback ("the processor slowed through a DevTools Protocol session"). With `simulate`, its default, it sends no such call and only clears network throttling, so a simulated run never counts (roster trap 2).
- Settlement of the [U] items (Appendix E item 17): 7.1, the version current when phase 3 starts, is `@lhci/cli` 0.15.1 (Lighthouse 12.6.1), read from the registry on 2026-10-10. 7.6, the behaviour under Node 22: it installs and runs under Node 22.22.0 with npm 10.9.4 on this machine without error, launches Playwright's Chromium (Chromium 141 here), applies DevTools throttling at 4 and yields the three numbers.
- One incident to record: the plan's step `npm --prefix <tmp> init -y` does not honour `--prefix` in npm 10.9.4. It merged its defaults into the package.json of the current directory, which was the worktree root (it added `description`, `main`, `keywords`, `author` and a `dependencies` list built from `node_modules`). The lockfile was not touched. The change was reverted at once with `git checkout -- package.json` and `git status --porcelain package.json package-lock.json` then printed nothing; the later `npm --prefix <tmp> install` did write only into `<tmp>`. A future trial should create `<tmp>/package.json` with the Write tool instead of `npm init`.
- The scratch directory was deleted by its absolute path after that check; nothing of the trial is committed.
