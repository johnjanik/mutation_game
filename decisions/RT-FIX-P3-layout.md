# Decisions of RT-FIX-P3-layout (red-team round 1 over phases 0 to 3, cluster "layout")

## 2026-10-17 RT-FIX-P3-layout: which of the two edge-to-edge rules a lesson's tool figure keeps (P3-RT-05-01)
Decision: below 400 pixels Lesson.astro runs a figure at `100vw` only when the figure holds no ToolFrame (`[data-anatomy='figure']:not(:has([data-frame]))`); a figure that holds a tool stays in the page column and ToolFrame alone moves the tool's `<figure>` out by the page gutter, exactly as on the tool routes. The tool's title, controls and share row then keep the page gutter on lessons too. Static figures keep the `100vw` rule of decisions/P1-A4.md. A browser without `:has()` drops the whole rule, so its static figures stay in the column and no page scrolls sideways (the other order, an override that undoes the 100vw rule for tools, would bring the double breakout back in such a browser). What the specification left open: SPEC 6.1 [D] says only that the box runs from edge to edge below 400 pixels; the finding offered either rule. Default used: none (6.1 applied as written; decisions/P0-A5.md "negative margins equal to the page gutter" and decisions/P1-A4.md "100vw below 400 pixels" both still hold, each for its own kind of figure). Reason: the gutter-based rule is exact (`100vw` also counts a classic scrollbar), and it keeps lessons and tool routes alike.

## 2026-10-17 RT-FIX-P3-layout: the width of a number prediction's answer field (P3-RT-05-01)
Decision: Predict.svelte gives the answer field of a number question `width: 8em` (class `number`), the width T05 had set locally for the same reason. With the browser's default width (about 20 characters) the label and the field could not be narrower than about 323 pixels, so a tool with a prediction was 349 pixels wide; this was hidden on lessons while the figure was 352 pixels wide and failed the adopted test once the figure was 320. Position answers keep `size="4"`. What the specification left open: the field's width. Default used: none. Reason: A-11 (controls reflow at 320), 4.0 "Small screens".

## 2026-10-17 RT-FIX-P3-layout: a lesson's Sources entries wrap long tokens (P3-RT-05-01)
Decision: Sources.astro sets `overflow-wrap: anywhere` on each entry, as Page.astro already does for the credits table. The W-MS entry holds the unbroken file name `MutationGameCoxeterGraphs.pdf`, which reached x = 326 at 320 pixels on M0, M1, M3, M4 and M5; like the Predict field it was hidden inside the wider figure and surfaced with the fix. What the specification left open: nothing beyond A-11. Reason: A-11.

## 2026-10-17 RT-FIX-P3-layout: every display formula of <Tex> is a tab stop (P3-RT-05-04)
Decision: Tex.astro adds `tabindex="0"` to the outer `<span class="katex-display">` of every display formula it typesets, and base.css gives it the focus ring of A-2. No role and no accessible name are added: on focus a screen reader reads the MathML inside (A-12), which an `aria-label` would replace. Every display box is a stop, not only those that scroll, because which formulas overflow depends on the reader's width and fonts and the layouts ship no script (P1-A4); this follows the scroll boxes of T7 (decisions/P3-A5.md, `tabindex="0"`). The build fails if KaTeX's display output no longer starts with that span, so that the stop cannot vanish silently on a KaTeX upgrade. Not taken: a script that marks only overflowing boxes (a script on every lesson); splitting the one formula of M2 beat 2 (the content would fit, the cause would stay). What the specification left open: how a scrolling formula is made keyboard operable (A-11, WCAG 2.1.1). Default used: none. Reason: SPEC 7.7 (no serious axe violation), A-11.

## 2026-10-17 RT-FIX-P3-layout: display formulas reflow at their break points, on every page (P3-RT-05-11)
Decision: the rule `.katex-display { overflow-x: auto; overflow-y: hidden }` moves from Lesson.astro and Page.astro to base.css, which every page loads, and display formulas may break between the pieces KaTeX already makes at the relations and binary operators of a formula's outer level (`.katex-display > .katex > .katex-html { white-space: normal }`), as TeX breaks an inline formula; a piece still wider than the column scrolls inside the formula's own box. The break is needed, not only the box: a formula written with `$$` goes through rehype-katex, cannot carry the tab stop of `<Tex display>`, and with the box alone a11y.spec.ts reported scrollable-region-focusable (serious) on /dev/math-check/ at 360. Wider than the column and without a break point, a `$$` formula would still be a box without a tab stop; giving those a stop needs a rehype step, which changes the mathematics route of decisions/P0-A3.md (left to the owner, see the report's open questions). What the specification left open: how a display formula reflows (A-11). Default used: none. Reason: A-11 on every route, SPEC 7.7.
