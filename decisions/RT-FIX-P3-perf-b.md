# RT-FIX-P3-perf-b: decisions of the red-team round 1 fixer, cluster perf-b

## 2026-10-17 RT-FIX-P3-perf-b: the history strip names only what History reads (P3-RT-07-01)
Decision: every tool that renders History.svelte derives `positionNames` through `historyNames(total, cursor, nameAt)` (site/src/components/board/historyNames.ts): every position's name while the strip shows one button per position (at most 50, `STRIP_BUTTONS_MAX`, now exported from that module and read by History.svelte), otherwise an array of length total + 1 holding only the cursor's name, which the slider reads as `aria-valuetext`. What the specification left open: SPEC 4.0 History [D] fixes the strip and the slider, 7.4 that a move costs one engine call however long the play; neither says which names a tool computes. Default used: none from section 10; the choice P2-A4 recorded for T15 ("position names are computed only for the cursor"), applied to T1, T3, T5, T6, T7, T8, T9, T11, T15, T16 and BoardSeed. Reason: a move rebuilt the names of all L + 1 positions (205.7 ms per Step after 20000 moves here, against 6.4 ms after 12); now 7.5 ms. HistoryProps keeps its shape (`positionNames: string[]`); above 50 positions the entries other than the cursor's are holes, which History never reads.

## 2026-10-17 RT-FIX-P3-perf-b: the browser never loads the tool registry (P3-RT-07-04)
Decision: site/src/tools/index.ts still collects the registry with `import.meta.glob` (CONTRACTS 5.2), but lazily and on the server only: `registry` is filled by a top-level await when `import.meta.env.SSR` (the pages at build time, Vitest), and is empty in the browser, where the glob and the entries are dropped from the bundle. `boardsOffered(id)` without an `entries` argument reads the small table `BOARDS_OFFERED` of site/src/tools/offered.ts, which imports only the light board lists the registry entries themselves read (t05/boards, t09/boards, t10/config, t11/config, t15/boards) and repeats the literal lists of T6, T7 and T8; with `entries` it reads them, as before (urlCodec.test.ts's fixture). What the specification left open: 7.6 [D] says what a route consists of, not how the codec learns the boards of 6.6 rule 8. Reason: the eager glob put every tool's registry entry and presets (several compute captions with the engine at load) into the ToolFrame chunk of every tool route and lesson. Consequence for later agents: a new registry file must also be listed in offered.ts; site/tests/unit/registry-offered.test.ts fails until it is, and holds the two equal. Measured with npm run size (base d9ed4d0 against this branch): every tool route and lesson fetches 7 to 9 kB less (for example /tools/board/ 80.0 to 71.3 kB, /tools/geometry/ 89.2 to 80.4 kB, /modules/m0-start/ 80.0 to 71.3 kB); / is unchanged (45.2 to 45.3 kB).

## 2026-10-17 RT-FIX-P3-perf-b: the registry outs check reads the built pages in the browser suite (P3-RT-10-06)
Decision: the RT-10 reproducer, which reads site/dist/tools/<id>/index.html, is adopted as site/tests/e2e/registry-outs.spec.ts (it needs no browser) instead of a unit test, and loads the registry files with readdirSync and a dynamic import instead of Vite's import.meta.glob. What the specification left open: the test directory (RT-FIX 5.3 names site/tests/unit for a script that reads files). Reason: CI runs `npm run check` (the unit suite) before `npm run build`, so a unit test reading site/dist would fail on every fresh checkout; the browser suite runs after the build. The names rendered only by a property or after hydration are checked in the tools' own files (T01.test.ts, T08.spec.ts).
