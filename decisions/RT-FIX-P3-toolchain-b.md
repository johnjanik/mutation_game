## 2026-10-17 RT-FIX-P3-toolchain-b: the internal-link check of the build (P3-RT-12-01)
Decision: `scripts/links.mjs` checks the built directory after every `npm run build`, through a root `postbuild` script (`node scripts/links.mjs`), so a preview build, a release build (`build:release` and deploy.yml both run `npm run build`) and the `BASE_PATH=/sub/path/ OUT_DIR=dist-basepath` build of `e2e:basepath` all fail on a problem; ci.yml needs no step of its own, since its two build steps run the check. It reads every URL attribute of every built page (`href`, `src`, `srcset`, `poster`, `action`, `xlink:href`, the island attributes `component-url`, `renderer-url`, `before-hydration-url`, and `data` on `<object>`), skips script and style contents and comments, resolves each against the page under the base, and reports a link that lies outside the base, one that names no file of the build (directory and `.html` forms accepted, as GitHub Pages and `astro preview` serve them), and one that names a page that is built but not released. The released flags are read from the sources by the rules of `site/src/lib/pages/released.ts` (a lesson of `src/content/modules` or a page of `src/content/pages` unless its front matter says `released: true`; a tool whose registry entry says `released: false`, both its `/tools/` and `/embed/` routes; a Markdown or MDX page of `src/pages` whose front matter says `released: false`, such as `dev/math-check`). Links to other origins are left to links.yml (SPEC 7.7); fragments are not checked against ids. No dependency. What the specification left open: how the build checks internal links (SPEC 7.7 Links row; DECISIONS.md "P0-A6: the Links row of SPEC 7.7 left open", passed to the orchestrator). Default used: none; the orchestrator's instruction for this cluster (a script under `scripts/`, run by a root npm script after the build, no new dependency), which pre-approved the root `package.json` script. Reason: "checked by the build" read literally, so the red team's three mutations now fail `npm run build` in both modes (exit 1, verified with redteam/rt12/run-mutations.sh m1 m2 m3). `site/tests/unit/scaffold.test.ts` lists `postbuild` among the root scripts it allows.
