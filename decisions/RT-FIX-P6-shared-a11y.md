## 2026-10-26 RT-FIX-P6-shared-a11y: the colour of links and the focus ring live in base.css (P6-RT-05-01)
Decision: the rules `a { color: var(--text) }` and `a:focus-visible, button:focus-visible { outline: 3px solid var(--focus-ring); outline-offset: 2px }` move unchanged from the `<style is:global>` of `site/src/layouts/Base.astro` to `site/src/styles/base.css`, which Base.astro and `pages/embed/[tool].astro` both import, so a link a tool draws on /embed/<id> has the text colour (A-6) and a button without a focus rule of its own the ring of A-2, as on /tools/<id>. The layout's own rules (skip link, header, footer) stay in Base.astro. The embed page's rules for its "Open on the site" link are left as they were (now the same values twice). Not taken: importing a second stylesheet only in the embed page, which would leave the next page without Base.astro open to the same defect. What the specification left open: where the site's global rules live (decisions/P6-A5.md "the embed page" gives the embed page base.css and says nothing about links). Default used: none. Reason: SPEC 7.5 A-6 and A-2, 7.4 "Embedding" (the same tool as /tools/<id>).

## 2026-10-26 RT-FIX-P6-shared-a11y: the table view's scroll box is a named tab stop (P6-RT-05-02)
Decision: in `site/src/components/board/ToolFrame.svelte` the "Show as table" view scrolls in a `<div class="bare" tabindex="0" role="group" aria-label="Table of <title>" data-scroll="table-view">` with the focus ring of A-2; inside it a `<fieldset>` (no longer the scroll box) still disables the table's buttons until hydration (7.4). The group carries the name the fieldset's visually hidden legend carried before ("Table of <title>"), and the legend is removed so that the name is not read twice. The box is a tab stop in every state, before hydration and without JavaScript included, since a disabled fieldset cannot take the focus; it is a stop whether or not the table overflows at the reader's width, as the display formulas are (the entry "RT-FIX-P3-layout: every display formula of <Tex> is a tab stop"). The hook `data-scroll="table-view"` is added, after T5's `data-scroll="tally"` for a scroll box; no hook or prop is renamed or removed (CONTRACTS 5.1). Role group, not region (the finding's proposal): a lesson with several tools of one title would hold several landmarks of one name (axe landmark-unique), and the site's other scroll boxes are named groups (decisions "P3-A3: tabs and scroll boxes", MatrixView). The table buttons of T13 and T9 stay disabled while a prediction freezes the tool, as the entries "P1-A5: prediction check" and "RT-FIX-P3-board-a11y: a frozen board stays one tab stop" record for History and the step controls; the box makes the table reachable without changing them. What the specification left open: how a scroll box with only disabled content is made keyboard operable (A-11 with A-1, WCAG 2.1.1). Default used: none. Reason: SPEC 7.5 A-1, A-10, A-11, 7.7 (axe scrollable-region-focusable).

## 2026-10-26 RT-FIX-P6-shared-a11y: the run without JavaScript reads a figure's marks and T13's panel figures (P6-RT-06-01)
Decision: in `site/tests/e2e/nojs.spec.ts` (`toolReport`), a figure holds content by its marks: an SVG drawing a circle, ellipse, line, path, polyline, polygon or text outside defs, marker, title, desc, clipPath, mask, pattern and symbol (a rect alone, which is often a background, is no mark); an HTML drawing of role img (T2's chart of bars, a fraction) an element, as before. A board is a group (data-board-group) with a data-node and a drawing beside it with marks. Every board group and every named drawing (aria-label, aria-labelledby or a title) that is shown, not only the first, must hold its content, else it is reported as a blank part. The figure of the panel a T13 instance is configured to show is read: `data-out="shadow-picture"` must hold a `data-point` drawn by a mark, `data-out="restricted-board"` a board, and a tab panel that names its restricted board (`data-out="restricted-name"`) must draw it. The kind of a root's figure is chosen as before. This adds to the entries "RT-FIX-P3-test-integrity: the default figure of the run without JavaScript", "RT-FIX-P4-tool-t10" and "RT-FIX-P5-t12-a11y". M9.spec.ts checks without JavaScript that b3's picture holds a point per restricted root with its multiplicity and that the restricted boards of b7 and b12 hold a node per simple restricted root, drawn, showing the default shadow's coordinates; T14.spec.ts that every Atlas drawing holds a disc and a label per node. What the specification left open: SPEC 7.4 asks that "every default figure" be present without JavaScript and does not say how a test recognises one. Default used: none. Reason: SPEC 7.4, 4 T13 Shadows and Restricted board, 4 T14, 7.7; RED-TEAM-COMMON 2.
