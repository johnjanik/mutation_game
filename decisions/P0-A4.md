## 2026-10-10 P0-A4: the golden path grammar (golden.ts)
Decision: `resolveGoldenPath` splits the trimmed path at dots outside brackets; each step is `key`, `key[index]` or `key[field=value;...]`, exactly the three forms of SPEC 7.3. What the specification left open: text comparison and error forms. Defaults used (plan 5.2): an integer field compares as its decimal digits, a string as it stands, a list as its entries joined by commas with no spaces (each entry by the same rule), a boolean as `true`/`false`, `null` as `null`; an object never matches; a record lacking the field does not match. Messages: `path <path> resolves to <n> values. The step "<step>" <why>.` with the path as written; malformed paths (empty step, unclosed bracket, a step starting with `[`, chained brackets, a negative or non-integer index, a selection term without `field=`) give `path <path> is malformed: step "<step>" ...` and `count` 0. `GoldenPathError` has `name`, `path` and `count`. Surrounding whitespace of the path is trimmed; whitespace inside a step is kept.

## 2026-10-10 P0-A4: value formatting
Decision: integers with U+2212 for the sign and U+202F between groups of three from five digits (the sign not counted); lists of integers as `(a, b, c)` with a comma and one ordinary space, grouping and U+2212 inside; lists of strings the same way with each string as it stands (`(A1~, A2^(2))`); strings as they stand (so the decimal strings of `bigint_test` print ungrouped and keep any hyphen-minus); `as="word"`: entries joined by U+2009, each with U+2212 if negative and no grouping; `as="count"`: the length formatted as an integer; `as="plain"`: no grouping and no brackets, for an integer and for every entry of a list (U+2212 kept). Booleans, `null`, non-integer numbers, objects, nested or mixed lists, `count`/`word` on a non-list, and an unknown `as` throw `GoldenPathError` whose message says what was found and suggests `<Tex>` or a table. `goldenProse(path, as)` (an extra export used by `<G>`) resolves and formats and adds the path to a formatting error. U+00A0 is never used. Reason: SPEC 7.3 and the plan 5.3.

## 2026-10-10 P0-A4: the TeX substitution
Decision: `substituteGoldenInTex(src)` replaces each `{{path}}` (inner whitespace trimmed) by the value in TeX form: integers with ASCII `-` and `\,` between groups from five digits (the prose threshold), lists as `(a, b)`, strings as they stand; anything else throws. ## 2026-10-10 P0-A4: the four components and their hooks
Decision: `<G>` prints `<span class="g" data-golden="<k>">...</span>` (no style, no script), throws on a missing `k` or an `as` outside word, count, plain. `<Tex>` emits KaTeX's markup through `<Fragment set:html>` with no wrapper, calls only `renderTex` from `@lib/katex` (KaTeX 0.16.47), and treats `display` as a presence flag (`Boolean(display)`). `<Cite>` prints `<a class="cite" data-cite="<k>" href="<base>sources#<k>" title="<citeTitle(k)>">[<k>]</a>`. `<Unverified>` prints, in a preview, `<span class="unverified" data-unverified="<item>"><slot/> <a class="unverified-mark" href="<base>open-items#<item>" title="Rests on item <item> of Appendix E; see its status on the open-items page">[unverified <item>]</a></span>` (mark `[unverified <item>, not in unverified.json]` for an unknown item; same mark for open and closed items); in a release, the children alone for a closed item, `<span class="unverified-fallback" data-unverified="<item>">fallback</span>` for an open or unknown item with a fallback, nothing without one. The mark is a dotted underline in `var(--text)` plus the bracketed link text (not colour alone), with a `var(--focus-ring)` outline on focus, in a scoped style. `<base>` is `import.meta.env.BASE_URL` joined with exactly one slash. None of the components has a `try`; the three that fail the build do so by an uncaught exception in the frontmatter. Hooks: `data-golden`, `data-cite`, `data-unverified`; tests find formulas by `<math`.

## 2026-10-10 P0-A4: release mode, unknown items, and the open-items report
Decision: `isReleaseBuild()` is `process.env.RELEASE !== undefined && process.env.RELEASE !== ''`, read at call time (so `RELEASE=0` is a release). `decide`: preview gives `marked` for every item; release gives `plain` for a closed item, else `fallback` or `nothing`. An item not in `unverified.json` or not of the form `E<digits>` is treated as open and listed under `unknownItems`. `registerUsage(item, Astro.url.pathname, hasFallback)` (the third argument, optional, is an addition so that the report and the stderr line can say whether the fallback was shown); the page is stored as given, base included. In a release build only, the registry writes `<dir>/open-items-report.json` and `<dir>/open-items-report.md`, where `<dir>` is `OPEN_ITEMS_REPORT_DIR` when set and non-empty, else `reports/` under the first ancestor of `process.cwd()` holding `reference/golden_data.json` (created if absent). JSON shape: `{ mode: 'release', generatedAt, buildId?, items: [{ id, status, gate, pages, fallbackShown }], unknownItems: [{ item, pages }] }`, every item listed, pages sorted; `fallbackShown` is true when at least one usage of the item rendered its fallback in this release. `buildId` is an extra field (P0-A6's `report.mjs` ignores it). The Markdown file is a table of all seventeen items (pages, fallback shown) and a table of unknown items. One `console.warn` line per new (item, page) pair in a release: `open item E4 used on / (fallback shown)` or `(nothing shown)`; none for a closed item; nothing printed or written in a preview, so an existing release report is never touched by a preview build.
Mechanism: `openItemsReportIntegration()` returns an integration named `open-items-report` whose `astro:build:start` hook, in a release build only, sets `process.env.OPEN_ITEMS_BUILD_ID` and writes the baseline (all items, no pages). After each registration the registry rewrites both files from its map merged with the pages already in the file when the file carries the same `buildId`, so that registrations from more than one module instance of one build are kept. The release fixture's report lists every registration of its page; the merge is unit-tested on its own.
