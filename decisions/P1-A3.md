## 2026-10-10 P1-A3: what counts as a custom board

## 2026-10-10 P1-A3: size rule in pixels
Decision: `toPixels(layout, W)`: row and grid layouts use u = `gridUnit(W, columns)`, 8 pixels of margin on each side (the 16 of the formula), half a unit around the outermost centres, box `columns * u + 16` by `rows * u + 16`, hit side `min(44, u)`; circle layouts use R = `polygonRadius(W)`, hit side 44, box `2R + 44 + 16` square. y is flipped here only. `boardBoxWidth(viewport, container)` returns the viewport below 400. Reason: SPEC 6.1, A-7; plan margin (5.4).

## 2026-10-10 P1-A3: road glyphs and elements
Decision: `roadGlyphs` lists joined pairs i < j in increasing order; `dynkin` gives `lines` (count max(m, m'), chevron towards the node receiving the extra roads) when m m' <= 3 and `thick` when m m' >= 4; `roads` gives one `arrow` per road, i to j first. The thick line writes beside each end the number of roads leaving that node (`countAtFrom` = A_ij beside node i): A~1 gives 2 and 2, `A2^(2)` gives 1 beside node 0 and 4 beside node 1. `roadElements(glyphs, centres, unit = 1)` returns `{ tag, attrs, text? }` descriptors (tags `line`, `path`, `polygon`, `text`) with `stroke` / `fill` equal to `var(--road)`, `var(--arrow)` or `var(--text)`, coordinates rounded to 4 decimals so server and client print the same text; each road of the `roads` style is a quadratic curve bent to the left of its direction by (index + 1) steps, so roads of one direction never coincide and the two directions bend to opposite sides. `Roads.svelte` renders the descriptors inside `<g aria-hidden="true">` and repeats the three colours in its CSS by class, so they hold even where a browser ignored `var()` in a presentation attribute (checked in Chromium: computed stroke `rgb(26, 26, 26)` light, roads `#E8E8E8` dark). The third argument `unit` is an addition to the plan's `roadElements(glyphs, centres)`: offsets of parallel lines, chevrons, counts and arrowheads are fractions of one grid unit. Reason: SPEC 6.2, 2.1; instruction 5.5.

## 2026-10-10 P1-A3: layered layout
Decision: `layeredLayout({ keys, rank, edges })` keeps `y = rank`; the lowest rank is sorted by key; each higher rank by the barycenter of the vertex's neighbours in lower ranks (the centred x already placed), compared exactly as integer fractions; ties, and vertices with no lower neighbour (placed after the others), by plain code-unit string comparison, never `localeCompare`. Edges are deduplicated as unordered pairs, may span several ranks, and edges inside one rank are ignored for ordering. `x` = index in the rank + `floor((widestRank - size) / 2)`. `rankCount` is the highest rank plus one; an unoccupied rank has an empty `order` entry. RangeError on a duplicate key, a rank that is not a non-negative safe integer, a length mismatch or an edge to a missing vertex. Timing on this machine (Node 22.22, 2000 vertices on 13 ranks, 3821 edges): first run 8.3 ms, median of nine 5.6 ms. Reason: SPEC 7.1, A-11, instruction 5.8.
