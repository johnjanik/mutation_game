## 2026-10-25 P6-A1: the order of checks in the five functions

## 2026-10-25 P6-A1: the Reason records (codes, nodes, value)
Decision: `reasons` has an entry only for each failed item, in the order `symmetry`, `condition_1`, `condition_2`, `condition_3`. Nodes are positions, increasing, never labels (E-7):
- `symmetry`: `{ code: 'not-a-symmetry', nodes }`, the positions `i` for which some `j` has `C[tau[i]][tau[j]] != C[i][j]` (on A4 with nodes 1 and 2 exchanged: `[0, 1, 2]`).
- `condition_1`: `{ code: 'not-an-involution', nodes }` with the positions `i` such that `tau[tau[i]] != i` whenever tau is not an involution (it takes precedence, as in the oracle); otherwise `{ code: 'moves-black-set', nodes }` with the black positions whose image is white.
- `condition_2`: `{ code: 'differs-from-minus-wX', nodes }`, the black positions `i` with `w_X(alpha_i) != -alpha_tau(i)` (the oracle's `bad2`).
- `condition_3`: `{ code: 'not-an-integer', nodes, value }`, the white positions fixed by tau whose `<alpha_i, rho_X^vee>` is not an integer (the oracle's `bad3`); `value` is the fraction through `ratToString` when one node fails (`'-1/2'`), and the fractions in the order of `nodes` joined by `'; '` when several fail (A5, black nodes 1, 2, 4: nodes `[2, 4]`, value `'-3/2; -1/2'`, the oracle's own separator).
No other code carries `value`. What the specification left open: SPEC 5.2 gives the codes and one `value`, not the nodes of the first three codes nor the format for several failing nodes. Default used: the plan's readings (instruction 5.5 table and the paragraph on several nodes). Reason: the tool writes the sentence from these data with labels (SPEC 4 T13, E-7). Named in `openQuestions` for confirmation.

## 2026-10-25 P6-A1: restricted_board is named by identify, not by classifyRestricted
Decision: `restricted_board` and `restricted_orbits_in_bourbaki_order` come from `identify` on the restricted board (the oracle's `identify_labelled(Cbar)`), called only when there is at least one orbit and the restricted Cartan matrix is connected; otherwise both are `null`. `restricted_type` is `classifyRestricted`'s name (`BC1`, `BC2`, `B2`, ...). ## 2026-10-25 P6-A1: the restricted board object (E-7 row "folded board, restricted board")

## 2026-10-25 P6-A1: shadows, classes and multiplicities
Decision: shadows are kept doubled (`shadow2`, integer vectors) everywhere: the multiset `restr` is keyed by the doubled shadow, `classifyRestricted` is called on the distinct doubled shadows with the board's `gram` (norms are 4 times the oracle's, the classes, their order and the name the same, since the classifier uses only norm ratios, counts and the "double is in the set" test), and each class's `mult` is the common count of the shadows whose norm, as `ratToString` text, equals the class's `form_value` (classes in `classifyRestricted`'s ascending order). `m_2lambda` is read at twice the simple doubled shadow. `real_rank` is the number of tau-orbits of white nodes (the oracle), and the span of the shadows is checked by test on all 167 records. What the specification left open: the scaling. Default used: the plan's (instruction 5.6, traps 5, 14, 15). Reason: exact integers, no halves in the engine (trap 23).

## 2026-10-25 P6-A1: boards in Big arithmetic and the population argument
Decision: the contract types the diagram's board as `Board` (numbers), as every named finite board is. Reason: T13 offers named boards; the copy costs nothing there and keeps a hand-built finite board from mixing bigint and number.
