## 2026-10-25 P6-A1: the Reason records (codes, nodes, value)
Decision: `reasons` has an entry only for each failed item, in the order `symmetry`, `condition_1`, `condition_2`, `condition_3`. Nodes are positions, increasing, never labels (E-7):
- `symmetry`: `{ code: 'not-a-symmetry', nodes }`, the positions `i` for which some `j` has `C[tau[i]][tau[j]] != C[i][j]` (on A4 with nodes 1 and 2 exchanged: `[0, 1, 2]`).
- `condition_1`: `{ code: 'not-an-involution', nodes }` with the positions `i` such that `tau[tau[i]] != i` whenever tau is not an involution (it takes precedence, as in the oracle); otherwise `{ code: 'moves-black-set', nodes }` with the black positions whose image is white.
- `condition_2`: `{ code: 'differs-from-minus-wX', nodes }`, the black positions `i` with `w_X(alpha_i) != -alpha_tau(i)` (the oracle's `bad2`).
- `condition_3`: `{ code: 'not-an-integer', nodes, value }`, the white positions fixed by tau whose `<alpha_i, rho_X^vee>` is not an integer (the oracle's `bad3`); `value` is the fraction through `ratToString` when one node fails (`'-1/2'`), and the fractions in the order of `nodes` joined by `'; '` when several fail (A5, black nodes 1, 2, 4: nodes `[2, 4]`, value `'-3/2; -1/2'`, the oracle's own separator).
No other code carries `value`. What the specification left open: SPEC 5.2 gives the codes and one `value`, not the nodes of the first three codes nor the format for several failing nodes. Default used: the plan's readings (instruction 5.5 table and the paragraph on several nodes). Reason: the tool writes the sentence from these data with labels (SPEC 4 T13, E-7). Named in `openQuestions` for confirmation.

## 2026-10-25 P6-A1: restrictedCoordinates, the shadow in the simple restricted roots (follow-up for T13)
Decision: `satake.ts` gains `export function restrictedCoordinates(d: SatakeDiagram, rb: RestrictedBoard, shadow2: Vec<number>): number[]`, exported by name from `index.ts` (a line of its own under the phase 6 block) and pinned in `PHASE_6_NAMES` of `test/unit/p1-api.test.ts` (the edit MERGE pre-approved). It returns the integers c, one per orbit in the order of `rb.orbits` (the order of `rb.simpleRestrictedRoots2`, `rb.cartan` and `rb.board`'s positions, never the Bourbaki order of `rb.board.labels`), with the sum of `c[k] * rb.simpleRestrictedRoots2[k]` equal to `shadow2` exactly; both sides are doubled, so c are the coordinates of the shadow itself in the simple restricted roots, and a composite move at orbit k changes them as `mutate(rb.board, c, k)`. Method, exact throughout: the normal equations `G c = S v` (G the integer dot-product Gram matrix of the doubled simple restricted roots, in bigint, invertible because they are independent) solved by `linalg.ts`'s `solve` over `Rational`, then the combination recomputed entry by entry with `ratEq` against `shadow2`, then the denominators checked; no float anywhere. Order of checks (the engine-wide order "argument shape, then kind"): the diagram's shape as for the other Satake functions (`checkDiagram`, RangeError), `shadow2` of the board's length with integer entries (RangeError, the message names the lengths), `rb` belongs to the diagram (RangeError: its orbits are exactly the tau-orbits of the diagram's white positions in `restrictedBoard`'s order, and each simple restricted root has n integer entries), then `requireGcm` and `requireFinite` (NeedsTwoWayRoads, NotFiniteType); then the arithmetic: RangeError "is not a combination of the simple restricted roots" outside their span, "is not zero, but this diagram has no simple restricted root (a compact form ...)" for a nonzero vector on a compact form (which gives `[]` for the zero vector), "is not an integer combination ...: its coordinates would be (1/2, 0)" with the fractions; EngineOverflow for a coordinate beyond the safe integers (unreachable on a finite board). Admissibility is not judged again: `rb` comes from `restrictedBoard`, which throws NotAdmissible, and the function stays cheap enough to call once per root on the main thread (it computes no root and no word of w_X). Pure: the arguments are read through copies, the result is a new array. The module keeps its top level free of side effects (a function declaration and one more named import from `linalg.ts`, already an engine module; P6-size). What the specification left open: SPEC does not name the function (P6-A3 instruction 5.8, plan name `restrictedCoordinates(d, rb, shadow2)`); the orchestrator asked for a check that rb belongs to the diagram's board size, and the orbit comparison is the plan's reading of "belongs", as cheap as the size check and it catches a restricted board kept from an earlier decoration. Default used: none of SPEC section 10. Reason: SPEC 7.3 "Components contain no mathematics beyond calling the engine": T13 draws the shadow picture, `data-out="shadow-coordinates"` and the values on the restricted board's nodes from this function instead of a solver of its own.
